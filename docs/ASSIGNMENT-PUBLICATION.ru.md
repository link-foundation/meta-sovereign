# Репозитории тестовых заданий (languages: [en](ASSIGNMENT-PUBLICATION.md) • [zh](ASSIGNMENT-PUBLICATION.zh.md) • [hi](ASSIGNMENT-PUBLICATION.hi.md) • ru)

[PR 57](https://github.com/link-foundation/meta-sovereign/pull/57) добавляет публикацию после проверки владельцем. Откройте форму через **Ещё → Формы**, выберите профиль и подготовьте ответы. При распознанном тестовом задании обычные ответы и загрузка PDF приостановлены до подтверждения репозитория. Проверка и сохранение ссылки на существующий репозиторий по-прежнему доступны.

Сначала включите локальную модель черновиков в настройках вопросов/форм. Публикация использует авторизованный `gh` и учётные данные Git на сервере. В панели укажите `owner/repository`, видимость, при необходимости URL вакансии HH и дополнительные названия работодателя. Подготовка черновика сохраняет закрытый предварительный просмотр без создания репозитория или issue. Проверьте точный английский текст, требования, язык, стек, источник шаблона и видимость, затем явно запустите публикацию. Без соответствующей возможности сервера эти элементы недоступны.

URL вакансии открывается в отдельном управляемом браузере по сохранённой политике `assignments`; по умолчанию браузер видимый. При необходимости войдите вручную. Читатель получает видимые название, работодателя, навыки и описание, закрывает браузер и кеширует только успешный результат. Обновление запускается явно. Точная ссылка на форму в сохранённых сообщениях HH может связать вакансию с исходным URL и URL после перенаправления. При противоречии нужен явный URL. Если связи нет, предварительный просмотр сообщает об отсутствии контекста вакансии, а модель выбирает подходящий поддерживаемый стек.

В поле URL инструкции укажите отдельное HTML- или текстовое задание. Оно читается в другом управляемом браузере с той же политикой видимости. Проверьте заголовок конечной страницы и время получения рядом с черновиком. Закрытая запись сохраняет текст и отпечаток: восстановление и публикация используют этот снимок без повторного чтения. Скрытый текст, редактируемые ответы и значения полей исключены. Вход, проверка пользователя, HTTP-ошибки, PDF/canvas/встроенные документы и превышение конечных лимитов останавливают процесс до вызова модели. Для таких документов предоставьте читаемую текстовую версию. Дальнейшие ссылки автоматически не обходятся.

Сначала читается актуальная основная таблица **Recommended CI/CD Templates** Hive Mind; использование встроенного резервного списка видно в просмотре. Явно указанный язык должности важнее случайно упомянутых технологий. Шаблоны GitHub используют `gh repo create --template`; остальные клонируются и публикуются с историей. Существующие файлы владельца сохраняются, недостающие workflow и история шаблона добавляются. Имеющийся pipeline сохраняется. Повторная публикация после нового просмотра обновляет однозначно помеченный issue и восстанавливает отсутствующий pipeline.

Локальные консервативные проверки контролируют английский текст, известные названия/склонения/транслитерации работодателя и шесть последовательных слов обоих источников, включая заголовок документа. Проверьте точность и неизвестные программе псевдонимы. Для письменного задания issue содержит **Deliverable and stack** и заключительный **Stack**: Markdown в `docs/`, исходный язык, ограничения объёма, предлагаемый стек и README со ссылкой на результат. Публикация подтверждает репозиторий, workflow и прочитанный issue. Выполнение задания, успешный CI и отправка формы этим не подтверждаются.

## CLI

Используйте сохранённый результат `forms-read` через `--file` либо настоящую форму через `--url`. Модель настраивается командами `answers model`.

```sh
meta-sovereign test-assignment task-name --file=inspection.json --vacancy=https://hh.ru/vacancy/12345 --visibility=private --employer='Employer alias' --dry-run --store=./store
meta-sovereign test-assignment owner/task-name --file=inspection.json --vacancy=https://hh.ru/vacancy/12345 --visibility=private --store=./store
meta-sovereign test-assignment owner/task-name --file=inspection.json --source=https://example.org/instructions --dry-run --store=./store
meta-sovereign test-assignment --draft-id=assignment-draft:UUID --store=./store
```

Для простого имени используется текущий авторизованный владелец либо `--owner`. По умолчанию видимость закрытая. `--dry-run` сохраняет и выводит просмотр; без него CLI публикует созданный черновик. `--draft-id` восстанавливает напечатанный `draft.id` без повторного запуска модели. Вместо URL вакансии можно передать ограниченный Lino-снимок `--vacancy-snapshot` с `title`, `description`, `company`, `skills`. `--refresh-vacancy=true` перечитывает URL. SIGINT/SIGTERM останавливают и дожидаются управляемых модели, браузера и команд до закрытия хранилища.

## API и восстановление

Доверенные POST-маршруты используют существующее согласование текстового/бинарного Lino:

| Маршрут                         | Вход                                                                                                                                        | Результат                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `/api/forms/assignment/draft`   | `inspection`, текущая `revision`, `target`, `visibility`; необязательные `vacancyUrl`/`vacancy`, `sourceUrl`, `refreshVacancy`, `employers` | Закрытый `draft`, необязательный `sourceEvidence`, `state: draft`                           |
| `/api/forms/assignment/restore` | `inspection`, текущая `revision`                                                                                                            | Сохранённый черновик и признак попытки публикации; без вызовов GitHub/модели                |
| `/api/forms/assignment/publish` | `draftId`                                                                                                                                   | Подтверждённые репозиторий, issue и новая ревизия задания либо сохранённая фаза `uncertain` |

Перед внешней записью намерение сохраняется на диск. Потерянный ответ оставляет состояние неопределённым и форму заблокированной. Восстановление той же публикации проверяет фактическую идентичность и помеченный issue, не повторяя неизвестные создания. После повторного открытия прочитайте форму, подготовьте план и восстановите сохранённый черновик, затем его публикацию. Изменённое задание/модель, другой ожидающий черновик, пересозданный репозиторий или отредактированный владельцем issue запрещают устаревшую публикацию. Без положительного подтверждения результат требует ручной проверки.

Закрытые пространства версии 1: `assignment-draft:` (проверенный текст/контекст), `assignment-publication:` (выпущенные действия/подтверждения), `assignment-vacancy:` (успешные снимки), `form-vacancy:` (точные URL и происхождение сообщений HH). Существующие формы записей сохранены. Тексты заданий/вакансий подчиняются обычной политике хранения и резервного копирования. Необязательная трассировка идентификаторов/состояний использует отключённую по умолчанию диагностику вопросов.

См. [публикацию и проверки](case-studies/issue-56/assignment-publication.md), [чтение инструкций](case-studies/issue-56/assignment-source.md). Полные сценарии провайдеров и остальные открытые требования issue 56 ещё не завершены.
