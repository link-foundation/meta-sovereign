# HTTP-транспорт (языки: [en](HTTP-TRANSPORT.md) • [zh](HTTP-TRANSPORT.zh.md) • [hi](HTTP-TRANSPORT.hi.md) • ru)

JavaScript-сервер использует `lino-rest-api` для структурированных HTTP-сообщений. Ответ по умолчанию — `text/lino`. Заголовок `Accept: application/lino-binary` выбирает бинарный Links Notation. Для записи укажите тот же тип в `Content-Type`; также поддерживаются `text/lino-line` и `text/lino-compact`. Бинарный формат кодирует типизированное дерево объекта, сохраняя строки, числа, Unicode и пустые контейнеры.

Неподдерживаемый формат запроса даёт 415. Неприемлемый формат ответа даёт 406 до выполнения изменения. Точное исключение в `Accept` важнее шаблона. Проверки Origin, Host, код доступа, скрытие секретов и ограничения размера сохраняются. Обычный запрос ограничен 1 МиБ; существующие увеличенные лимиты архивных маршрутов сохранены. Декодеры ограничивают размер, вложенность и развёртывание бинарного графа.

Совместимость с JSON по умолчанию выключена. Для старого клиента явно включите её на сервере:

```bash
node js/bin/meta-sovereign.js serve --json-compatibility=true
```

Опция библиотеки: `startServer({ jsonCompatibility: true })`; переменная среды: `MS_JSON_COMPATIBILITY=1`. В этом режиме клиент может запросить `application/json`; явный запрос Lino продолжает работать. Новый браузерный клиент использует Lino и по умолчанию отвергает неожиданный JSON. API провайдеров, скачиваемые файлы и необработанные загрузки медиа/архивов сохраняют свои форматы.

Потоки изменений и уведомлений аккаунтов Telegram используют `text/event-stream` с одной записью `text/lino-line` в поле data. Браузер запрашивает `?format=lino-line`, в том числе при включённой совместимости. Кодек экранирует переводы строк. События JSON требуют режима совместимости на сервере; иначе `?format=json` даёт 406. Переподключение, проверка Origin, фильтрация секретов и обработка медленных клиентов сохраняются.

WebSocket-синхронизация и WebRTC-сигнализация JavaScript согласуют `meta-sovereign-sync.lino.v2` (текст) или `meta-sovereign-sync.lino-binary.v2` (бинарный формат). Каналы данных WebRTC объявляют тот же протокол. Клиенты отклоняют отсутствующий или несовпадающий выбор. Старый JSON-протокол `meta-sovereign-sync.v1` требует режима совместимости с обеих сторон. Без указания протокола используется текстовый Lino, либо старый JSON при явно включённой совместимости сервера. Сообщения и очередь до подключения ограничены 4 МиБ; слишком большие или некорректные входящие кадры закрывают соединение. Проверки источника, изоляция комнат и фильтрация секретов сохраняются. См. [исследование синхронизации](case-studies/issue-56/lino-sync.md).

TCP-синхронизация JavaScript использует те же версионные протоколы. Обе стороны сначала отправляют выбранный протокол с переводом строки, затем записи: четырёхбайтовая беззнаковая длина в байтах в порядке big-endian и тело выбранного Lino. По умолчанию используется текст; для бинарного формата задайте с обеих сторон `--sync-format=binary` (в библиотеке: `format: 'application/lino-binary'`). Автоматического отката нет. Записи и очереди ограничены 4 МиБ, префикс — 128 байт, рукопожатие — 10 секунд. Старый JSON с разделением по строкам требует `--sync-format=json --json-compatibility=true` с обеих сторон. Слушатель по-прежнему доступен только через loopback. Команды синхронизации CLI работают до прерывания, затем закрывают соединения, сбрасывают данные на диск и освобождают хранилище.

R-AA16 ещё не завершено: Rust-сервер требует миграции протокола и проверки. Паритет нативного сервера остаётся открытым. См. [требования](REQUIREMENTS.ru.md) и [исследование HTTP-транспорта](case-studies/issue-56/lino-http.md).
