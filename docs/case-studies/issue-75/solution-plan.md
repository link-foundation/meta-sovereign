## Alternatives and decision

| Approach                                     | Consequence                                                                                                                                                |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Group messages by sender in the app          | This removes visual repetition in this app only. Everyone else receives separate posts and notifications.                                                  |
| Delay every submission for a debounce window | This can send a single combined message, but leaves the first message waiting and changes existing send and recovery behavior.                             |
| Edit the cached last visible bubble          | This is quick but can cross hidden, off-page or out-of-date messages, and it cannot establish that a chat is public.                                       |
| Use the provider's current tail and edit     | This directly satisfies the message-count requirement. The existing queue, confirmation, Telegram client and update handling provide the extension points. |

The implementation treats “publish chat” as “public chat.” Consecutive means the provider has no newer message in the same conversation or topic. Telegram's edit window and message size limits govern eligibility. The setting is browser-local. Cloud draft cleanup checks for the text just submitted and leaves a newer saved draft in place. Explicit replies, schedule or silent choices, effects, paid sends, explicit previews, a send-as choice that differs from the provider's default, commands, forwards and media keep their normal behavior. An appended link stays in the text without generating a preview for the combined message.

The server serializes normal and continuation sends per account and dialog. Telegram does not provide an atomic read-and-edit that coordinates with other devices or users. A new message arriving between the history read and the edit is a provider race; checking the tail immediately before editing keeps that window small. Once a provider write has been attempted, a durable receipt prevents a retry from repeating its effect or switching an unconfirmed edit to a new post.

## Reproduce and verify

1. In a public Telegram group or channel, send two short text messages with the option off. The normal composer posts both.
2. Turn on **Continue my last message in public chats** under **Settings → Sending messages**. Send another short text message while the previous message is still the newest. The newest bubble grows by one paragraph and shows the Telegram edited mark.
3. Have another participant send a message. Send again. The new message is posted separately.

```sh
node --test --test-concurrency=1 --test-timeout=30000 js/tests/telegram-continuation.test.js
RUN_BROWSER_E2E=1 npm run test:e2e:continuation
```

The provider tests use the installed TL constructors and a fake transport. The browser test uses a separate fixture server and the production code for confirmation, delivery and live updates. No Telegram account or public conversation is needed.
