# Requirements for Issue #12

The directive in issue #12 is:

> Tasks search, orders/tasks communication before worker approval and
> after (from both task giver and task taker perspectives).
>
> So all communication about work/tasks will be also supported in our
> APP, with caching all the data in our links data store. With ability
> to account level import data exports from upwork.

The issue title says **"Add people per hour support"**. The body's
single mention of "exports from upwork" is a copy/paste artefact from
the immediately preceding Upwork issue (#4) — title is treated as
authoritative; we ship a PeoplePerHour adapter and call it out
explicitly in `README.md` of this case study so future readers do not
trip over the same wording.

The issue then asks for case-study artefacts under
`docs/case-studies/issue-12/`, deep analysis with online research, an
explicit list of every requirement, a per-requirement solution plan,
a survey of existing components and libraries, and a single PR that
iterates until each requirement is fully addressed.

The atomic requirements derived from that directive are tracked with
the prefix `R-T*` (`R-S*` is taken by issue #4 — Upwork; `R-R*` by
issue #5 — GitHub).
