# Online research

| Source                                                                                                                                                                                                                                                               | Finding and effect on the design                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [AWS SaaS Lens on full stack isolation](https://docs.aws.amazon.com/wellarchitected/latest/saas-lens/full-stack-isolation.html)                                                                                                                                      | Dedicated stacks can be SaaS when operated and provisioned consistently. Separate workspace processes let the current file store and provider services remain single-owner, at the cost of a higher operating cost per tenant.                                                                                                         |
| [Kubernetes multi-tenancy](https://kubernetes.io/docs/concepts/security/multi-tenancy/)                                                                                                                                                                              | Workload network and data-plane isolation remain separate from identity and namespace names. A cluster deployment needs explicit isolation and network policy. Compose provides a small-host deployment with a separate project per workspace.                                                                                         |
| [OWASP multi-tenant security](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html) and [OWASP network-layer SSRF controls](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) | Authentication and tenant isolation are distinct. Provider adapters can accept mail and proxy endpoints, so outgoing connections need an enforced network boundary beyond input validation.                                                                                                                                            |
| [Docker Compose networking](https://docs.docker.com/compose/how-tos/networking/) and [startup order](https://docs.docker.com/compose/how-tos/startup-order/)                                                                                                         | Containers can share an egress namespace and wait for its health check. This lets a small setup process install the policy while the web process has no network administration capability.                                                                                                                                             |
| [Docker port publishing](https://docs.docker.com/engine/network/port-publishing/)                                                                                                                                                                                    | Loopback-bound ports keep proxy backends accessible only on the local host on current supported Docker versions. Use Docker 28 or later and keep cloud firewall rules scoped to the ingress.                                                                                                                                           |
| [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https) and [reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)                                                                                                           | Caddy renews certificates and proxies standard upgraded and streaming connections. The app checks the original public Host and needs no automatic local trust prompt.                                                                                                                                                                  |
| [OAuth2 Proxy session storage](https://oauth2-proxy.github.io/oauth2-proxy/7.6.x/configuration/session_storage/) and [Caddy forward authentication](https://caddyserver.com/docs/caddyfile/directives/forward_auth)                                                  | A deployment can apply external login at the edge, including OIDC. Field-level access for multiple owners of a single store would still need membership and role rules in the app. The built-in owner session keeps the minimum deployment independent of an identity service.                                                         |
| [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) and [Clear-Site-Data](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Clear-Site-Data)                                                          | A Secure, host-only cookie is scoped to its workspace hostname. No-store responses and cache clearing at sign-out reduce local persistence of workspace data.                                                                                                                                                                          |
| [Playwright isolation](https://playwright.dev/docs/browser-contexts) and [noVNC](https://github.com/novnc/noVNC)                                                                                                                                                     | A separate hosted browser can expose an interactive page via a viewer. Its browser contexts provide browser-session isolation, while isolation from process credentials, the network and the OS requires a separate workload. Browser mirroring cannot retrieve already installed browser profiles or contacts from the user's device. |

Reviewed on 2026-11-22. See the [solution plan](solution-plan.md) for how the findings apply to this repository.
