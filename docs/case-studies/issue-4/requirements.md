# Requirements for Issue #4

The directive in issue #4 is:

> Tasks search, orders/tasks communication before worker approval and
> after (from both task giver and task taker perspectives).
>
> So all communication about work/tasks will be also supported in our
> APP, with caching all the data in our links data store. With ability
> to account level import data exports from upwork.

It then asks for case-study artefacts under
`docs/case-studies/issue-4/`, deep analysis with online research, an
explicit list of every requirement, a per-requirement solution plan,
a survey of existing components and libraries, and a single PR that
iterates until each requirement is fully addressed.

The atomic requirements derived from that directive are tracked with
the prefix `R-S*` (`R-R` is already taken by issue #5 — GitHub).

| ID    | Requirement                                                                                                                                                                                                                                                          | State                                                                                                                                                                                                                                                                                                                                  |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-S1  | Treat Upwork as a first-class `MessageSource` so messages, proposals, contracts, jobs, and rooms become normalized links in the links data store.                                                                                                                    | Done: `js/src/sources/upwork.js` registers an `upwork` source with `parseArchive`/`live.pullMessages` covering every comment-bearing surface and additional `job:`, `proposal:`, `contract:`, `room:`, `transaction:` link prefixes.                                                                                                   |
| R-S2  | Allow archive imports of Upwork data — both the user-supplied **GraphQL JSON dumps** and the **CSV exports** Upwork actually offers (transaction history, weekly summary).                                                                                           | Done: `parseArchive(input)` accepts (a) an array of GraphQL nodes / `gh-api`-style payloads, (b) a structured envelope `{ jobs, proposals, contracts, rooms, messages, transactions, timeLogs }`, (c) raw CSV strings (transaction history) via the `text/csv` content sniff.                                                          |
| R-S3  | Pull live data through the Upwork **GraphQL API** at `https://api.upwork.com/graphql` (`marketplaceJobPostingsSearch`, room queries, contract queries, message queries) using OAuth 2.0 Bearer tokens.                                                               | Done: `createUpworkLive({ token, fetchImpl, baseUrl, organizationId })` posts GraphQL operations through `requestJson()` with `Authorization: Bearer <PAT>` and follows Relay-style cursor pagination via `pageInfo.endCursor`.                                                                                                        |
| R-S4  | Support job/task search from the freelancer perspective so users can see open marketplace jobs.                                                                                                                                                                      | Done: `createUpworkLive().searchJobs({ query, sort, limit })` runs `marketplaceJobPostingsSearch` and yields `job:upwork:<ciphertext>` links (also returned as plain rows for the SPA).                                                                                                                                                |
| R-S5  | Cover communication **before** worker approval (proposals to a job, proposal-room messages from both sides).                                                                                                                                                         | Done: `createUpworkLive().pullMessages({ stage: 'proposal', jobId })` walks proposal listings + their proposal-room messages, normalised through `buildMessageLink()` with a `proposal:` chat namespace.                                                                                                                               |
| R-S6  | Cover communication **after** worker approval (contract rooms, room messages, file attachments).                                                                                                                                                                     | Done: `createUpworkLive().pullMessages({ stage: 'contract', contractId })` (and the default `stage:'all'`) walks contract rooms and their messages with a `room:` chat namespace.                                                                                                                                                      |
| R-S7  | Both the **client (task giver)** and **freelancer (task taker)** perspectives are supported — same adapter, perspective is a parameter rather than a separate code path.                                                                                             | Done: `pullMessages({ perspective: 'client' \| 'freelancer' \| 'both' })` selects which jobs / contracts / rooms to enumerate; `parseArchive` keeps both sides side by side.                                                                                                                                                           |
| R-S8  | Allow posting messages back into Upwork rooms so the unified inbox stays bidirectional once Upwork enables write access for the user's app.                                                                                                                          | Done: `createUpworkLive().post({ text }, { roomId, contractId })` issues the `roomsCreateMessage` GraphQL mutation. The mutation name is treated as configurable via `mutationName` because Upwork's documented field name is **unverified** publicly.                                                                                 |
| R-S9  | Allow ingesting account-level Upwork **data exports** (the user-initiated GDPR / DSAR bundle, the Reports → Transaction History CSV, the Weekly Summary CSV).                                                                                                        | Done: `parseArchive` recognises the GDPR JSON envelope (top-level `messages`, `rooms`, `contracts`, `jobs`, `proposals`, `transactions`, `time_logs`) and CSV strings (header sniffed against `Date,Type,Description,Amount,Balance,Freelancer,Team,Account name,PO,Ref ID`). Output is one link per row, all under `msg:upwork:*`. |
| R-S10 | Index Upwork **jobs** as their own link kind so the CRM and audience filters can group threads by job/task.                                                                                                                                                          | Done: `job:upwork:<ciphertext>` links are written for every job seen, with `children` pointing at related proposal/contract/room links.                                                                                                                                                                                                |
| R-S11 | Index Upwork **contracts** as their own link kind so reporting / hours / earnings can be related back without re-walking message bodies.                                                                                                                             | Done: `contract:upwork:<id>` links carry `clientId`, `freelancerId`, `jobId`, `startDate`, `status`, and `children` linking to the room and the time logs.                                                                                                                                                                             |
| R-S12 | Honour Upwork's API ToS — no permanent caching of Upwork-derived content past **24 hours** without user consent; user-imported export rows are durable.                                                                                                              | Done: live-pulled links carry `cacheTtlMs: 86_400_000` and a `softCache: true` flag; archive-imported links are written without a TTL. The TTL is documented in `docs/REQUIREMENTS.md` and enforced by `softCacheRetention()` exported from the adapter (purges live links older than TTL on next pull unless `keepCache` is set).     |
| R-S13 | Add CLI subcommands so contributors can drive every feature without booting the SPA.                                                                                                                                                                                 | Done: `source-pull --source=upwork [--stage=…] [--perspective=…] [--organization-id=…]`, `upwork-search --query=<q>`, `upwork-message --room-id=<r> --text=<t>`, plus `source-import --source=upwork --file=<path>` for bundles.                                                                                                       |
| R-S14 | Add same-origin server routes so the browser SPA can use the JS server as a proxy when Upwork blocks cross-origin requests (Upwork's GraphQL endpoint does not advertise permissive CORS).                                                                            | Done: `POST /api/upwork/pull`, `POST /api/upwork/search`, `POST /api/upwork/post-message` route to `createUpworkLive()`, read the OAuth token from `secret:upwork:access-token` (or `secret:upwork:bot-token` as a fallback), and stamp imported links via `stampSourceLink`.                                                          |
