## WebKit native ICE policy

[Checks run 42616808291](https://github.com/link-foundation/meta-sovereign/actions/runs/42616808291), created 12:24:53 UTC for `ae8cdd3d8b5ad94ed5d23a3c7457d4fc95d91cb0`, passes all nine runtime targets, Chromium, Rust, packaging and CodeQL. WebKit now passes the expanded layout checks but fails real RTC convergence (full-log line 78388). The full log and final exact-SHA/job metadata are retained in `data/ci-ae8-final.tar.gz`. The fixture's timeout alone cannot distinguish a codec, signaling or native network problem.

The added failure-only trace records connection/signaling state, candidate presence and protocol, excluding SDP, candidate addresses and stored records. Offers, answers and ICE arrive, but both native connections remain `new`. `experiments/issue-56/webrtc-loopback.mjs` then removes the application, server and Lino entirely: two native peer connections exchange offer/answer/candidates directly, with a ten-second limit and guaranteed channel/peer/browser cleanup. On Playwright 1.65.0, WebKit revision 2388 (27.2), the default probe fails; granting microphone permission alone also fails. Starting an explicitly permitted mock capture stream succeeds and delivers the exact Unicode message. Raw results are `data/rtc-native-{default,permission,capture}.txt`.

This is consistent with WebKit's [documented ICE candidate restrictions](https://webkit.org/blog/7763/a-closer-look-into-webrtc/): access to local host candidates depends on capture access; data-only connections can instead need a permitted STUN/TURN path. That article dates from 2017, so the current-version native experiment is the evidence for this fixture. Playwright's [pinned WebKit bootstrap patch](https://github.com/microsoft/playwright/blob/v1.65.0/browser_patches/webkit/patches/bootstrap.diff#L11951) enables deterministic mock capture devices and gates them on granted permissions. No physical microphone or provider account is used.

Only the WebKit browser test grants fixture-origin microphone permission and starts its mock stream before the actual application module executes. Native signaling, ICE, SCTP, data channels and Lino remain in use; no connection state or message is faked. The stream is stopped during cleanup. The same real-store convergence, typed Unicode, secret exclusion, protocol and deletion assertions now pass (`data/rtc-webkit-{before,after}.txt`). Chromium retains its existing data-only setup. Production does not request capture to enable sync. This verifies transport under usable local ICE conditions; it does **not** establish production data-only Safari LAN discovery, relay configuration or iPhone connectivity. Those acceptance criteria remain open.

## Listener failure and snapshot resource ownership

[Checks run 42619112738](https://github.com/link-foundation/meta-sovereign/actions/runs/42619112738), created 12:41:27 UTC for `c84b4d899f0226e43573d77e31655daf9cba6a43`, completes with one failed runtime case: Windows-Deno reports `EBUSY: resource busy or locked, rm` in the busy-port test. The complete log records the test at 39178 and the error/summary at 40720–40745; the standalone job log records the error at 6503–6511. The other eight runtimes pass. WebKit was cancelled (full-log line 19825); the pipeline correctly fails at 84742. Full logs and exact-SHA/job metadata are retained in `data/ci-c84-final.tar.gz` with verified hashes. The separate worker-error diagnostic at 37546–37556 comes from the deliberate invalid-path cancellation fixture, which passes; it is not the failing busy-port case.

The server's failed-listener path previously flushed its internally opened store without closing it, retaining the writer lock and allowing the snapshot scheduler to survive the rejected startup. Normal shutdown likewise retained owned stores. Two minimal integration cases in `server-resource-release.test.js` fail before the correction with `STORE_LOCKED` when acquiring exclusive ownership after startup rejection or normal close (`data/server-release-before.txt`). The correction awaits runtime cleanup, flushes, then closes only internally owned stores. Injected stores remain owned by their caller, preserving rolling-worker ownership. A separate controlled-promise case verifies that both normal and handoff shutdown wait for reply, automation, job and account cleanup before flushing or releasing ownership.

The snapshot worker also posted its successful result before its `finally` closed SQLite. Its parent can terminate the worker immediately on that message, interrupting handle cleanup. The success message now follows encoder closure, including an asynchronous close if supplied by the runtime. This removes a concrete cleanup race without adding filesystem sleeps, retries or skipped tests. The nine selected lifecycle/snapshot tests and existing busy-port case pass locally with concurrency one and a 192 MiB heap (`data/server-release-after.txt`, `data/server-busy-port-after.txt`). These results prove the ownership and shutdown ordering corrections; Windows-specific `EBUSY` resolution remains subject to the next exact-head CI run.
