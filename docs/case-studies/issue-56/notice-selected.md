# Check the selected HeadHunter chat before the unread list

HeadHunter can clear a conversation's unread badge as soon as it opens. The pinned C4 requirements still expect an eligible application update in that selected conversation to receive a reply first. On published commit `8b3554bc`, a one-chat pass visited chat 8 and sent its exact saved reply while the already-open chat 7 had a recognized application update. [Pinned requirements](https://github.com/konard/hh-job-application-automation/blob/fa0991b8c2d0896fb3b4be6c69947f0590094b15/docs/requirements/forms-and-chats.md#L247-L255)

In Automation, enable an acknowledgement reply policy, open a HeadHunter chat with a pending update, then leave the provider window inactive. Under **Unread conversations**, enable notice policies, set the maximum to one and confirm the pass. In the isolated Chromium fixture, the pass verifies complete history and sends the approved thanks in chat 7 before opening the unread list. The receipt identifies provider message `708`. The selected chat, filter and empty composer are preserved. The receipt counts the selected visit against the limit and distinguishes that scope from an unread-only pass. [Before](../../screenshots/issue-56/notice-selected/selected-before.png) · [After](../../screenshots/issue-56/notice-selected/selected-after.png)

A subsequent explicitly started repeating pass visits unread chat 8 once, confirms its own reply and stops on request. The same history, outbox and ownership guards govern both passes. Drafts, a later owner reply or a turn without an eligible saved answer leave remaining unread chats available for the ordinary pass. The focused history, notice, polling and receipt checks passed 60 tests each on Node and Deno.

The independent Playwright MCP run on a 390-pixel viewport verifies that setting controls leaves the synthetic provider unchanged. It starts a limited pass, sees receipt `708` with the approved thanks and confirms one send with no navigation to chat 8. Individual-watch reply visibility, authenticated HeadHunter and wider provider parity remain open under QA17.
