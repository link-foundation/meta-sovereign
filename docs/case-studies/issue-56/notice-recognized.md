# Reuse approved thanks for recognized HeadHunter updates

HeadHunter C4 calls for saved thanks when an employer uses new wording for a routine review, screening or application acknowledgement. The published `989c1e3a` planner accepts approved exact notice answers. The three focused recognized-mode regressions fail on that parent, where the policy value is unsupported. [Pinned requirements](https://github.com/konard/hh-job-application-automation/blob/fa0991b8c2d0896fb3b4be6c69947f0590094b15/docs/requirements/forms-and-chats.md#L239-L262)

In Automation, open Questions and saved answers, then Answer reuse policy. Save an approved notice answer for an earlier application update and choose **Reuse approved thanks**. The policy is available through the answer-policy command and both Lino encodings. Saving it starts no watch. Inspect the HeadHunter chat and explicitly start its inactive notice watch to use the policy.

The planner checks each clause of an English or Russian update and requires positive application status. It uses scoped and approved examples, prioritizes an approved exact decision and holds a tie between distinct reply wordings. It accepts the original optional HeadHunter employer link only with explicit informational wording and a matching bounded native destination if one is present. A matching binary question and completed delivery handover can precede a human acknowledgement. A pending question, request, draft or rejected saved answer keeps the reply out of automatic delivery.

In the native Chromium fixture, the same selected chat starts with a completed bot answer, a completed handover and the recruiter’s new update. The exact-only setting records zero sends. The recognized setting records zero while the tab has focus and adds outgoing message `102` with the saved thanks after the owner switches to a tab containing an unfinished draft. That unrelated draft is intact. The fixture targets an isolated routed provider page.
