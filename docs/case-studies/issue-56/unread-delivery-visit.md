# Borrowed unread-conversation visits

The finite unread scanner owns the provider's serialized queue for the entire navigation pass. The current-chat notice watch enters that queue for each read or write and also acquires a private inactive-view lease. Opening another watch from inside an unread visit would therefore wait for its own queue slot and contend with its own lease. The scanner now offers a private sequential `onConversation` callback with a handle borrowed from the existing visit. Public unread review remains read-only; policy delivery and polling are still required follow-up work.

The callback runs after the bounded full-history scan has returned its actual coverage and restoration receipt. A separate tail-only scroll control waits for two matching latest snapshots before admission. Its native input exemption accepts only the exact untrusted event witnessed by the existing inactive lease; unrelated input, actual pointer/keyboard activity, focus and changed drafts still revoke ownership. Reads and replies serialize on the borrowed handle, without entering the provider queue again. The handle expires on callback return. Cleanup drains any already issued reply before restoring the reading anchor and releasing the visit.

An initial native run found that the read-only navigation adapter did not forward `clickButton`. The send primitive correctly retained an unknown receipt, zero sends and a restored owner view. The adapter now forwards that method through its existing document, native-history and owner checks. A second native run confirmed both outgoing replies but exposed an inaccurate restoration offset: full-history traversal compensates for older messages prepended above the reader, while a tail-only reply adds a message below it. The tail control now restores its original offset before checking the original anchor, rather than applying the prepend compensation. It returns the actual restoration boolean independently of the positive send receipt.

Targeted default-off `MS_BROWSER_HISTORY_DEBUG=1` tracing then showed the original offset already restored while the mounted rows still belonged to the newest window. Background Chromium had deferred the scroll event that remounts those rows. Restoration now marks that pending event and waits for it within two seconds of additional settling, checking ownership on every observation. An unsettled scroll or interrupted view reports failure; unrelated provider loading retains the existing restoration behavior. The scanner stops visiting additional chats after a failed per-chat restoration. The synthetic send fixture also keeps its dynamically extended transcript renderer attached during later scrolling.

Focused unit checks cover stable-tail admission, bounded loading/instability, expired handles, cancellation before issue, in-flight receipt draining and actual restoration failure. Native Chromium checks use the default sender and real browser-commander over three synthetic chats. They require two sequential positive outgoing receipts, an unchanged original owner draft/selection/URL/filter/scroll, cancellation with no send, and owner interruption retaining the selected chat and new draft without a send or restoration. The provider fixture is synthetic and establishes no live account parity. The mandatory browser group uses native focus; unsupported engines explicitly refuse that capability.
