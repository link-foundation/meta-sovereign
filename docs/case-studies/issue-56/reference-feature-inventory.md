# Reference feature inventory

This is the implementation checklist for issue 56's six feature references. The source revisions and original repository/tree/README responses are preserved in `data/reference-snapshots.tar.gz`. References are read to understand behavior; their code is not copied or executed. A feature is complete only after CLI, API and UI controls and the relevant regression evidence are recorded. Existing related modules below identify integration points, not verified parity. Every unchecked row remains required work in PR 57.

The first source pass covers the six READMEs, HH's forms/chat and CV requirements, Telegram's sending scripts and VK's trigger entry points. Additional source/test auditing continues alongside implementation; this inventory must expand when that audit reveals another behavior. It is not yet a certificate of exhaustive coverage.

The HH browser scanner now explicitly selects all/unread conversations through the actual nested native control and restores the original filter/list position while owned. Two actual-parent regressions, focused Node/Deno, native Chromium and independent MCP evidence are in [filter ownership](chat-filter.md). This internal primitive leaves HH09, HH10 and QA17 unchecked: cross-chat state restoration, persistent unread orchestration, shared public controls and live-provider verification remain required.

A finite existing-view unread read API now visits actual main/child conversations through native SPA controls and restores owned URL/filter/draft/selection/scroll, with truthful incomplete coverage and Stop/shutdown draining; see [navigation evidence](chat-navigation.md). Existing forward history is protected, while added forward entries are explicitly reported. Repeated passes can now reuse precisely witnessed automation-created native forward entries; owner activity, navigation or changed entry IDs revoke reuse. See [repetition evidence](chat-repetition.md). Original history length remains explicitly disclosed. The finite pass now has confirmed CLI, text/binary Lino and shared localized Questions/Chat/Operator controls, durable non-replaying pass IDs and frozen per-chat reviews; see [unread review](question-unread-review.md). Persistent polling, policy delivery and live verification remain required; QA17, HH09 and HH10 stay unchecked.

## Shared questions, answers and application forms

Completed summaries and approved no-reply notices do not mask earlier requests; strict automatic selection waits for earlier actionable messages, while all-approved free-text turns may be prefilled without sending. Queued current-knowledge and full pending-context checks remain enforced. CLI, both Lino formats and shared Questions/Chat/Operator/watch controls are covered in [whole-turn evidence](whole-turn.md), alongside [rendered context](pending-turn.md). Complete provider history, activity ownership, inactive acknowledgements/rejections and unread orchestration remain required.

The actual-parent regression, 67 Node/Deno checks, CLI/both Lino formats/offline controls, production Chromium and independent MCP evidence are in [notice patterns](notice-patterns.md). Complete pending-turn/activity guards, unread orchestration and live-provider workflow parity remain required.

HH's `README.md` sections “Answer Chats”, “Prefill External Forms” and “The Resume as .lino Files”, plus `docs/requirements/forms-and-chats.md`, define behavior that issue 56 explicitly extends to **every provider**. Current integration points are `replies/`, `crm/conversation-questions.js`, `patterns/`, `automation/`, shared Chat and Operator. The shared `answer-questions` action now provides the foundation described in [question-answers.md](question-answers.md). Partial evidence below does not complete the advanced reference behaviors or actual provider execution.

Full provider parity and all unchecked rows remain required.
