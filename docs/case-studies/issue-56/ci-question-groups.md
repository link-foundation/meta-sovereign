# Keep all Questions browser scenarios within their existing budgets

Two exact-parent hosted runs exceeded the Questions subprocess's existing 180-second deadline. WebKit job [130487773262](https://github.com/link-foundation/meta-sovereign/actions/runs/43009884857/job/130487773262), for `1fb190ca`, reports `ETIMEDOUT` at full log line 2473 and a duration of 180,173 ms at line 2480. Chromium job [130501372720](https://github.com/link-foundation/meta-sovereign/actions/runs/43013880375/job/130501372720), for `50021c33`, reports the same error at line 2579 and 180,054 ms at line 2586. The last passing scenario differs between these runs. Neither establishes that its next scenario hangs.

The Questions entry point had accumulated the production question/profile UI plus seven additional provider, list, native-choice and watcher helpers. A bounded local Chromium measurement of the latter helpers confirms their cumulative cost: configured-provider choices took 28,909 ms, HH choices 46,324 ms, native chat lists 6,451 ms and virtual-list scans 84,493 ms. Those 59 cases alone took about 166 seconds. The separate controls measurement passed 18 cases: shared browser controls took 25,949 ms, summary choices 10,618 ms and current-chat watchers 46,690 ms.

The same scenarios now run in four mandatory groups: `questions`, `question-providers`, `question-chat-lists` and `question-controls`. Both hosted browser lanes run every group. Each new group closes its browser after the existing helpers close their own isolated servers/contexts. Per-scenario start, result and elapsed-time records make future failures attributable. The subprocess deadline remains 180 seconds and the browser-job deadline remains 35 minutes. No scenario, assertion or required engine was removed.
