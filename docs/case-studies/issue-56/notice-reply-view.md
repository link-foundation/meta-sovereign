# Reveal confirmed replies in the inactive HeadHunter watch

On published commit `96a86641`, an explicitly started notice watch could confirm message `102` while its bubble remained outside the provider pane. The provider fixture clears the sent composer by dispatching an untrusted `input` event. The view watcher treated that event as owner activity and kept the old scroll anchor. The same clipping occurred in ordinary and reversed panes. [Pinned C4 and C9 delivery rules](https://github.com/konard/hh-job-application-automation/blob/fa0991b8c2d0896fb3b4be6c69947f0590094b15/docs/requirements/forms-and-chats.md#L255-L263)

Run `node experiments/issue-56/notice-reply-view-probe.mjs` with a local Chromium binary. Start an individual inactive notice watch with the exact saved thanks, and open another tab. Once the guarded click issues, the two page observers recognize the same first synthetic empty input from the admitted composer. A unique new outgoing bubble with the expected text can then be revealed while the inactive view still belongs to the watch. The watch records one confirmed send.
