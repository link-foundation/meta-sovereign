# Native owner edits and deletion clocks

[PR #57](https://github.com/link-foundation/meta-sovereign/pull/57), issue #56.

Published `bd954afdf44e681abbf5d4cc97b1bd8ed50efb9a` checks received
replica records, but ordinary native HTTP handlers still call a trusted
unversioned write primitive. An edit after observing a remote record therefore
loses its causal context. A delayed packet rolls it back; physical deletion
allows resurrection, and recreation loses to an old deletion clock. Responses
also omit the clock actually needed by subsequent replication. Four finite
regressions reproduce these failures against that exact published commit.

Run `python3 -B experiments/issue-56/native-rich-check.py --owner --before`
for the four expected failures, then omit `--before` for the corrected checks.
The probe compiles the actual core, JSON reader, state, register, handlers,
email and route dispatcher with the real HTTP request/response declarations.
It does not compile a substitute merge or router. The complete network server
and wire dependencies remain covered by hosted Cargo and interoperability
checks.

Native owner admission joins stored and supplied observations before ticking
the opening's writer. A new assignment discards its prior assignment stamp;
replicated admission continues to merge without inventing an owner edit. Every
production mutating path uses checked admission: links, patterns, graphs,
replies, profile, resume, broadcast, and email pull/send. Successful responses
include the admitted record. Malformed records and exhausted counters return
HTTP 400 before mutation; previously these inputs could report success without
storing a usable record. Email imports prepare the complete batch before
committing either the rich record or typed mirror. Repeated IDs in one batch
observe the preceding admitted clock.

Owner deletion preserves only the ID, existing child links and a fresh clock,
plus the reserved deletion marker. Public reads and counts hide these records;
raw replication retains them. Repeated deletion advances the clock without
claiming that a visible record existed. A later recreation observes the
deletion before ticking its own assignment. Private/schema records retain
their separate local behavior and are excluded from raw replication. Trusted
restoration/test primitives remain available.

Each state opening receives a new nonsecret writer name using fresh standard
library randomized hash keys and a process-local sequence. An explicit actor
constructor supports reproducible fixtures. These names identify writes; they
are not credentials.

Ten focused Rust tests pass, covering the original four failures, malformed
and exhausted batch refusal, duplicate IDs, private-record isolation, sixteen
independent opening identities, every mutating route, email HTTP error status,
three concurrent writes and payload-free repeated deletion. Twelve fixtures
are generated by the actual production JavaScript `withCausalWrites` over its
memory store: supplied and observed clocks, assignment replacement, missing,
existing and repeated deletion, null/empty/ordered children, and recreation.
Run `node experiments/issue-56/native-rich-vectors.mjs --check` to check the
committed data against JavaScript. The existing hosted native interop test now
stores and fetches all twenty-one wire values inside real records in all four
representations, checking both their payload and admitted clock.
