# VK 好友问候（语言：[en](VK-FRIEND-GREETINGS.md) • [ru](VK-FRIEND-GREETINGS.ru.md) • [hi](VK-FRIEND-GREETINGS.hi.md) • zh）

打开 **连接 → VK → 手动输入 → VK 好友问候**。服务使用已配置的个人 VK API 凭据检查当前好友关系。离线时可以编辑设置，但无法审核 VK 状态或发送消息。自动计划默认关闭，仅在线好友筛选默认开启。

选择问候文字或原生 VK 贴纸 ID。非零贴纸 ID 会替代文字。设置对话最短沉默时间、每人间隔、检查好友数及发送上限。上限为零时不执行操作。可以仅选择空对话，也可以关闭在线筛选。首先排列空对话，再排列最早的对话；可选的好友总数排序优先。优先 ID 和共享的消息退出列表始终保护对应账户。

保存后点击 **审核当前状态**，查看确切内容及资格。确认只适用于已审核的计划，有效期为五分钟。每次发送前都必须重新核实实际好友关系、在线状态、未读状态、发送权限、完整且有界的历史及账户仍然一致。未读对话、服务事件、无法获取或不完整的历史以及未知发送结果都会暂缓。超过 1,000 条消息的对话不会仅凭末尾历史猜测资格。每批最多发送 100 次问候，检查 10,000 位好友，操作间隔为 30 秒。

开启自动计划后，本地应用服务器每分钟检查保存的间隔，并负责后台任务直到关闭。自动发送遵守安静时段。关闭服务器会停止新操作并中断发送间隔等待。手动确认不会开启自动计划。

CLI 使用相同的策略与持久存储：

```sh
meta-sovereign vk-greet status
meta-sovereign vk-greet save --message="你好！" --limit=3 --online-only=true --stale-days=30 --cooldown-days=7
meta-sovereign vk-greet plan
meta-sovereign vk-greet run --plan=THE_REVIEWED_PLAN_ID --confirm
```

本地 API 为 `/api/vk/greet`，操作路径为 `/plan` 和 `/run`。支持默认的 Lino 文本及二进制传输格式、同源写入检查和相同的明确计划确认。外部请求不能冒充自动计划执行。

只有收到正数的原生消息回执才会显示已确认。已确认的问候通过真实 VK 消息 ID 显示在 Chat 中；贴纸也保留原生 ID。回执丢失或无效时结果为未知，刷新或重启后不会自动重发。明确拒绝与未知送达状态分别保留。之后的新问候需要重新审核，并同时满足保存的沉默时间与每人间隔。
