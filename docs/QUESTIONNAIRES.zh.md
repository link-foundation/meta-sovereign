# 已保存的问卷

聊天、求职申请和外部表单共用回答规划器。读取当前规则以生成方案时，
它会从已保存的完整问卷中索引明确对应的编号回答。编号、项目符号和分行问题的
条件追问、说明及代码保留在所属问题中。对应关系不明确时保留整段；完整已保存回答优先。

即使完整回答已获批准，提取的分项仍需审核。服务和聊天限制、明确更正、当前薪酬及
联系方式上下文和缺失值检查仍然有效。读取不会写入派生规则或发送内容。新组合的问卷也需审核。

原生求职申请的预填和精确回答自动提交也要求已批准且无歧义的已保存回答。
提取、未批准或冲突的回答仍须由所有者审核，即使字段内容与其措辞相同。
所有者可以填写原生表单，再单独确认提交。

在 **问题与已保存的回答 → 从对话中学习** 中，可同时预览已保存问卷的分项及存档回答，
然后保存建议供审核。保存的措辞增加零次使用；只有实际发出的存档回复增加频率。
重复运行不会重复计数，也会保留批准状态。此操作不会下载服务商历史。

从实际观察的表单学习时，也会将完整回答和明确对应的分项保存为未批准建议，
保留相同的观察次数和证据。对应关系不明时保留整段。重复观察不会重复计数；
日志分别统计跳过的输入问答对和保存的建议。

离线命令：

```sh
meta-sovereign automations answers backfill-questionnaires
meta-sovereign automations answers backfill-questionnaires --apply
```

`answers learn` 包含相同操作。两种 Links Notation 编码均支持
`POST /api/automations/answers/backfill-questionnaires` 和 `/api/automations/answers/learn`。
`apply: false` 仅预览，`apply: true` 保存建议。容量不足或知识并发变化时拒绝应用；请重新预览。

## 原生申请上下文

在 CV 中开始单次申请或批量申请之前，可在申请设置中选择共享档案并配置薪资目标。
问卷的每个组成部分分别使用对应币种、税前或税后金额以及联系信息。回执显示已确认的
档案和固定目标。每次重新规划都会读取已保存档案的当前值；修改联系方式不会改变
固定的薪资目标。档案不存在时拒绝规划。组合答案需要人工审核，不能触发精确答案自动提交。

单次和批量申请 CLI 支持 `--profile-id` 和 `--salary`（使用共享薪资配置的
Links Notation 记录）。对应的申请打开及批量启动 API 支持 `profileId` 和
`salary`，并接受两种 Lino 编码。省略这些字段可保留原有行为。浏览器恢复存储中
仅保存申请标识。

## 答案末尾句点偏好

在**问题与已保存答案 → 答案复用策略**中选择带句点（默认）或不带句点，
然后保存。同一问题、相同批准和更正状态下，只有实际观察到 `Vietnam`
和 `Vietnam.` 两种写法时，规划器才合并真实次数和证据，并选择指定写法。
只有一种写法时保持原样。其他标点、大小写、不同问题及批准状态保持分开。
原始答案记录和聊天内容保持完整，重复学习不会重复计数。

独立的广义标点等价选项保留原有行为：启用时优先使用出现次数最多的原始
写法，此时末尾句点选择器禁用。保存失败会保留待保存选择并显示实际错误，
不会宣称更改已成功。

保存共享偏好：`meta-sovereign automations answers policy --answer-final-period=without`。
`answers plan`、`answers browser inspect`、`answers browser unread` 和
`automations plan` / `run` 支持 `--answer-final-period=with|without`、
环境变量 `ANSWER_FINAL_PERIOD` 或 `.lenv` 中的 `ANSWER_FINAL_PERIOD: "without"`。
用 `--configuration=path.lenv` 指定其他文件。优先级依次为显式参数、环境、
选定文件、工作目录 `.lenv`、已保存的回答动作、共享策略、最后为 `with`。
覆盖值不修改环境、已保存的动作或策略。浏览器审阅在监看和未读处理的再次验证中
保留此偏好；普通运行在确认发送前的检查中保留它。预览本身不启动提供商自动化。

两种 Lino 编码均支持向 `POST /api/automations/answers/policy` 发送
`{ policy: { answerFinalPeriod: 'without' } }`。规划请求中的
`answerFinalPeriod` 仅覆盖读取值。无效值会被拒绝，策略保持不变。
离线界面使用相同规划器与已保存偏好。

## 首选答案措辞

在每个已保存答案的**等价答案措辞，每行一个**中列出应改用上方答案的精确
措辞。偏好仅适用于此问题、已保存的等价问题及其提供方和聊天范围，不会推测
同义改写。例如，两次和三次已观察到的等价回复合并为首选答案的五次使用。
手动首选答案从零次开始。“一个月后”等不同承诺以及其他问题的答案保持独立。

批准仅适用于首选答案；未批准的偏好仍需审核。设置偏好不会发送回复。偏好
冲突或原始观察证据重叠时必须审核，不会静默累计次数。原始答案和消息保持
不变，重复学习不会增加计数。已拒绝短语仍被排除，选择题选项保持原文。

在线和离线编辑器仅在收到确认后显示保存成功；失败时保留草稿。刷新会读取
当前保存的偏好，删除所有行可清除它。CLI `answers save` 可接受一个字面值
`--equivalent-answer=<text>`。多个措辞请在 Lino 或 JSON 文件的首选答案上
设置 `equivalents: [text, text]`，然后运行
`meta-sovereign automations answers save preference.lino`。重新保存会读取文件
修改；省略字段会清除列表。两种 Lino API 编码都保留该字段。没有列表就不会
替换措辞。

## 开始工作的时间回答

对于明确询问何时开始工作的问题，共享规划和学习会排除没有可识别时间或
条件的回复，即使历史次数较高。此有限检查支持英语、俄语、印地语和中文，
接受数字日期并保留不同的时间承诺。封闭式时间问题仍可回答是或否；办公室
意愿、项目时长和性能指标等其他问题不变。这是有限措辞检查，并非通用语义
验证。原始保存答案和消息仍可查看且不会修改；没有可用答案时保持待审核。
