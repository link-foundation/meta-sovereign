# Chat loading and local data

The default app is [GitHub Pages](https://link-foundation.github.io/meta-sovereign/). A local JavaScript server supplies your messages and connected accounts; its localhost UI is optional. See [server setup and security](LOCAL-SERVER-SECURITY.md).

The Pages entry uses content-versioned script and stylesheet filenames, so reopening the latest build does not reuse an older interface from the browser cache.

If startup discovery fails, the hosted app retries after 5, 10, 20 and then every 30 seconds. Returning to the tab, making it visible or regaining network connectivity starts an immediate check. Checks never overlap; finding the server reloads the app once. Discovery and availability checks use `GET /api/status?probe=1`, a small identity response that never scans messages, aggregates contacts or verifies the store. The primary `127.0.0.1:8787` probe allows up to 15 seconds for a busy startup; other candidates retain their short deadline. Older servers can answer with their regular status response. Full statistics stay at `/api/status`; callers share one in-flight computation even when sync writes arrive, and a slow statistics request alone does not mark the server offline. Verification recognises the live binary mirror’s reads from the same authoritative text store, avoiding a second scan and repeated serialization of identical records. Independent stores still receive a full comparison. Availability probes are shared; two consecutive probe failures are required before the app changes to offline. A successful API response immediately restores availability, and a late failed probe cannot override it. Account status survives transport failures; only an actual disconnected-account response signs it out. Routine health checks use the store’s size, and typing polls maintain a live subset instead of repeatedly scanning the message archive. A failed browser connection does not mean the server process stopped. The offline notice describes the connection state and ongoing retries; passcode checks go only to a discovered local server.

## Opening and reading a conversation

A cached preview stays visible while the chat loads. A status above the messages explains foreground loading, background history, interrupted connections and Telegram's requested wait, including a retry countdown. Completed short conversations say **All available messages loaded** in the header. A short conversation can legitimately contain only a few messages; that completion state comes from the history returned by Telegram, not from the number of cached previews.

Opening a chat gives its requests `view` priority. A queued prefetch for that chat is promoted, and concurrent reads of the same page share one request. The background reader prioritises the open conversation before enumerating the entire chat list, while the app renews that preference every 30 seconds until the history is complete. Switching chats changes the foreground preference; abandoned views stop their retries. Telegram's rate limits still apply: the server respects the wait and returns HTTP 429 with `Retry-After` rather than reporting a gateway failure.

You can keep composing while history loads. Older pages load automatically as you approach the top, two screens ahead, while preserving your reading position. Idle partial history has no persistent saved-message notice or manual loading button. Active loading, interruptions and Telegram waits remain visible. This behavior is shared by Chat and embedded Operator cards. Cached messages and history coverage remain on disk, so a restart resumes missing history instead of discarding what was downloaded.

## Operator and navigation counts

**Operator** opens one unread conversation card at a time, without the chat list. The card includes history, unread context and the normal reply composer. Only positive unread message counts qualify; a manual unread mark with zero messages does not. Before selecting a Telegram card, the app refreshes that peer’s counters with `messages.getPeerDialogs`, without marking history, mentions or reactions read. Forum groups use the sum from a complete topic list: Telegram can retain a stale nonzero dialog aggregate even when every topic is read. Partial topic pages never imply zero; newer incoming messages and later read markers still update the count. The same correction feeds Chat, folder, title and Operator badges. Already-read candidates are skipped, including on Next. A failed check shows its reason and retries instead of inventing an empty queue. If a live update clears the current chat’s count, the queue advances. **Next (N)** leaves it unread and moves to the next conversation; **Done (D)** acknowledges the displayed message boundary and advances only after the server succeeds. A failed acknowledgement keeps the card with a retry message. Typing in a field never activates these shortcuts. New unread conversations enter the queue live; a finished queue says “No unread conversations.” Monochrome circles beside Chat, Calls and Operator show unread messages, unread missed calls and waiting conversations. Chat counts exclude muted conversations, matching the tab title; Operator counts conversations with unread messages, including muted ones. Badges cover all folders, while folder/type counts describe that filter; their accessible labels and tooltips explain the scope and unit. Zero counts are hidden; Calls uses “+” when older call history remains beyond the loaded recent page, and opening Calls acknowledges its notifications in this browser.

The conversation directory and live event stream are shared per API/account. Switching sections reuses the last successful snapshot immediately, and refresh requests coalesce. Server counters override older browser counters. A failed or partial load never replaces a known directory with an empty browser cache, and live updates received during a refresh override its older response. Initial loading, checking unread status and failed refreshes have distinct visible states.

## Message selection, suggestions and automation status

Click the empty space anywhere on a message’s line to start selection. Once selecting, clicking anywhere on the line toggles it; Shift-click extends a range. Drag across rows to select a range, including outside the centered bubble column. Right-click anywhere on that line opens the message or selection menu at the pointer. Bubble text and links retain their normal behavior before selection; long-press and the keyboard menu remain available. Escape closes a menu first, then clears selection. The behavior is shared by Chat and Operator. Selected rows and checkmarks stay monochrome in the default dark theme. See the official-client references in [CHAT-REFERENCES.md](CHAT-REFERENCES.md).

An empty composer can show relevant replies learned from your past conversations. Suggestions are unique across local/server replies and words. Answers for a previous chat or different typed text are never reused for the current composer.

A **Telegram Business bot** banner appears only when Telegram supplies a real positive bot ID. It names the bot (or its ID when no name is available) and says whether it is paused. It is separate from this app’s **Automations** menu, which labels each autopilot active, paused or off and shows the number running. Each item separately says whether automatic incoming/scheduled triggers are enabled, disabled, or the automation runs manually only. Opening that menu or viewing suggestions does not enable an automation.

## Folders and panel widths

Named Telegram folders keep their own row, order and unread counts. The global **All** tab is last by default. **Settings → Folder tabs → Always show “All” first** moves it first in this browser without changing the remote Telegram folder order. On startup, folder updates and column resizing, the strip scrolls horizontally to reveal the selected tab; a remembered named-folder selection is preserved. A second row provides **All / Private / Groups / Channels** inside every selected folder, including All. Folder and type choices are independent and remembered; narrowing a folder never silently switches to a global list. The same type selection applies to archived items when browsing the archive.

On desktop, drag the vertical dividers to change the navigation, chat-list and open-details column widths. Widths are saved in this browser. Focus a divider and use the arrow keys; Home and End choose its bounds. Double-click or press Enter to reset its width. Compact phone layouts keep their single-column navigation.

**Calls** is a main-menu section immediately after Chat; it shows recent and missed Telegram calls. Clicking a call opens that person's chat. Telegram's own account editor is under **Profile**. Default dark-theme controls use white SVG icons and neutral surfaces; contact photos, message content and meaningful status colours remain available.

## Durable application folder

The JavaScript CLI and server use a per-user folder, independent of the directory where the command runs:

| System  | Default store                                        |
| ------- | ---------------------------------------------------- |
| macOS   | `~/Library/Application Support/Meta Sovereign/store` |
| Windows | `%APPDATA%/Meta Sovereign/store`                     |
| Linux   | `${XDG_CONFIG_HOME:-~/.config}/Meta Sovereign/store` |

Messages, contacts, account sessions, sync cursors, history coverage, media, TLS material, logs and the application's browser profiles stay under that store. Desktop shells use `<userData>/store`. User-selected exports and explicit `--profile` paths remain where you choose. `--store=<directory>` and `META_SOVEREIGN_STORE_DIR` override the default.

Starting `serve` or `trust` from a checkout containing an older `.meta-sovereign` store migrates it once to the user folder. The operation takes the existing writer lock, moves the complete directory, preserves the certificate and protected key, and leaves a compatibility directory link so old media paths keep working. A running writer prevents migration. Two existing databases are never merged or overwritten: startup explains the conflict and asks you to select one with `--store`. The automatic move requires both locations on the same filesystem; otherwise the original data remains intact and an explicit store path can be used. An unused destination directory is preserved with a `.before-migration-<timestamp>` suffix. On Windows, directory moves retry temporary sharing/permission errors while keeping the writer lock, so a recently closed file or antivirus scan does not abort setup.

The standalone CV browser also uses this application folder. Its older default browser profile is moved when next opened, with a compatibility link; an existing `SingletonLock` prevents moving a profile still in use.

## Diagnostics and verification

The main log is `<store>/logs/meta-sovereign.log`, rotated by size. Refused requests include the origin, HTTP/HTTPS transport and Fetch Metadata site classification, without cookies, tokens or query strings. Late or duplicate WebRTC answers from another tab are ignored after negotiation; unexpected SDP failures are handled and retained as `client_rtc_negotiation_failed` warnings rather than unhandled promise rejections. A denied foreign origin is an access decision. Telegram waits are reported as waits; unexpected errors retain failure severity. Avatar retries are counted as informational pending media while retrying, with terminal resource failures retained as warnings.

Regression coverage includes a single cached message with delayed history, Telegram wait/retry, concurrent prefetch/open, focused backfill, every folder's type filters, column resizing and saved widths, Calls/Profile navigation, message sending with fixtures, store migration, certificate preservation and repeated store reopening. Chromium and WebKit exercise the browser flows, including failed startup and remount loads, stale zero-unread candidates, cached Operator recovery, automatic history loading, wide-row selection and menus. Tests also cover shared in-flight reads/events, live updates during refresh, account isolation, duplicate suggestions, missing Business bot IDs and scan-free routine health polling. Automated sends use fixtures and do not send messages to personal contacts.
