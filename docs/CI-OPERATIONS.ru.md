# Диагностика CI и выпуска (языки: [en](CI-OPERATIONS.md) • [zh](CI-OPERATIONS.zh.md) • [hi](CI-OPERATIONS.hi.md) • ru)

R-Z32 требует проверять именно публикуемый исходный код и сохранять диагностику. [Исследование issue 43](case-studies/issue-43/README.md) содержит исходные журналы и сравнение шаблонов.

## Локальная проверка и CI

Установите зависимости через `npm ci`. Локально проверяйте изменённые файлы и соответствующие тесты с `--test-concurrency=1`. Полную матрицу Node/Bun/Deno и ОС, Chromium, WebKit на macOS, Rust и сборки настольного приложения запускает GitHub CI. Тесты используют временные хранилища и отдельные серверы, не сервер пользователя.

Оба браузера выполняют одинаковый набор из `js/scripts/browser-checks.json`, включая восстановление соединений. Отсутствующий браузер, ошибка или превышение срока завершают проверку ошибкой. Артефакты загружаются после запуска тестового процесса; ошибка слияния или установки остаётся основной причиной.

Тест резервного копирования 200 тысяч записей выполняется только отдельной задачей CI: `RUN_BACKUP_STRESS=1`, предел кучи V8 — 384 МиБ. Обычные тесты его пропускают. Не запускайте нагрузочный тест на машине пользователя.

## Диагностика

Сначала сопоставьте время запуска и SHA с последним коммитом ветки. Сохраните журнал: `gh run view RUN_ID --log > run.log`. Найдите ошибочный шаг и отличайте ошибку теста, отказ API, отсутствие отчёта и отменённый устаревший запуск. Скрипт `experiments/issue43-runs.py` сохраняет журналы и аннотации исследования.

Проверка пакета разделяет установку с пустым кэшем и запуск; журналы npm и последние сообщения процесса находятся в `artifacts/pack/`. Браузерные журналы и `summary.json` — в `artifacts/browser/`. Архив Wayback предлагает исправление ссылки, но не делает неработающую исходную ссылку успешной. Отсутствующий или неверный отчёт также считается ошибкой.

Подробная диагностика по умолчанию выключена. Переменная репозитория `CI_BROWSER_DEBUG=1` включает трассировку Playwright; `CI_SCRIPTS_DEBUG=1` или отладка шагов/runner GitHub — диагностику загрузки помощников; `PACK_SMOKE_VERBOSE=1` — установку и запуск пакета. Используйте искусственные данные, никогда не записывайте токены, сессии, сообщения и учётные данные пользователя.

## Условия публикации и восстановление

Публикация ждёт итоговой проверки всех задач. Проверки отменяют устаревшие запуски; операции выпуска выполняются последовательно без отмены. После проверенного коммита допускается продвижение только версии, журнала изменений и changeset. Изменения исходников или зависимостей требуют нового успешного CI.

Для npm нужны Node 26.12.1 с закреплённой версией npm 12.2.1, `id-token: write` и trusted publisher для `link-foundation/meta-sovereign`, workflow `release.yml`. При необходимости администратор пакета должен первоначально настроить пакет и издателя в npm. Отказ обмена токена нельзя обходить непроверенной публикацией.

Включите **Settings → Security → Code security → Dependency graph**. В PR отсутствие возможности сообщается без секретов участника. На `main` отсутствие графа или издателя npm останавливает preflight до дорогих сборок и выводит инструкции настройки. Сетевые ошибки, ошибки авторизации и неверные ответы остаются ошибками.

Только точная версия или явный npm E404/GitHub 404 определяют наличие/отсутствие выпуска. Остальные ответы означают неизвестное состояние. Повторяются лишь известные временные сетевые/серверные ошибки в пределах общего срока. Для staged-версии проверяется доступность без повторной загрузки; отказ прав или политики немедленно останавливает выпуск. Отсутствующий GitHub release можно восстановить без повторной публикации существующей версии npm.

## Зависимости

Помощники выпуска закреплены в manifest/lockfile. Telegram использует поддерживаемый `teleproto` и слой совместимости; имя провайдера остаётся `telegram`. KaTeX обновлён. Нужные native install scripts явно разрешены для npm, Bun и Deno.

`electron-builder` закреплён на `27.0.0-alpha.13`: ветка 26.x всё ещё содержит устаревшие зависимости. Это предварительная версия инструмента сборки; все нативные цели должны пройти CI. Не скрывайте предупреждения и не подменяйте несовместимые major-версии. Тест lockfile запрещает записи deprecated.

Конфигурация сборщика v27 сохраняет файлы пакета, политику нативных модулей, desktop-файл и права macOS в новой схеме. Ad-hoc подпись использует `mac.sign.identity` и `mac.sign.sign`. Существующий канал updater 6 явно сохраняет неподписанные манифесты обновлений и артефакты Windows; для включения проверки Authenticode необходим настроенный издатель подписи. В staged updater точный npm alias заменяет устаревший `lodash.isequal` на `lodash.isequalwith@4.4.0`: без customizer оба метода возвращают тот же результат глубокого сравнения. Каждая установка проверяет настоящий кэш updater на копиях и изменениях метаданных и отсутствующем файле. Override удаляется после исправления upstream; alias на весь `lodash` небезопасен, поскольку возвращает объект-обёртку.

В Windows Deno до инициализации Telegram выбирается существующий WASM backend AES cifrante: создание native IGE в cifrante 0.6.0 завершает Deno 2.9.8 с `0xC0000005`. Выбор на других ОС и runtime сохраняется. Ограниченный `experiments/issue43-cifrante.mjs` проверяет путь приложения и шифрование/дешифрование; `--raw-native` явно воспроизводит сбой. `CI_CRYPTO_DIAGNOSTICS=1` включает трассировку этапов теста, по умолчанию выключенную. Проверки runtime и криптографии не пропускаются.

Команды desktop, реестра, мобильных платформ и package-smoke используют закреплённый `cross-spawn@7.0.6` для Windows npm/npx и экранирования аргументов. Массив аргументов с Node `shell: true` вызывает DEP0190; общий launcher использует `shell: false` и сохраняет ошибки команд. Регрессии запускают npm/npx с `--throw-deprecation`, проверяют буквальные аргументы и коды выхода.

Pre-commit передаёт lint-staged `--config package.json`, чтобы конфигурации из архивных снимков шаблонов не обнаруживались автоматически. Корневые исключения ESLint/Prettier сохраняют исходные данные. Регрессия с временным Git проверяет, что вложенные задачи не запускаются, а поддерживаемые файлы проходят корневые проверки.

GitHub test fixtures при завершении закрывают все свои соединения, включая keep-alive и незавершённые запросы; сервер приложения работает отдельно. `CI_FIXTURE_DEBUG=1` выводит число соединений и время закрытия (по умолчанию выключен). Лимит времени runtime job не увеличивается: исправляется управление соединениями fixture.

`MS_LIFECYCLE_DEBUG=1` выводит фиксированные имена этапов завершения, прошедшие миллисекунды и число собственных соединений без содержимого запросов и учётных записей. По умолчанию он выключен; Windows Node CI включает его. Регрессия keep-alive удерживает сброс хранилища в памяти, проверяя закрытие сокета отдельно от сохранения; затем обязательно освобождает сброс и ждёт полного завершения.

Node и WebKit используют закреплённый нативный пул `macos-26-intel` после повторных отказов GitHub выделить macOS ARM runner. Bun, Deno и сборка desktop сохраняют покрытие macOS ARM. Все девять сочетаний runtime/ОС и обе браузерные проверки остаются обязательными; очередь не считается успешной проверкой.

Все собственные сетевые fixture используют общий helper закрытия с учётом сокетов: GitHub, serverFetch, маршруты archive/WhatsApp/marketplace, локальные Pages и почтовые протоколы. Документация Rust отклоняет предупреждения в проверке и обоих путях релиза (`RUSTDOCFLAGS=-D warnings`). Временные Git fixture задают собственную политику LF, не меняя настройки пользователя.

Оба режима релиза изменяют только два корневых поля версии lockfile без разрешения зависимостей. CI запускает автономную репетицию `node experiments/issue-52/rehearse-release.mjs` для корневого и вложенного пакета. `CI_SCRIPTS_DEBUG=1` показывает версии и число пакетов. Desktop отклоняет неполные результаты upstream и явно отмечает блокировку. См. [аудит issue 52](../dev/log/issues/52/pulls/53/README.md).

Все задания, изменяющие внешнее состояние, используют общую группу параллельности репозитория/main без отмены. Проверки отменяют только свои устаревшие экземпляры с учётом матрицы. При конфликте отправки версии main загружается заново, проверяется идентичность исходников и пересчитываются метаданные; не более трёх попыток. Ошибки правил и аутентификации завершаются сразу. Изолированный `rehearse-push.mjs` проверяет настоящие локальные Git-репозитории без публикации.

CodeQL при выпуске и по расписанию требует корректный SARIF и отклоняет каждое неразобранное замечание. Два намеренных случая регулярных выражений проверены по правилу, пути, строке и SHA256 всего файла с указанными регрессионными тестами; изменение файла отменяет исключение. Отчёты сохраняются и при ошибке. Импорт HTML, CV и SVG использует закреплённый потоковый парсер; записи CV разрешают только канонические собственные поля. Для известной зависимости Pages временно фильтруется только `DEP0040` в одном шаге развёртывания; остальные предупреждения видны. Удалите фильтр после исправления и пересборки действия upstream.

Оба семейства CodeQL также проверяют каждый PR в main, включая изменения только документации, чтобы GitHub мог сопоставить все базовые конфигурации. Проверяйте общий результат CodeQL вместе с заданиями workflow. Ответы с ошибками и сохранённые описания содержат только первую строку сообщения с удалёнными секретами; выброшенные строки стека и преобразование произвольных объектов в строки не раскрывают кадры стека.

## Содержимое релизов и кэш npm

[Аудит issue 54](../dev/log/issues/54/pulls/55/README.md) сохраняет шесть указанных запусков и полные деревья шаблонов. После изменения версии локальные ссылки для создания и оформления GitHub-релиза преобразуются в точный SHA коммита; отсутствие обязательного релиза, отказ или неизвестный ответ API приводят к ошибке до записи. Заметки сохраняют все разделы changeset, блоки кода, буквальные escape-последовательности и ссылки на PR; большие тексты ограничены по байтам UTF-8 и содержат неизменяемую ссылку на полный changelog. Потребители только восстанавливают кэш npm; для каждого ключа workflow/ref/платформы назначен один писатель. Все шаги setup-node явно отключают неявное кэширование менеджера пакетов. Контрольные суммы архива доказательств проверяются в CI.

Аудит workflow также проверяет составные actions и Dependabot. Локальные actions используют синтаксис GitHub `$/...`; обычные обновления версий ждут семь дней, а обновления безопасности применяются без этой задержки. Закреплённая версия actionlint 1.7.12 не поддерживает этот синтаксис; узкое исключение связано с upstream issue 711 и проверяется на реальных ошибках.
