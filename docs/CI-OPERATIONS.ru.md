# Диагностика CI и выпуска (языки: [en](CI-OPERATIONS.md) • [zh](CI-OPERATIONS.zh.md) • [hi](CI-OPERATIONS.hi.md) • ru)

R-Z32 требует проверять именно публикуемый исходный код и сохранять диагностику. [Исследование issue 43](case-studies/issue-43/README.md) содержит исходные журналы и сравнение шаблонов.

## Локальная проверка и CI

Установите зависимости через `npm ci`. Локально проверяйте изменённые файлы и соответствующие тесты с `--test-concurrency=1`. Полную матрицу Node/Bun/Deno и ОС, Chromium, WebKit на macOS, Rust и сборки настольного приложения запускает GitHub CI. Тесты используют временные хранилища и отдельные серверы, не сервер пользователя.

Оба браузера выполняют одинаковый набор из `js/scripts/browser-checks.json`, включая восстановление соединений. Отсутствующий браузер, ошибка или превышение срока завершают проверку ошибкой. Артефакты загружаются после запуска тестового процесса; ошибка слияния или установки остаётся основной причиной.

Тест резервного копирования 200 тысяч записей выполняется только отдельной задачей CI: `RUN_BACKUP_STRESS=1`, предел кучи V8 — 384 МиБ. Обычные тесты его пропускают. Не запускайте нагрузочный тест на машине пользователя.

## Диагностика

Сначала сопоставьте время запуска и SHA с последним коммитом ветки. Сохраните журнал: `gh run view RUN_ID --log > run.log`. Найдите ошибочный шаг и отличайте ошибку теста, отказ API, отсутствие отчёта и отменённый устаревший запуск. Скрипт `experiments/issue43-runs.py` сохраняет журналы и аннотации исследования.

Проверка пакета разделяет установку с пустым кэшем и запуск; журналы npm и последние сообщения процесса находятся в `artifacts/pack/`. Браузерные журналы и `summary.json` — в `artifacts/browser/`. Архив Wayback предлагает исправление ссылки, но не делает неработающую исходную ссылку успешной. Отсутствующий или неверный отчёт также считается ошибкой.

Подробная диагностика по умолчанию выключена. Переменная репозитория `CI_BROWSER_DEBUG=1` включает трассировку Playwright; `CISCRIPTS_DEBUG=1` или отладка шагов/runner GitHub — диагностику загрузки помощников; `PACK_SMOKE_VERBOSE=1` — установку и запуск пакета. Используйте искусственные данные, никогда не записывайте токены, сессии, сообщения и учётные данные пользователя.

## Условия публикации и восстановление

Публикация ждёт итоговой проверки всех задач. Проверки отменяют устаревшие запуски; операции выпуска выполняются последовательно без отмены. После проверенного коммита допускается продвижение только версии, журнала изменений и changeset. Изменения исходников или зависимостей требуют нового успешного CI.

Для npm нужны Node 24 с npm не ниже 11.5.1, `id-token: write` и trusted publisher для `link-foundation/meta-sovereign`, workflow `release.yml`. При необходимости администратор пакета должен первоначально настроить пакет и издателя в npm. Отказ обмена токена нельзя обходить непроверенной публикацией.

Включите **Settings → Security → Code security → Dependency graph**. В PR отсутствие возможности сообщается без секретов участника. На `main` отсутствие графа или издателя npm останавливает preflight до дорогих сборок и выводит инструкции настройки. Сетевые ошибки, ошибки авторизации и неверные ответы остаются ошибками.

Только точная версия или явный npm E404/GitHub 404 определяют наличие/отсутствие выпуска. Остальные ответы означают неизвестное состояние. Повторяются лишь известные временные сетевые/серверные ошибки в пределах общего срока. Для staged-версии проверяется доступность без повторной загрузки; отказ прав или политики немедленно останавливает выпуск. Отсутствующий GitHub release можно восстановить без повторной публикации существующей версии npm.

## Зависимости

Помощники выпуска закреплены в manifest/lockfile. Telegram использует поддерживаемый `teleproto` и слой совместимости; имя провайдера остаётся `telegram`. KaTeX обновлён. Нужные native install scripts явно разрешены для npm, Bun и Deno.

`electron-builder` закреплён на `27.0.0-alpha.13`: ветка 26.x всё ещё содержит устаревшие зависимости. Это предварительная версия инструмента сборки; все нативные цели должны пройти CI. Требования runtime-пакета к Node не изменяются. Не скрывайте предупреждения и не подменяйте несовместимые major-версии. Тест lockfile запрещает записи deprecated.

Конфигурация сборщика v27 сохраняет файлы пакета, политику нативных модулей, desktop-файл и права macOS в новой схеме. Ad-hoc подпись использует `mac.sign.identity` и `mac.sign.sign`. Существующий канал updater 6 явно сохраняет неподписанные манифесты обновлений и артефакты Windows; для включения проверки Authenticode необходим настроенный издатель подписи. В staged updater точный npm alias заменяет устаревший `lodash.isequal` на `lodash.isequalwith@4.4.0`: без customizer оба метода возвращают тот же результат глубокого сравнения. Каждая установка проверяет настоящий кэш updater на копиях и изменениях метаданных и отсутствующем файле. Override удаляется после исправления upstream; alias на весь `lodash` небезопасен, поскольку возвращает объект-обёртку.

В Windows Deno до инициализации Telegram выбирается существующий WASM backend AES cifrante: создание native IGE в cifrante 0.6.0 завершает Deno 2.9.8 с `0xC0000005`. Выбор на других ОС и runtime сохраняется. Ограниченный `experiments/issue43-cifrante.mjs` проверяет путь приложения и шифрование/дешифрование; `--raw-native` явно воспроизводит сбой. `CI_CRYPTO_DIAGNOSTICS=1` включает трассировку этапов теста, по умолчанию выключенную. Проверки runtime и криптографии не пропускаются.

Команды desktop, реестра, мобильных платформ и package-smoke используют закреплённый `cross-spawn@7.0.6` для Windows npm/npx и экранирования аргументов. Массив аргументов с Node `shell: true` вызывает DEP0190; общий launcher использует `shell: false` и сохраняет ошибки команд. Регрессии запускают npm/npx с `--throw-deprecation`, проверяют буквальные аргументы и коды выхода.
