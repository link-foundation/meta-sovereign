# VK इतिहास प्रतिधारण

कनेक्शन → VK → इतिहास प्रतिधारण खोलें। शेड्यूल पहले बंद रहता है। चैट ID, संदेश संख्या की कड़ी सीमा और उससे बड़ी जाँच सीमा चुनें। ऋणात्मक और समूह चैट ID मान्य हैं। संरक्षित निरपेक्ष ID और वैश्विक ऑप्ट-आउट सूची छोड़ी जाती हैं।

समीक्षा में खाता, चुने इतिहास, प्रदाता तथा मेल खाने वाले स्थानीय संदेशों की संख्या और सुरक्षित हटाने की रसीदें दिखती हैं। केवल दिखाया गया प्लान पुष्ट करें। सेटिंग, कुंजी, खाता, इतिहास, स्थानीय सामग्री बदलने या समीक्षा की अवधि बीतने पर काम रुकता है। जाँच सीमा से बड़ा इतिहास नहीं हटता।

वर्तमान messages.deleteConversation केवल इस खाते के लिए इतिहास हटाता है। केवल स्पष्ट VK त्रुटि 3 मिलने पर messages.delete में समीक्षित cmids और delete_for_all=0 उपयोग होते हैं; हर बैच अधिकतम 100 और दो सेकंड की दूरी। टाइमआउट, खोया उत्तर या अमान्य पुष्टि पर न वैकल्पिक विधि चलती है न स्वतः दोहराव। स्थानीय सफ़ाई से पहले प्रदाता इतिहास दोबारा पढ़कर परिणाम जाँचा जाता है।

आंशिक काम में पुष्ट ID और रसीदें सुरक्षित रहती हैं। पुनः शुरू करके शेष मूल संदेशों की मैन्युअल समीक्षा करें; शेड्यूल आंशिक काम नहीं दोहराता। स्थानीय रिकॉर्ड ID, चैट, पाठ और समय से मिलते हैं। सामग्री पुनर्प्राप्त करने योग्य चिह्न के नीचे बचती है और कारण-संगत सिंक बना रहता है। अन्य प्रदाता और असमीक्षित रिकॉर्ड नहीं बदलते। डेटा भौतिक रूप से नहीं मिटता।

अग्रभूमि CLI:

```sh
meta-sovereign vk-retention save --peers=9,-12 --threshold=1000 --scan-limit=2000 --enabled=false
meta-sovereign vk-retention plan
meta-sovereign vk-retention run --plan=<reviewed-plan-id> --confirm=true
meta-sovereign vk-retention status
```

`/api/vk/retention` · `POST /plan` · `POST /run` · Lino text / binary.
