# Токен пользователя VK

В **Подключения → VK** можно проверить готовый пользовательский токен или
вставить точный адрес `https://oauth.vk.com/blank.html#…`. Настольное приложение
также открывает изолированное окно **Авторизоваться через Kate Mobile**.
VK может отказать этому историческому клиенту или запретить доступ к сообщениям.
Страница входа сама по себе не подтверждает работоспособность авторизации.

Перед запуском JS-сервера или настольного приложения задайте
`MS_SECRET_PASSPHRASE` согласно разделу о защите секретов в
[руководстве](USER-GUIDE.ru.md). При каждом запуске нужен тот же пароль.
Без защищённого хранилища сохранение запрещено. Остальное содержимое базы
эта настройка не шифрует.

Подтверждайте замену отдельно для каждой попытки. Проверка читает профиль,
разрешения и счётчик одного запроса бесед, не отправляя сообщений. Токен
сохраняется как защищённый `secret:vk:user-token`, общий для чтения и публикаций.
Старые реквизиты остаются резервными. При запрете сообщений действительный
пользовательский токен сохраняется с явным указанием ограничения. Недействительные
токены, токены сообществ и несовпадающие аккаунты отклоняются. После ошибки
хранилища проверьте состояние перед повторной попыткой.

Поле пароля очищается при начале импорта. Ответ содержит идентификатор операции,
проверенный аккаунт и возможности, без токена и вставленного URL. Отмена ждёт
завершения принадлежащей операции работы; уже подтверждённое сохранение остаётся
успешным. Перезагрузка только читает состояние, не повторяет импорт и не
восстанавливает согласие. После перезапуска сервера временное состояние операции
сбрасывается, а защищённый токен сохраняется.

```sh
node js/bin/meta-sovereign.js vk-token status
node js/bin/meta-sovereign.js vk-token start --confirm
node js/bin/meta-sovereign.js vk-token import --confirm
node js/bin/meta-sovereign.js vk-token cancel --id=<operation-id>
```

Импорт запрашивает секрет скрытым вводом: не передавайте токен аргументом.
После start/import читайте status до завершения. Окно авторизации доступно
только в настольном приложении, импорт — и на сервере. `--url` принимает HTTPS
или локальный HTTP-адрес. Общие `GET /api/vk/token` и
`POST /api/vk/token/{start,import,cancel}` работают в текстовой и бинарной
Links Notation: start/import требуют `confirm: true`, import — `value`,
cancel — текущий `id`. Неопределённый запрос автоматически не повторяется.
[Воспроизводимые проверки](case-studies/issue-56/vk-token.md).
