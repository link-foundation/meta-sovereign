# Requirements discussed on 2026-10-31

This ledger preserves the requested scope across development sessions. A passing
focused check is not a claim that all providers or all runtime/browser matrices
have been verified. GitHub CI runs full suites; local checks use specific tests
with limited concurrency and temporary fixtures, separate from the running app.

## Shared messaging and interaction requirements

- Consistent vertical alignment, spacing, delivery indicators and monochrome
  controls across Chat, Operator and other affected surfaces.
- Automatic server/provider reconnection, loading and queued-message retry.
  Avoid redundant failure banners or manual recovery requirements. After a real
  Telegram connection, browser-only mode is an explicit Settings choice.
- Keep edited and deleted message versions on the server while the browser is
  closed, preserving observed history after provider data disappears. Display
  their controls in one compact bar.
- Place Unread immediately after All. Preserve configurable start/end ordering,
  defaulting to the current end/newest behavior.
- Mention, quote, search and pinned-message navigation loads the actual message
  and briefly highlights it, including when already visible.
- Context menus clearly mark their target and include Select. Reuse persistent
  full-row selection behavior, without silently altering the selected set.
- Share message/composer/scroll logic between Chat and Operator. No messages may
  sink behind the composer during typing, sending, incoming updates, suggestion
  changes, media loading or header resizing. Preserve older reading positions;
  avoid oversized footer gaps.
- Retire the opening unread divider when its opening messages are confirmed
  read; new live arrivals must not resurrect it.
- Upload percentages and bar geometry agree. Distinguish uploading from provider
  confirmation, recover safely, and render the confirmed attachment immediately.
- Apply the common blur/surface treatment to sticker, emoji and other popovers.
- Automation tests give immediate feedback, show useful closable previews, reuse
  existing pending drafts, and provide a read-only next-matching-chat action.
- Show today's birthdays by default; tomorrow is optional. Hide today's contacts
  already congratulated. Keep both preferences configurable.
- Empty conversations have a deliberate shared empty state.
- Suggestions stay previews until explicitly selected. Use middle ellipsis for
  long alternatives, deduplicate real suggestions, distinguish observed sent
  messages from generated continuations, and omit unhelpful tiny word choices.
- Indicate explicitly deleted accounts in lists, headers and profiles. Unknown
  numeric provider IDs are labeled in profiles rather than displayed as names
  or confused with phone numbers.
- Keep chat-list interaction immediate, rows bounded, unchanged rows reusable
  and avatars prefetched ahead of scrolling. The splitter lives on the right
  of the list and must not intercept its scrollbar.
- Recover stalled media and quoted thumbnails automatically, including requests
  that remain pending without native error events.

These areas have implementations and focused regression coverage in the shared
components. The latest typing/header overlap regression and diagnostics are part
of the current delivery; production verification remains necessary after deploy.

## Learning, facts and history review

- Default-on, configurable read-only conversation skills retain source-backed
  questions/answers, professions, reciprocal friendship agreements, address form
  and shared profile links. Explicit reply context can continue the earlier
  programmer → GitHub thread rather than only answer the last message.
- Facts, Replies and Patterns must show learned history, not only manually saved
  definitions or a false "connect first" message.
- Start discovery with meaningful-word frequencies. Default minimum frequency:
  **five**. Exclude common function words. Only qualifying messages seed
  discovery; answers remain evidence for qualifying questions. Keep adjacency
  and explicit reply links accurate. Show the threshold and history coverage,
  and allow changing the threshold.
- Use bounded caches and existing indexes; do not build another full archive
  copy for each page. Repeated question comparisons must not repeatedly tokenize
  and classify the same strings.

The frequency-filtered history library and its three page integrations are in
the current delivery, with focused unit and isolated WebKit coverage.

## Feedback and people

- Add Feedback, defaulting to **my messages**, ranked by received reactions.
- Cover saved messages from connected public channels/chats and other supported
  services, with explicit filters and a provider capability contract.
- Retrieve available reaction authors with pagination, preserve evidence locally
  and show it in profiles ("reacted … to …"). Provide a private-chat action for
  actual known identities, without sending automatically.
- Keep anonymous counts useful without inventing hidden authors or interpreting
  a reaction as proof of shared beliefs. Record unsupported live APIs honestly.
- Collect in the background while the server runs, including when the client is
  closed. Default-on collection/profile evidence have persistent opt-outs.

Implementation, limitations and provider follow-ups are in [Feedback](FEEDBACK.md).
Live author collection currently targets Telegram; other providers can supply
normalized saved observations. Their remaining live adapters are open work.

## Connection status

- Telegram configured on the server must appear connected in Connections and
  other relevant surfaces, even though secrets are intentionally absent from
  browser storage. Distinguish connection state from saved-credential presence,
  reconnecting state, missing data and loading.

The server-status-based UI correction is in progress in the current delivery.

## Stickers and collections

- Rename Greetings to **Stickers** while preserving existing saved selections
  and routes.
- Support provider-specific collections, including default greeting collections
  for VK and Telegram, and other providers where stickers are supported.
- Load Telegram's sticker catalogue and render its real supported formats.
- Configure collections by category; offer automatic categorization from
  available labels, emoji and metadata where reliable. Keep uncertain results
  editable and preserve provider-specific send capabilities.

This newly requested work remains open until implemented and verified.

## Reliability, resources and delivery

- Pull GitHub changes, reconcile current work, commit and push completed changes,
  review GitHub CI/CD, and keep/start the server so the user can test.
- Never run full suites, stress tests or complete matrices on the user's machine.
- Identify actual causes of high CPU and 3.5–6 GB memory, fix retention and
  excessive repeated work, and add useful bounded diagnostics when absent.
- Check logs for real failures and misleading warnings/successes; do not silence
  failures merely to make logs look clean.
- Follow [Product Vision](PRODUCT-VISION.md) and pinned [Chat References](CHAT-REFERENCES.md):
  T3 Code for visual style/configuration, Telegram for common messaging behavior,
  original implementations and accurate capabilities across providers.

Resource work already moved cold provider payloads and snapshot work off the
main heap, bounded reply/context caches and added periodic resource diagnostics.
Large-archive metadata/index retention still needs reduction; a lower RSS alone
does not prove that the memory problem is solved. The current delivery removes
repeated question classification/tokenization and limits layout-log flooding.
Continue measuring the deployed worker and keep unresolved resource work open.
