# Руководство пользователя (languages: [en](USER-GUIDE.md) • [zh](USER-GUIDE.zh.md) • [hi](USER-GUIDE.hi.md) • ru)

Эта страница собирает пользовательские сценарии `meta-sovereign` в одном месте. Они упорядочены от “ничего не устанавливать” до “установить все”, чтобы можно было остановиться сразу после нужного варианта.

> **TL;DR:** откройте <https://link-foundation.github.io/meta-sovereign/>. Это все web-приложение. При необходимости запустите локальный Rust server или JS server, чтобы синхронизировать данные между устройствами.

## 1. Ничего не устанавливать — открыть web app

1. Откройте <https://link-foundation.github.io/meta-sovereign/> в Chrome, Firefox, Safari или Edge.
2. App запускается сразу. Нет sign-up, нет telemetry, и данные не выходят из браузера, пока вы не укажете server.
3. Данные хранятся в browser-local storage ([`createBrowserStore`](../js/src/storage/browser-store.js): IndexedDB → localStorage → memory). Уже можно:
   - просматривать и искать импортированные contacts;
   - создавать chat patterns и reply variations;
   - собирать broadcasts и outreach plans;
   - triage чатов через operator UI.

Если вы используете один device, этого достаточно.

## 2. Добавить локальный Rust server (preferred)

Rust server — один binary без runtime и с самым быстрым cold start. Он exposes тот же wire protocol, что и JS server (см. [`docs/SERVER-PARITY.ru.md`](./SERVER-PARITY.ru.md)).

```bash
git clone https://github.com/link-foundation/meta-sovereign
cd meta-sovereign
cargo run --manifest-path rust/Cargo.toml -p meta-sovereign-server -- serve
```

Server слушает <http://127.0.0.1:8787> по умолчанию. SPA на GitHub Pages найдет его автоматически через saved override (`metaServer` в `localStorage`) и список портов `127.0.0.1`.

Если browser не подключился, откройте **Settings → Server** и вставьте URL, который напечатал Rust binary.

## 3. Добавить локальный JS server (fallback)

Используйте этот вариант, если нет Rust toolchain или нужны routes, которые Rust server еще не догнал: `/api/backups`, `/api/export-encrypted`, `/api/links/purge-tombstones`, `/api/outreach`.

```bash
npm install -g meta-sovereign
meta-sovereign serve
```

Или через Bun:

```bash
bunx meta-sovereign serve
```

JS server слушает тот же port и говорит тем же wire protocol; SPA не важно, какой backend на другой стороне.

Если npm отвечает `404` (пакета еще нет в npm), запустите тот же server прямо из GitHub:

```bash
npx -y github:link-foundation/meta-sovereign serve
```

## 4. Установить desktop или mobile app

Desktop и mobile apps заворачивают тот же SPA с GitHub Pages и встроенный server в native shell. Используйте их, если нужно полное приложение без отдельного запуска server.

### Desktop (Linux, macOS, Windows)

Откройте <https://link-foundation.github.io/meta-sovereign/download/>. Страница определяет вашу систему, предлагает подходящий installer из самого нового release и показывает все остальные сборки. Каждый файл также приложен к [GitHub releases](https://github.com/link-foundation/meta-sovereign/releases).

| Система | Файлы (x64 и arm64)                                                     |
| ------- | ----------------------------------------------------------------------- |
| Linux   | `.AppImage` (обновляется сам), `.deb`, `.tar.gz`                        |
| macOS   | `.dmg` (перетащите в Applications), `.zip`                              |
| Windows | `windows-installer` `.exe` (обновляется сам), `windows-portable` `.exe` |

Первый запуск:

- **macOS.** Сборки без Apple Developer ID подписаны ad-hoc, поэтому macOS блокирует первый запуск («Apple could not verify…»). Откройте System Settings → Privacy & Security и нажмите **Open Anyway**. Такие сборки не обновляются сами; новые версии скачивайте со страницы.
- **Windows.** Если SmartScreen показывает «Windows protected your PC», нажмите **More info** → **Run anyway**.
- **Linux.** `chmod +x meta-sovereign-desktop-linux-*.AppImage` и запустите его, или установите `.deb` через `sudo apt install ./<file>.deb`.

Проверьте скачанный файл по `SHA256SUMS.txt` из release: в разделе **Verify your download** на странице загрузки (выберите файл и `SHA256SUMS.txt`; ничего не покидает браузер) или в терминале:

```bash
sha256sum --check --ignore-missing SHA256SUMS.txt
gh attestation verify <file> --repo link-foundation/meta-sovereign
```

Приложение хранит данные в системной папке приложений пользователя, поэтому они переживают обновления. Чтобы собрать installers самостоятельно: `npm i --no-save electron-builder@^26 && npm run desktop:build -- --linux --x64` (см. `js/scripts/build-desktop.mjs`).

### Mobile и development сборки

| Platform | Build command                                       |
| -------- | --------------------------------------------------- |
| Electron | `npm run electron` (запуск из исходников)           |
| iOS      | `npm run mobile:ios` (открывает Xcode)              |
| Android  | `npm run mobile:android` (открывает Android Studio) |

Electron и Capacitor shell переиспользуют `js/src/web/` без изменений, поэтому UI совпадает с приложением на GitHub Pages.

## 5. Подключить SPA к server

[`discoverServer()`](../js/src/web/discover.js) выбирает server так:

1. **Same origin** — когда SPA отдается прямо JS или Rust server.
2. **Saved override** — `localStorage.metaServer = "https://my-server"`, задается через **Settings → Server**.
3. **Runtime shell candidates** — Electron и Capacitor inject URL встроенного server.
4. **Порты `127.0.0.1`** — default server port probe-ится автоматически.
5. **Caller-supplied LAN candidates** — список передается программно.

Если ничего не отвечает, SPA остается в **offline mode** и пишет в local browser store. Когда server появляется позже, [`OfflineClient`](../js/src/web/client.js) replay-ит queued writes.

В offline mode hosted app показывает уведомление **browser-only mode** с командами запуска локального server, кнопкой **Check again** и ссылкой на desktop app. Imports, automations, sync, CV sync и greetings требуют server. Contacts, patterns и broadcasts продолжают работать из browser store.

Hosted app живет на `https://link-foundation.github.io`, поэтому браузер сначала спрашивает у локального server разрешение (CORS). JS server по умолчанию разрешает этот origin и Capacitor app. Чтобы разрешить другой origin, например вашу копию SPA:

```bash
meta-sovereign serve --allow-origin=https://example.org
# или: MS_ALLOW_ORIGINS="https://example.org https://link-foundation.github.io"
# --allow-origin=none выключает cross-origin доступ
```

По умолчанию интерфейс — размещённое приложение. `serve` печатает его
адрес, приложение само находит сервер на порту 8787, а своя копия сервера на
<http://127.0.0.1:8787> остаётся запасной (Safari, нет интернета).
Чтобы её не отдавать:

```bash
meta-sovereign serve --local-ui=false   # или MS_LOCAL_UI=off
# теперь / открывает размещённое приложение; --ui-url=<url> задаёт другую копию
meta-sovereign serve --tls=false        # или MS_TLS=off — отключает HTTPS
```

Заметки о браузерах:

- **Chrome и Edge** (и новые версии Firefox) один раз спрашивают, может ли страница обращаться к устройствам в локальной сети. Разрешите.
- **Safari** не пускает `https` страницы на `http://127.0.0.1`, но server теперь также отвечает по HTTPS на том же порту с самоподписанным сертификатом для localhost. Чтобы hosted app в Safari подключался напрямую, доверьте сертификату один раз: выполните `npx -y meta-sovereign trust` (macOS добавляет сертификат в login keychain; на других системах печатается путь к нему) или откройте `https://127.0.0.1:8787/trust` в Safari, нажмите **Подробнее → зайти на этот сайт** и введите пароль, затем нажмите **Check again**. После этого hosted app в Safari работает напрямую. До доверия уведомление даёт ссылки **Открыть приложение с сервера** (<http://127.0.0.1:8787>) и **Доверять серверу** (<https://127.0.0.1:8787/trust>). `--tls=false` / `MS_TLS=off` отключает HTTPS; копия приложения с сервера остаётся запасным вариантом.

## 6. Sync между устройствами (WebRTC)

Когда устройства используют один server (Rust или JS), они sync-ятся через WebRTC и server endpoint `/rtc` ([`webrtc-sync.js`](../js/src/web/webrtc-sync.js)). Трафик peer-to-peer; server нужен только для initial handshake. Для symmetric NAT см. [`docs/WEBRTC-TURN.ru.md`](./WEBRTC-TURN.ru.md).

## 7. Encrypted backup and export

Данные encrypted-at-rest by default ([`vault.js`](../js/src/storage/vault.js), AES-256-GCM, master key + passphrase/PIN/passkey/TOTP unlocks).

Экспорт encrypted snapshot из CLI:

```bash
meta-sovereign export-encrypted --file=backup.lino.gcm --passphrase='…'
```

Также доступен `POST /api/export-encrypted` из SPA, подключенного к JS server. Rust server пока не exposes этот route; в этом случае используйте CLI.

## 8. Import данных

Положите archive files в `~/.meta-sovereign/imports/` (configurable) и выполните:

```bash
meta-sovereign import
```

Supported sources: email (`.eml`/mbox), VK, Telegram Desktop, X, WhatsApp, Facebook, LinkedIn, career.habr.com, hh.ru, superjob.ru. Полный список — в [`docs/REQUIREMENTS.ru.md`](./REQUIREMENTS.ru.md), section E.

Для live email используйте `source-pull --source=email --protocol=gmail`, `microsoft-graph`, `jmap`, `imap` или `pop3`. Raw IMAP/POP3/SMTP требуют `--host`, `--username`, `--password`, если не заданы эквивалентные `EMAIL_*` env vars.

### Импорт через браузер

На карточке каждого сервиса в **Подключениях** — два отдельных способа:
**Импорт через браузер** (рекомендуем) и **Ввести вручную** (ключи API,
файл выгрузки или вставленный текст). На странице сервиса это две
вкладки, а адрес (`#conn-<service>` или `#conn-<service>/manual`)
сохраняет открытую вкладку после перезагрузки. **Импорту через браузер**
нужен JS server (`meta-sovereign serve`, Node.js 22.12 или новее) на этом
же компьютере; он
управляет Chrome через
[browser-commander](https://github.com/link-foundation/browser-commander).

1. Нажмите **Открыть браузер**. Сервис откроется в отдельном окне Chrome
   со своим профилем (`<store>/auto-import/profiles/<service>`, доступ
   только владельцу), поэтому войти нужно один раз.
2. Запустите там выгрузку данных. Каждый файл, скачанный в этом окне,
   перехватывается; ZIP и tar.gz распаковываются, файлы выгрузки
   импортируются.
3. В Telegram Web и WhatsApp Web выгрузки нет: откройте чат и нажмите
   **Сохранить этот чат**.
4. Нажмите **Готово** или закройте окно. Браузер без действий
   закрывается сам через 30 минут.

**Входы из ваших браузеров (рекомендуем).** Вверху **Подключений**
кнопка **Найти входы** показывает все браузеры на компьютере (Chrome,
Safari, Firefox, Edge, Brave, Arc, Яндекс Браузер и другие) и сервисы, в
которые в каждом выполнен вход. Для этого читаются только имена сайтов.
**Использовать эти входы** копирует cookies этих сервисов из отмеченных
браузеров в файл, доступный только владельцу
(`<store>/auto-import/sign-ins/<service>.json`); следующее окно импорта
этого сервиса откроется с выполненным входом, а копия удалится. Браузеры
только читаются, ничего не покидает компьютер. Telegram Web и WhatsApp
Web хранят вход не в cookies, поэтому один раз отсканируйте их QR-код.
В macOS данные Safari требуют **полного доступа к диску**: панель
называет приложение, которому его нужно дать (ваш терминал или
настольное приложение), и открывает «Системные настройки» →
«Конфиденциальность и безопасность» → «Полный доступ к диску»; после
этого перезапустите сервер. Chrome может один раз запросить пароль
связки ключей.

Сервисы упорядочены по числу пользователей, самые крупные вверху,
поэтому Email — первым.

Серверу нужно право запускать процесс браузера и писать в каталог
хранилища. Необязательные настройки:

| Переменная                                     | Что делает                                                                                                                                |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `MS_BROWSER_CDP_URL`                           | Подключиться к уже запущенному Chrome (`chrome --remote-debugging-port=9222`, затем `http://127.0.0.1:9222`). Для Docker, где нет экрана. |
| `MS_BROWSER_CHANNEL` / `MS_BROWSER_EXECUTABLE` | Другой браузер на Chromium.                                                                                                               |
| `MS_BROWSER_HEADLESS=1`                        | Без окна (только для профилей, где вход уже выполнен).                                                                                    |
| `MS_BROWSER_VERBOSE=1`                         | Отладочные логи browser-commander.                                                                                                        |

В Deno запускайте сервер через `deno task serve` — он даёт `--allow-run`
для процесса браузера. Импорт можно запустить только из самого
приложения: запросы с других сайтов сервер отклоняет.

## 9. Sync CV между job platforms

CV обычно живет одновременно на LinkedIn, hh.ru, Habr Career, Naukri,
VietnamWorks, TopCV и SuperJob, и эти семь копий расходятся.
`meta-sovereign` читает их все через браузер на вашей машине, показывает
различия и записывает согласованные значения обратно.

Для этого нужен CLI: web page не может управлять другой web page,
поэтому экран **CV** в приложении показывает покрытие, различия и историю
запусков, а сами запуски отдает терминалу.

```bash
# один раз: поставить browser engine (optional dependency)
npm install playwright browser-commander
npx playwright install chromium

# что поддерживается и насколько markup уже проверен
meta-sovereign cv-platforms

# войти один раз в видимом браузере; session сохранится в profile
meta-sovereign cv-read --platforms=linkedin --headed --profile=~/.meta-sovereign/cv

# прочитать несколько профилей, сохраняя snapshots страниц
meta-sovereign cv-read --platforms=linkedin,hh,naukri --login=<ваш-логин> --artifacts=./cv-runs

# сравнить прочитанное — браузер не нужен
meta-sovereign cv-diff --prefer=linkedin

# посмотреть, что изменит sync, и выполнить его
meta-sovereign cv-sync --platforms=linkedin,hh,naukri
meta-sovereign cv-sync --platforms=linkedin,hh,naukri --apply

# записать одно поле или одну секцию редактора и ничего больше
meta-sovereign cv-sync --platforms=linkedin --paths=basics.headline --apply
meta-sovereign cv-sync --platforms=linkedin --groups=intro --apply

# что происходило в последних запусках
meta-sovereign cv-telemetry --type=step.miss
```

Пароль платформы никто не спрашивает: браузер открывается с `--headed`,
вы входите как обычно, а session остается в указанном profile directory.

Те же операции доступны по HTTP, когда запущен локальный server:
`GET /api/cv/platforms`, `GET /api/cv/plan?platform=…`,
`GET /api/cv/stored`, `POST /api/cv/read`, `POST /api/cv/compare`,
`POST /api/cv/sync`, `GET /api/cv/telemetry`.

| Симптом                               | Что это значит                                                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `browser-commander is not installed`  | Поставьте optional dependencies выше или используйте `cv-platforms` / `cv-plan` / `cv-diff` — они браузер не открывают. |
| Запуск остановился с `login-required` | Платформа перебросила на страницу входа. Повторите с `--headed` и войдите.                                              |
| Запуск остановился с `step-missed`    | Сайт изменил markup. В причине указан selector; `cv-telemetry` и HTML из `--artifacts` показывают страницу.             |
| Платформа сообщает `unsupported`      | Для этого поля у платформы нет редактора — изменение не теряется молча, а попадает в отчет.                             |
| Поле помечено `deselected`            | Оно записываемое, но ваш фильтр `--paths`/`--groups` его не выбрал.                                                     |
| Экран CV говорит, что нужен JS server | Подключенный backend (например, Rust server) не отдает маршруты `/api/cv/*`.                                            |

Подробности — канонический формат CV, словарь шагов, события telemetry и
что именно проверено на каждой платформе — в
[`docs/CV-SYNC.ru.md`](./CV-SYNC.ru.md).

## 10. Начать диалог с привета или стикера

Начать диалог — самая медленная часть общения с людьми. Экран
**Приветствия** отправляет за вас «привет» или приветственный стикер,
как это делает [konard/vk-bot](https://github.com/konard/vk-bot) во VK,
чтобы вы сразу перешли к сообщению, которое действительно хотите
проверить.

1. Откройте **Приветствия**. Сетка стикеров показывает приветственные
   стикеры VK (картинки грузятся прямо с vk.com) и thumbs-up из
   Messenger. Отметьте те, которыми хотите приветствовать.
2. Нажмите **Получить стикеры из сетей**, чтобы подтянуть больше из ваших
   аккаунтов: стикеры VK, чьи keywords — приветствия, и стикеры 👋 из
   Telegram sets, перечисленных под сеткой. Set можно добавить в
   Telegram по его ссылке `t.me`.
3. Выберите язык текстов приветствия и что вы предпочитаете — стикер или
   текст, затем нажмите **Сохранить выбор**.
4. Установите **План** в **начать новые диалоги** (люди, которым вы
   никогда не писали, сначала самые старые) или **ответить на
   приветствия** (люди, которые сказали «привет» и ждут), затем нажмите
   **Показать план**. Таблица показывает, кто что получит и почему
   кто-то пропущен — например, WhatsApp и Messenger разрешают
   произвольные сообщения только в течение 24 часов после последнего
   сообщения человека, а Telegram bot может только отвечать.
5. **Отправить приветствия** ставит план в очередь с паузой между
   сообщениями (по умолчанию 30 секунд). Никто не получит приветствие
   дважды.

То же самое из терминала:

```bash
meta-sovereign greetings-stickers --live --networks=vk,telegram
meta-sovereign greetings-select --stickers=vk:72789,vk:21 --language=ru
meta-sovereign greetings-plan --mode=initiate --limit=10
meta-sovereign greetings-send --mode=reply
```

Для получения стикеров и отправки нужны JS server (`meta-sovereign serve`)
и подключённые аккаунты VK, Telegram, WhatsApp или Messenger. Без server
экран всё равно показывает каталог и preview. Собственные подсказки
Telegram для пустых чатов ботам недоступны — подробности об этом и
остальном в [`docs/GREETINGS.ru.md`](./GREETINGS.ru.md).

## 11. Автоматизации: писать людям по правилам, безопасно

Автоматизация задаёт, кому писать, когда, при каких условиях и каким
текстом. Откройте вкладку **Автоматизация**, чтобы редактировать,
просматривать и запускать их. Первая из них — пресет из issue #31
"Say hi to contacts silent for 90 days" (поздороваться с теми, кто
молчит 90 дней): каждый личный 1:1 чат без сообщений не меньше 90
дней — группы, каналы и боты не попадают — получает одно сообщение:

- "Привет … Тебе или твоим друзьям …", если вы с этим человеком были на
  "ты", и "Здравствуйте … Вам или вашим друзьям …", если на "вы". Форма
  определяется по диалогу правилами на уровне слов; если данных нет или
  их поровну, используется вежливое "вы". Оба текста можно изменить, в
  них доступны `{name}`, `{days}` и `{network}`.
- Другие пресеты спрашивают об открытых вакансиях, предлагают работу по
  контракту или отвечают на приветствие тому, кто поздоровался.
  **Новая автоматизация** создаёт пустую.

У каждой автоматизации есть:

- **Когда запускается**: вручную, из меню чата, по расписанию
  (`30m`, `12h`, `1d`, `2w`) и/или на входящее сообщение, совпадающее с
  регулярным выражением.
- **Кому**: аудитория — `personal`, `friends:vk`, `chat:vk:<id>`,
  `community:vk:<id>`, `list:<id>`, `audience:<id>` или `person:vk:<id>`,
  соединённые через `|` (или), `&` (и), `-` (кроме) и скобки, например
  `friends:vk & chat:vk:2000000001 - list:blocked`.
- **Условия**: молчание не меньше N дней, не повторять N дней, только
  чаты, где вы тоже писали, только личные чаты, кто написал последним,
  какие сети.
- **Режим**: **безопасный** (по умолчанию) оставляет черновик в каждом
  чате; **автоматический** отправляет с индикатором набора, случайными
  паузами и дневным лимитом, один раз спросив вас.

**Предпросмотр** показывает, кто какой текст получит и почему остальные
не вошли ("недавно общались", "черновик уже ждёт", …); ничего не
отправляется. В безопасном режиме каждый черновик появляется в своём
чате: отредактируйте его, нажмите **Отправить** (сам клик и есть
подтверждение), переключите ты/вы, **Открыть чат** в сети, **Я
отправил(а) сам(а)** или **Пропустить**. Каждый исход запоминается, так
что тому же человеку случайно не напишут дважды.

**Люди** — поиск по всем сетям (тот же человек в других сетях показан
перекрёстными ссылками); выберите людей, чтобы запустить автоматизацию
только для них, или сохраните их списком. **Аудитории** сохраняют
именованные спецификации и считают, кто под них подходит. Чтобы
проверить автоматизацию на одном человеке, откройте его чат и выберите
**⚡ Автоматизации → Проверить в этом чате**.

Сам чат (вкладка **Чат**) подсказывает ответы, пока вы печатаете:
сначала целые ответы, которые вы раньше давали на последнее сообщение
чата, начиная с самых частых, затем слово за словом из ваших
собственных сообщений; **Tab** берёт первую подсказку. Чат показывает,
когда печатает собеседник — или автоматизация от вашего имени. Отправка
идёт через API сети, а если не получается — через её официальный web
UI. **Настройки → Внешний вид** выбирает тему (как в системе, светлая,
тёмная или авто по времени суток) и оформление (t3.codes, Telegram,
WhatsApp или Signal).

Сообщения работают как в Telegram Desktop. Правый клик по сообщению (на
телефоне — долгое нажатие) открывает его меню там, где был клик:
реакции, затем **Ответить** (**Цитировать и ответить**, если выделена
часть текста: ответ цитирует эту часть), **Копировать выделенный
текст**, **Изменить**, **Закрепить**/**Открепить**, **Сохранить как…** и
**Копировать изображение** на фото, **Копировать текст**, **Копировать
ссылку** на ссылке или иначе **Копировать ссылку на сообщение**
(**Копировать ссылку на пост** в канале), **Переслать**, **Удалить** и
**Выделить**. В группе у входящего сообщения под указателем в углу есть
**Ответить**. Двойной клик по сообщению (или свайп влево на телефоне)
отвечает на него; двойное касание ставит 👍. Чтобы выделить сообщения,
протяните мышью от одного сообщения к другому (если начать с выделенного
— выделение снимается) или выберите **Выделить**; дальше клик добавляет
или убирает сообщение, Shift+клик — диапазон, до 100. Верхняя панель
чата показывает **Переслать n**, **Удалить n** и **Отмена**. Правый клик
по выделенному сообщению даёт **Копировать выделенное как текст**,
**Переслать выделенное**, **Удалить выделенное**, **Открепить
выделенное** и **Снять выделение**, по другому — **Выделить до этого
сообщения**. Несколько сообщений копируются как в Telegram Desktop,
каждое как «[дата время] Имя: текст». **Esc** завершает выделение,
**Ctrl/Cmd+C** копирует, **Delete** удаляет. В пустом поле ввода **↑**
редактирует ваше последнее сообщение, а **Ctrl/Cmd+↑/↓** выбирают
сообщение для ответа.

Список чатов как в Telegram: закреплённые сверху, в своём порядке, со
значком булавки; счётчик чата без звука — серый; архивные чаты — за
одной строкой **Архив**; каждая строка говорит, кто написал последним и
что («🙂 Стикер», «Фото» с картинкой). Чат, прочитанный на другом
устройстве, сохраняет число непрочитанных, которое сообщает Telegram.

```bash
# сохранённые автоматизации и пресеты
meta-sovereign automations
# кто что получит и почему остальные не вошли — ничего не записывается
meta-sovereign automations plan reengage-dormant
# безопасный режим: поставить в очередь по одному черновику на человека
meta-sovereign automations run reengage-dormant
# по одному черновику за раз — [y] отправить, [m] отправил(а) сам(а), [e] изменить, [f] переключить ты/вы, [s] пропустить, [q] выйти
meta-sovereign automations review
# автоматический режим отправляет только с --confirm=true; --chat сужает запуск до выбранных чатов
meta-sovereign automations run job-search --chat=vk:101 --confirm=true
```

По HTTP: `/api/automations` (список, `PUT` для сохранения),
`/api/automations/plan`, `/run`, `/drafts`,
`/drafts/{send,form,mark,skip}` и `/history`; `/api/people`,
`/api/audiences`, `/api/lists`, `/api/send`, `/api/typing` и
`/api/suggest`. Подробности:
[`docs/case-studies/issue-31/`](./case-studies/issue-31/README.md).

**Без вас ничего не отправляется.** Чтение — импорт, загрузка новых
сообщений, предпросмотр — происходит по мере надобности. Всё, что пишет
в другой сервис или что увидят другие люди (сообщение, пост, приветствие,
рассылка, изменение профиля или резюме), сначала показывается и
отправляется только после того, как вы подтвердите именно это: кнопкой
«Отправить» под набранным текстом, кнопкой «Отправить» у черновика или
подтверждением со списком того, что уйдёт. Расписание и триггеры на
входящие сообщения только готовят черновики, даже в режиме auto.
Сохранение профиля или резюме оставляет их на этом устройстве; кнопка
**Обновить на других сервисах** на экране профиля публикует их в
отмеченные сети. «Печатает…» передаётся, только если включить это в
**Настройки → Конфиденциальность**. В командной строке команды отправки
показывают план и спрашивают y/N; скрипты передают `--yes`.

| Symptom                                                         | Fix                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SPA завис на loading spinner.                                   | Dev tools → Application → IndexedDB: проверьте database `meta-sovereign`; возможно, storage disabled.                                                                                                                                                                                                                                                                                                                           |
| SPA не видит local server.                                      | В app откройте **Settings → Server** и вставьте точный URL.                                                                                                                                                                                                                                                                                                                                                                     |
| Hosted app остается в browser-only mode, хотя server запущен.   | Нажмите **Check again**. Разрешите запрос браузера о локальной сети. В Safari: выполните `npx -y meta-sovereign trust` один раз (macOS) или откройте **Доверять серверу** (<https://127.0.0.1:8787/trust>), нажмите «Подробнее → зайти на этот сайт», затем **Check again**. Или нажмите **Открыть приложение с сервера** (<http://127.0.0.1:8787>). Если SPA размещен у вас, запустите server с `--allow-origin=<ваш origin>`. |
| Сразу после перезагрузки не видно части сообщений или аватаров. | Подождите несколько секунд: чат запрашивает сообщения снова, пока они не придут, а фото, которое ещё скачивается из Telegram, появится, когда сохранится (в первый раз Telegram отдаёт каждое медленно). Потом сохранённые фото загружаются сразу.                                                                                                                                                                              |
| Server сообщает `EADDRINUSE`.                                   | Передайте `--port=NNNN` в `meta-sovereign serve` или Rust `serve --port=NNNN`.                                                                                                                                                                                                                                                                                                                                                  |
| WebRTC sync ломается между двумя LAN.                           | Настройте TURN server: [`docs/WEBRTC-TURN.ru.md`](./WEBRTC-TURN.ru.md).                                                                                                                                                                                                                                                                                                                                                         |
| `cargo build` падает с linker error.                            | Установите C toolchain (`build-essential` на Debian/Ubuntu, Xcode CLI tools на macOS).                                                                                                                                                                                                                                                                                                                                          |

**Найдите сессии Telegram на этом компьютере.** Если вы эксперименти­ровали
с Telegram в нескольких репозиториях, ваши входы уже на этой машине — токен
бота в `.env` одного проекта, пользовательская _строковая сессия_ GramJS
(сохранённая как `.telegram_session`) рядом с другим. На экране
**Подключения → Telegram → Ввести вручную** кнопка **Найти мои сессии
Telegram** просматривает папки с проектами (`~/Code`, `~/projects`, … и
текущий каталог), собирает и **токены ботов**, и **пользовательские
сессии**, и группирует их по аккаунтам — один и тот же аккаунт, найденный в
трёх репозиториях, показывается как один. Токены ботов подтверждаются через
`getMe`; пользовательские сессии группируются по телефону (и тоже
подтверждаются, если доступен клиент GramJS). Папки только читаются; браузер
видит лишь тип, путь и замаскированную подсказку (последние четыре символа)
— никогда сам токен или сессию. Выбранное сохраняется под `secret:telegram:*`
(шифруется при заданной парольной фразе) и отправляется только в Telegram.

**Вход в Telegram по телефону.** Под поиском «Войти в свой аккаунт Telegram» выполняет вход как Telegram Desktop и как konard/telegram-bot: введите `api_id`, `api_hash` и номер, нажмите «Отправить код», введите код из Telegram (и пароль 2FA, если он есть) — полученная пользовательская сессия сохраняется под `secret:telegram:*`. Поддерживаются и токены ботов, и полноценные аккаунты. Вход выполняется на локальном сервере (GramJS); найденный `.telegram_session` проверяется по реальному аккаунту, если GramJS установлен.

**Логин и пароль для почты.** На экране «Ввести вручную» для почты можно указать сервер IMAP/SMTP, логин (адрес) и пароль (или пароль приложения) — сохраняются как `secret:email:host` / `secret:email:username` / `secret:email:password`, помимо OAuth-токена.
