# Сохранённые анкеты

Чаты, ответы в откликах и внешние формы используют общий планировщик. При чтении
актуальных правил он индексирует согласованные нумерованные ответы из сохранённых
полных анкет. Условия, инструкции и код остаются при родительском вопросе.
Неоднозначные пары не разделяются; полный сохранённый ответ имеет приоритет.

Извлечённая часть требует проверки даже после одобрения полного ответа.
Ограничения по сервису и чату, исправления, актуальные зарплатные и контактные
данные сохраняются. Чтение не записывает правила и ничего не отправляет.
Новая сборка анкеты также требует проверки.

Заполнение нативного отклика и автоматическая отправка точных ответов также
требуют одобренного однозначного сохранённого ответа. Извлечённые,
неодобренные или конфликтующие ответы остаются для проверки владельцем, даже
если текст поля совпадает. Владелец может заполнить форму и отдельно подтвердить отправку.

В разделе **Вопросы и сохранённые ответы → Изучить разговоры** можно посмотреть
части сохранённых анкет вместе с ответами из архива и сохранить предложения для
проверки. Сохранённая формулировка добавляет ноль использований; частоты берутся
только из реально отправленных ответов. Повторный запуск не пересчитывает те же
наблюдения и сохраняет одобрения. История из сервисов не загружается.

Обучение по наблюдаемым формам также сохраняет полный ответ и согласованные
части как неодобренные предложения с одинаковой частотой и свидетельствами.
Неоднозначные ответы остаются целыми. Повторное наблюдение не увеличивает
счётчик; журнал считает пропущенные входные пары отдельно от предложений.

Офлайн-команды:

```sh
meta-sovereign automations answers backfill-questionnaires
meta-sovereign automations answers backfill-questionnaires --apply
```

`answers learn` включает ту же операцию. Оба формата Links Notation поддерживают
`POST /api/automations/answers/backfill-questionnaires` и `/api/automations/answers/learn`.
`apply: false` только показывает предложения; `apply: true` сохраняет их.
Отказ из-за ёмкости или изменения правил не применяет предложения: сначала
запросите новый предпросмотр.

## Контекст нативного отклика

Перед запуском отдельного отклика или пакета в CV выберите общий профиль и
задайте зарплатные цели в настройках отклика. Каждая часть анкеты использует
свою валюту, сумму до или после налогов и нужный контакт. Квитанция показывает
подтверждённый профиль и зафиксированные цели. Каждый новый план читает
актуальные значения сохранённого профиля; изменение контактов не меняет
зарплатные цели. Если профиль удалён, планирование отклоняется. Составные
ответы требуют проверки и не запускают автоматическую отправку точных ответов.

CLI отдельного и пакетного отклика принимает `--profile-id` и `--salary`
(запись Links Notation с общей конфигурацией зарплаты). API открытия отклика и
запуска пакета принимает `profileId` и `salary` в обоих форматах Lino. Без этих
полей сохраняется прежнее поведение. В браузере для восстановления хранится
только идентификатор отклика.

## Точка в конце ответа

В разделе **Вопросы и сохранённые ответы → Правила повторного использования**
выберите вариант с точкой (по умолчанию) или без точки и сохраните. Если для
одного вопроса и одинакового состояния одобрения/исправления наблюдались оба
ответа `Vietnam` и `Vietnam.`, план объединяет их реальные частоты и источники,
выбирая указанное написание. Единственный вариант остаётся неизменным. Другие
знаки, регистр, вопросы и состояния одобрения не объединяются. Исходные ответы
и переписка сохраняются: повторное обучение не пересчитывает наблюдения.

Отдельный широкий режим эквивалентности пунктуации сохраняет прежнее поведение:
он имеет приоритет и выбирает самое частое исходное написание. При включённом
режиме выбор конечной точки недоступен. Ошибка сохранения оставляет введённый
выбор и показывает отказ, не подтверждая изменение.

Общая настройка: `meta-sovereign automations answers policy --answer-final-period=without`.
Для предварительного `answers plan` доступны `--answer-final-period=with|without`,
переменная `ANSWER_FINAL_PERIOD` и строка `ANSWER_FINAL_PERIOD: "without"` в
`.lenv`. Файл выбирается через `--configuration=path.lenv`. Приоритет: явный
флаг, окружение, выбранный файл, `.lenv` рабочего каталога, сохранённая настройка,
затем `with`. Переопределение плана не меняет окружение или сохранённую настройку
и не запускает автоматизацию провайдера. Остальные команды используют общую настройку.

Оба кодирования Lino поддерживают `POST /api/automations/answers/policy` с
`{ policy: { answerFinalPeriod: 'without' } }`. В плане `answerFinalPeriod`
переопределяет только чтение. Недопустимые значения отклоняются без записи.
Автономный интерфейс использует те же планировщик и сохранённую настройку.

## Предпочтительная формулировка ответа

В поле **Равнозначные формулировки ответа, по одной на строку** укажите точные
варианты, для которых следует использовать ответ выше. Настройка относится только
к этому вопросу, его сохранённым равнозначным вопросам, провайдерам и чатам.
Перефразирование не угадывается. Например, два и три наблюдения равнозначных
вариантов дают пять использований предпочтительного ответа. Ручной ответ начинает
с нуля. «Через месяц» и ответы на другие вопросы остаются отдельными.

Одобрение относится к предпочтительному ответу. Без одобрения нужна проверка;
настройка ничего не отправляет. Конфликт предпочтений и пересечение исходных
наблюдений требуют проверки, их частоты не суммируются молча. Исходные ответы и
сообщения сохраняются, повторное обучение не увеличивает частоты. Отклонённые
фразы исключаются, варианты выбора остаются буквальными.

Редактор онлайн и офлайн подтверждает только принятые сохранения; при отказе
черновик остаётся. Обновление читает сохранённую настройку. Удаление всех строк
очищает её. CLI `answers save` принимает один `--equivalent-answer=<текст>`.
Для нескольких вариантов укажите `equivalents: [текст, текст]` у предпочтительного
ответа в файле Lino или JSON и выполните
`meta-sovereign automations answers save preference.lino`. Повторное сохранение
читает изменения, отсутствие поля очищает варианты. Обе кодировки API Lino
сохраняют это поле. Без настройки равнозначных вариантов замены нет.
