# Проверенные ответы через браузер

В разделе «Автоматизация → Вопросы и сохранённые ответы» откройте ответы через
браузер провайдера. Те же элементы доступны в меню автоматизации Чата и Оператора.
Выберите провайдера, укажите веб-чат и прочитайте текущий вопрос. Для HH нужен
числовой ID веб-чата или официальный URL; UUID API для этого не подходит.
Необязательный официальный URL отклика выбирает его видимую встроенную переписку.

Проверьте вопрос, источники ответа и точные варианты. Кнопка отправки подтверждает
один конкретный вариант в интерфейсе провайдера. Изменившийся вопрос, недоступные
варианты или ваш черновик блокируют нажатие. Обычные подсказки для начала беседы не
считаются ответами. Для свободного ответа предзаполнение записывает проверенный
черновик только в пустое поле. Отправьте его самостоятельно у провайдера.

Сервер хранит приватную проверку 30 минут. Общая с автоматизацией запись исходящих
защищает вопрос от повторной отправки. Успех требует подтверждённого исходящего
сообщения провайдера. Восстановление статуса читает сохранённые данные, не открывая
браузер и не повторяя нажатие. При потере ответа отправка заблокирована до проверки
статуса. Неизвестный результат сохраняется после перезагрузки и перезапуска:
проверьте чат и разрешите запись в исходящих. Без поддержки сервера или офлайн
успех не имитируется. Проверка возможностей не запускает браузер.

CLI: `automations answers browser show`, `inspect --source=hh --chat=7`,
`select --id=<review-id> --option=Yes --confirm=true`, `status --id=<review-id>`
и `prefill --id=<free-text-review-id>`. Перед ними укажите `meta-sovereign`.
Доверенный сервер предоставляет `GET /api/automations/answers/browser` и
`POST /api/automations/answers/browser/{inspect,prefill,select,status}` в текстовом
и бинарном Links Notation. Для выбора нужны сохранённый ID, точная строка варианта
и логическое `confirm: true`. Проверка использует текущие настройки профиля,
контекста, зарплаты и необязательной модели.

Завершённая входящая анкета с тем же вопросом может восстановить один точный
текущий вариант из сохранённых чатов. Противоречия, неполная проверка истории,
сообщения владельца, запрещённые ответы и явные исправления требуют проверки.
Анкета не одобряет правило и не увеличивает частоту ответов; её нельзя использовать
для свободного текста, поля формы или целевой зарплаты. Одобренный точный вариант
сохраняет приоритет. Перед автоматической отправкой источник проверяется заново;
общий интерфейс показывает исходные сообщения.

CLI: `meta-sovereign automations answers plan --question="Do you have distributed systems experience?" --options='(Yes No)' --strict-options=true`.
Варианты задаются в Links Notation. API планирования принимает `options` и
логическое `strictOptions`.

После чтения вопроса HH явный запуск наблюдения действует 1–120 минут (по умолчанию
120). Автоматически нажимаются только одобренные точные варианты или единственный
вариант из завершённой анкеты; текущие знания проверяются перед каждым действием.
Недоступные варианты ожидаются. Свободный текст лишь предзаполняется для проверки.
При появлении кнопок неизменённый автоматический черновик очищается, ваши правки
сохраняются. Навигация, перезагрузка, неизвестная доставка или потеря владельца
приостанавливает наблюдение. Остановка дожидается завершения текущего действия.

CLI: `meta-sovereign automations answers browser watch --id=<review-id>
--confirm=true --duration-ms=7200000`. Команда работает на переднем плане;
Ctrl+C/SIGTERM останавливает её с ожиданием. Отдельный процесс читает сохранённый
`watch-status --watch-id=<watch-id>`, но не управляет владельцем и не возобновляет его.
Сервер-владелец предоставляет доверенные текстовые/бинарные Lino-маршруты
`POST /api/automations/answers/browser/{watch-start,watch-status,watch-stop}`.
Запуск требует UUID в `id: 'question-watch:<uuid>'`, `review`, `confirm: true`
и необязательную `durationMs`. Сохраните ID при потере ответа: повторный запуск
с ним лишь читает состояние. Перезагрузка UI не запускает наблюдатель;
сохранённый активный процесс без владельца показывается приостановленным.

Проверено на изолированных страницах с рабочим отправителем. Настоящие аккаунты
и обработка всех непрочитанных чатов остаются критериями #56. См.
[проверку наблюдателя](case-studies/issue-56/question-watch.md).

Явно запущенный проход непрочитанных чатов сохраняет каждое проверенное окно
истории в обычный архив сообщений выбранного сервера до прокрутки. Повторные
нативные ID обновляют те же сообщения; наблюдаемые правки сохраняют версии.
Ошибка сохранения останавливает проход с попыткой восстановить исходный вид,
пока он принадлежит автоматизации. Остановка дожидается уже начатого сохранения.
Восстановление статуса не повторяет обход. Неполная история остаётся неполной;
невидимые сообщения и отсутствующие даты не восстанавливаются. Явное обучение
ответам может использовать архив: приватные адреса ссылок исключаются, новые
ответы требуют одобрения. [Проверки истории](case-studies/issue-56/browser-history-archive.md).

Чтение браузера HH сохраняет нативные pending, failed, sent, delivered и read. Отсутствующие, незнакомые или противоречивые значки исходящего сообщения означают unknown: такое сообщение не подтверждает отправку и не обучает ответы. Миграция 0021 помечает старые ответы без подтверждения как unknown до повторного чтения. Сохранённая база ответов остаётся данными владельца. [Проверка доставки](case-studies/issue-56/hh-browser-delivery.md).

Подтверждённый наблюдатель текущего чата снимает изменения видимых сообщений
при вызове DOM-наблюдателя, до следующего опроса. Записи архива подтверждаются
последовательно; замеченные версии текста и доставки сохраняются после удаления
из панели. Повторное использование ID другим чатом или изменение ранее
замеченного заголовка HH запрещает привязку. Ошибка записи или очередь больше
64 снимков либо 2 МиБ приостанавливает наблюдатель. Stop отключает захват,
дожидается начатых записей и сообщает о пропуске. Восстановление статуса ничего
не запускает. Это охватывает подтверждённый документ, а не другие чаты и не каждое
промежуточное синхронное состояние DOM. Настоящий аккаунт и обход всех
непрочитанных чатов ещё требуют проверки.
[Проверки захвата](case-studies/issue-56/hh-live-capture.md).
