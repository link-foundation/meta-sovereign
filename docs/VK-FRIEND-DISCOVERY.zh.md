# 审核后的 VK 好友发现

连接 → VK 提供三个独立策略，自动计划默认关闭。每个策略分别保存间隔、
操作上限、受保护 ID、审核和凭据。准备审核会读取服务端状态并保存计划；
更改好友关系需要明确确认已审核的操作。

- **最佳建议**：检查最多 100 个共同好友建议，按共同好友数量降序、ID 升序
  排列。账号须可访问，且当前允许发帖、查看、私信和好友请求。
- **社群好友发现**：配置自己的社群 ID、偏移和有限窗口。可选择在线、
  照片、公开资料及性别筛选（0 全部、1 女性、2 男性）。不会预选私人社群。
  审核显示已检查数量、服务端总数和偏移。发送前再次检查社群成员资格。
- **已停用账号的入站请求**：检查配置范围内的请求，最多 10,000 项。仅
  拒绝当前入站且账号当前已封禁或删除的请求，保留活跃账号。普通删除成功
  或移除好友的凭据不能证明入站请求已被拒绝。

前两个策略按账号共享持久配额：每个 UTC 日最多尝试 40 次新请求。发送前
保存预留；拒绝、结果未知或随后取消均不会退回预留。重启后仍保留。
单次操作上限 0 表示不执行，好友容量 0 表示暂缓所有新请求。建议间隔
3 秒，社群请求 5 秒，拒绝请求 10 秒。VK 错误 8 暂停 24 小时，14/29
暂停一小时，暂停状态也会持久保存。

所有共享 VK 好友策略的受保护 ID 和全局退出设置均生效。审核有效期五分钟。
令牌、账号、策略、日期、资料、关系、共同好友数量或成员资格变化后需重新
审核。Stop 等待已进入的工作结束，并阻止之后的写入。结果未知的操作保留
在共享日志中，重启或切换其他好友策略后均不会重放。

现有停用好友清理、好友请求接受及出站请求取消审核也可查看当前好友、
入站和出站请求；确认前不会改变关系。清理完整检查支持的好友列表，最多 10,000 项。出站审核检查配置的
数量上限，最大 10,000；可提高该上限来查看更大的请求列表而不确认更改。新的停用请求策略可独立分页检查入站
请求，不受原有排序接受批次的限制。

CLI：`meta-sovereign vk-suggestions`、`vk-community`、`vk-rejections`，
操作包括 `status`、`save`、`plan`、`run --plan <review-id> --confirm`。
例如 `meta-sovereign vk-community save --community-id 55 --scan-limit 100 --limit 1`，
随后执行 `plan` 并确认输出的审核 ID。API：`/api/vk/suggestions`、
`/api/vk/community`、`/api/vk/rejections`，使用 Lino text/binary 和同源
审核确认。仅浏览器模式可保存本地设置，但服务端操作不可用。合成测试不能
证明某个真实 VK 账号具备 API 权限。

独立的限速、输入状态出站消息队列仍属于 VK26 的必需范围。这些好友策略
不能替代该队列要求。
