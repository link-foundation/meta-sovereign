# Telegram Mini Apps

Bots' menu, inline/reply keyboard and direct-link Mini Apps open in a sandboxed frame. Telegram supplies the signed launch URL; no bot credentials or authorization fragments are written into diagnostics. The host accepts supported bridge messages only from that frame and its expected HTTPS origin. Other frames and origins are rejected.

The [official Telegram SDK](https://telegram.org/js/telegram-web-app.js) serializes no-argument bridge events with `eventData: ''`. The bridge accepts that representation for ready, close, expand and the supported theme/viewport requests. Action payloads still require their proper object shape. The initial iframe handshake receives the host's theme and size, and the bridge listener is installed before painting the frame to avoid missing early readiness from a cached app. The implementation follows the documented protocol; no Telegram implementation code was copied.

Only a validated SDK ready event confirms that the app is ready. An iframe load event is not proof of success: browsers also emit it for some blocked/error pages. If readiness has not arrived within 15 seconds, the spinner changes to an explanation with **Retry** and **Open in browser**. A failed launch request also retains a retryable dialog. A late valid ready event recovers normally. Reload obtains a fresh launch URL and resets the loading state. Closing remains available throughout.

An app's own site can be offline or forbid embedding with `X-Frame-Options` or CSP. Those restrictions are not bypassed. During the 2026-10-28 investigation, Telegram successfully returned a launch URL for the reported Pintopay bot, but `https://my.pintopay.me` returned HTTP 521 and `X-Frame-Options: SAMEORIGIN`. That provider failure cannot be repaired by changing local server CORS. The recovery UI avoids an endless spinner; **Open in browser** offers a user-controlled alternative when a site permits standalone operation. No payments or other financial actions were performed during diagnosis.

The supported SDK surface is covered by `web-apps.test.js` and `e2e-web-apps-browser.mjs`: official empty-string events, theme/viewport exchange, main/secondary/back controls, popups, reload, close, reply-keyboard data, forged messages and unavailable-site timeout/retry. Both Chromium and WebKit run the browser fixture. Unsupported SDK methods are not advertised as supported; external service availability and every third-party Mini App's feature set cannot be guaranteed.
