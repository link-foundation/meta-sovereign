# VK feature matrix (languages: en • [zh](vk.zh.md) • [hi](vk.hi.md) • [ru](vk.ru.md))

Back to the [Telegram feature matrix](../FEATURES.md). This page covers VK only.

## Scope and access

The scope is a personal VK account. Nothing here has been verified against a live VK account: every test uses fakes, and the web selectors are unverified guesses. Facts about VK itself come from the repo's case study (`docs/case-studies/issue-32/README.md`) and VK's published documentation; where a VK detail could not be re-checked it is said so in the notes.

Three routes exist.

1. **Official API (`api.vk.ru/method/*`).** Auth is an access token that the user pastes (`VK_ACCESS_TOKEN` or a stored secret). Hard limits:
   - Since 2024-06-25 VK no longer grants the user `messages` right to new apps, and the user-token implicit flow is closed. Only legacy tokens (Kate Mobile, VK Admin) ever had it, and those have been cut off. Tokens of the vk.com web client (id 6287487) and VK Calls (7793118) are reported to still work, at the risk of the user's own account (freezes of 24 hours to 4 days are reported).
   - A **community token** works only for that community's dialogs. It cannot read the user's personal chats; member listing, friends and typing partly do not apply (error 27).
   - Every messaging method (`messages.getConversations`, `getHistory`, `send`, `edit`, `delete`, `markAsRead`, `sendReaction`, `getLongPollServer`, photo and document upload) needs the `messages` (and `photos` / `docs`) right; a user token without it gets error 7 or 15.
   - Docs: https://dev.vk.ru/ru/api/access-token/getting-started , https://dev.vk.ru/ru/reference/access-rights , https://dev.vk.ru/ru/reference/errors , https://dev.vk.com/en/method/messages .
2. **Web app (vk.com/im) in the user's own browser profile.** The only route that works without a `messages` token: the user signs in once in the profile. The selectors cover two VK UI generations and are unverified against live vk.com.
3. **Data export archive** (https://vk.com/data_protection?section=rules). The importer reads the JSON shape of konard/vk-export (`conversations[].messages[]`). VK's own export is HTML; its pages are now read too (R-Z8, not yet tried on a real archive).

**Not accessible** (official app only, or closed to third parties by VK): voice and video calls, VK Pay transfers, mini apps and VK Play inside chats, end-to-end (secret) chats of VK Messenger, VK ID passkey login, sticker purchases and VK Donut, message translation, the clips and stories viewer inside a chat, push notification delivery, and the music API (`audio.*`, closed to third parties since 2016/2018).

VK now keeps itself current while the server runs and a token is saved: a Fetch now button on the card, a 10 minute schedule and the official Long Poll (R-Z8). Nothing has been tried against live VK.

## Legend

- **Status**: Supported = works end to end in the app a user runs; Partial = works with the limit named in the notes ("fix in progress (R-Z<n>)" = a fix is being built right now); Not supported = not built although reachable; Not accessible = needs a capability only the official apps have.
- **Access**: API = the network's official API (endpoints named where known); Web = the network's web app in a browser, as a fallback (R-Y38); Archive = import of the network's data export; API + Web = API first, web app when the API has no such call or refuses; Not accessible = needs a capability only the official apps have.
- **Requirements**: R-IDs in [`REQUIREMENTS.md`](../REQUIREMENTS.md) that implement the feature.
- **Verification**: everything here is checked against the code on main and against fakes (test doubles). Nothing is verified against a live account. "Planned (R-Z<n>)" in the notes means later work, not in progress now.

## Known gaps

1. VK keeps itself current (Fetch now, a 10 minute schedule and the official Long Poll, R-Z8), but only with a token that can still read messages; new apps cannot get that right, and none of it has been tried against live VK.
2. Chat names and sender names are filled in; history is paged back a few chats and pages per fetch, and scrolling to the top of a VK chat loads older messages from VK until its first message (R-Z8, R-Z20). The chat list is not read live from VK.
3. Pictures and stickers draw inline from VK's picture CDN; voice messages, audio and videos that come as a direct file on a VK CDN play inline, and everything else (files, a video that only has its VK page) opens as a link, never an iframe. Every attachment of a message is shown. VK URLs expire and are not downloaded (R-Z8, R-Z20).
4. VK's official HTML data export can be imported (R-Z8), but the reader was written from the page layout from memory and has not been tried on a real archive; archive times are read as UTC.
5. Reactions show as emoji through the same id table used for sending (unknown ids stay numbers); VK's real id list is unverified, so the table may still be wrong (R-Z8).
6. Sending is text and stickers only: no reply, photos, files or voice. `random_id` now comes from the draft, so a retry is not delivered twice, and a captcha is reported as `captcha` (R-Z8). An ambiguous API failure no longer falls back to the browser (fixed, R-Z4).
7. The web fallback is unverified against current vk.com.
8. Getting a token is the weak point after the Kate Mobile cut-off; the page offers no guided flow.
9. Lower priority: deleted-message detection (planned; nothing in the history pull marks a deleted VK message), friends and profile cards, chat admin, search methods, stories, wall, bot keyboards.
