# LinkedIn 功能矩阵 (languages: [en](linkedin.md) • zh • [hi](linkedin.hi.md) • [ru](linkedin.ru.md))

返回 [Telegram 功能矩阵](../FEATURES.zh.md)。本页只涉及 LinkedIn。

## 范围与访问方式

1. **官方 API。** 文档：Posts API https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api 和 Sign In with LinkedIn (OIDC) https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2。
   - 会员自助可用：`openid profile email`（OIDC `GET /v2/userinfo`：sub、姓名、头像、语言区域、邮箱）和 `w_member_social`（创建帖子、通过 PARTIAL_UPDATE 修改正文、删除帖子；图片、视频、文档、多图、投票、文章、转发）。
   - **受限：** `r_member_social`（读取自己的帖子、评论、点赞）仅对获批用户开放，因此普通个人应用连通过 `GET /rest/posts?q=author` 读取自己的帖子也做不到。
   - **Messaging API 仅限合作伙伴**，没有自助开通途径（常识）：个人无法读取或发送消息。资料编辑 API 同样只对合作伙伴项目开放。
2. **浏览器中的网页应用**（linkedin.com/messaging、/in/me）：读取和发送消息、编辑资料的唯一途径。LinkedIn 对自动化流量封锁很严，任何自动化都有账号受限风险。
3. **数据导出归档**（设置 > 获取数据副本）：导入 `messages.csv`。其他 CSV（Connections、Profile、Positions、Skills、Shares、Comments、Invitations）未导入。

不可访问：通话、视频会议、Premium 与 InMail 额度、Sales Navigator、招聘工具、职位申请流程，以及只有应用才有的一切。

除简历界面（`/api/cv/*`）外，没有 LinkedIn 专用的服务器路由或页面界面。消息走通用代码。网页选择器从未在真实已登录的 LinkedIn 上检查过。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（“修复进行中 (R-Z<n>)” = 修复正在开发）；不支持 = 虽可访问但尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 该网络的官方 API（已知时给出端点）；网页 = 浏览器中该网络的网页应用，作为后备（R-Y38）；归档 = 导入该网络的数据导出；API + 网页 = 先用 API，API 没有该调用或被拒绝时用网页应用；不可访问 = 需要只有官方应用才具备的能力。
- **需求**：[`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中实现该功能的 R-ID。
- **验证**：此处所有内容均对照 main 上的代码和测试替身（fake）检查，没有任何内容在真实账号上验证过。备注中的“计划 (R-Z<n>)”表示以后的工作，当前并未进行。

## 已知缺口

1. 发给 LinkedIn 聊天的消息不再变成公开动态，资料或简历同步在未传入 `shareAsPost` 时返回 `unsupported`（已修复，R-Z4）。发往 LinkedIn 的消息走网页应用，尚未在真实网站上测试。
2. 消息只有浏览器路径，选择器未经验证；LinkedIn 可能限制自动化账号。
3. 归档导入完整读取 `messages.csv`（R-Z10）；Connections、Shares 和 Profile 文件仍未导入（计划，R-Z10）。
4. 资料写入只覆盖标题、About 和技能；位置、经历、教育不写入。
5. 通过 API 的帖子生命周期很简陋：没有帖子 ID、编辑、删除、媒体、仅人脉可见；作者 URN 要手动输入。
6. 读取自己的帖子需要 LinkedIn 批准 `r_member_social`。
7. 不导入联系人和人脉。
8. 低优先级：转发、评论、主页、投票、定时发布。
