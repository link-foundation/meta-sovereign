## 范围与访问方式

本页涵盖六个求职网站：hh.ru、Habr Career、SuperJob、Naukri、TopCV 和 VietnamWorks。Issue #29 要求用 browser-commander 在 LinkedIn、hh.ru、Habr、Naukri、VietnamWorks 和 TopCV 上读取并更新简历，在标记尚不清楚的地方允许遥测和草稿。需求行：R-E7..R-E13、R-D6、R-V1..R-V22。LinkedIn 有自己的网络页面，本页不涵盖。这里没有任何内容在真实网站上验证过：大多数 CV 方案步骤是从未在真实网站上运行过的草稿（草稿步骤数见各行）。

**与招聘者的消息** 有三种可能途径：官方 API（只有 hh.ru 和 SuperJob）、由浏览器发送器驱动的网站网页应用（需要 `WEB_UIS` 条目）、以及归档导入。**六个网站都没有 `WEB_UIS` 条目**（只有 vk、telegram、whatsapp、x、facebook、linkedin 和 upwork 有），所以读取或发送消息的浏览器途径在每个网站上都未构建。现有的“网页”工作只有 CV 资料方案，它们通过 browser-commander 在持久配置文件中运行（[CV 同步](../CV-SYNC.zh.md)）。

**官方 API**：

- hh.ru：`https://api.hh.ru`（[GitHub 上的 hhru/api](https://github.com/hhru/api)、[dev.hh.ru](https://dev.hh.ru/)）。需要在 hh 账号中注册应用并使用 OAuth。OpenAPI 规范无法获取（HTTP 403），也没有找到关于求职者令牌是否可用的说明；行业报道称访问控制很严。仓库自己 2026-09-16 的证据说，公开 OpenAPI 没有求职者简历修改操作（`/resumes/{id}` 只有 GET），而 `/resumes/mine` 可读。
- SuperJob：`https://api.superjob.ru/2.0`（[文档](https://api.superjob.ru/)）。需要注册的应用（密钥通过 `X-Api-App-Id` 发送）和用户令牌。审计时文档站返回 HTTP 403。仓库的 SuperJob CV 方案写明，API 密钥只覆盖职位，不覆盖求职者简历编辑。
- Habr Career：没有公开的求职者 API。适配器自己也这么说；它的 `/api/applications`、`/api/resume` 路径和 `/api/frontend/me` 探测都是杜撰的。
- Naukri、TopCV、VietnamWorks：没有求职者 API。

**归档**：没有哪个网站已知提供解析器所期望格式的申请或消息的用户数据导出。连接指南让用户“使用 JSON 导出”（hh、Habr、SuperJob）或“保存页面加载的 JSON 数据”（Naukri、TopCV、VietnamWorks）；无法确认存在这样的导出。对 Naukri，真实途径是招聘者邮件，邮件来源可以导入。

**不可访问**：雇主和招聘者功能（发布职位、简历库搜索）、官方移动应用、视频面试，以及付费服务（hh 和 TopCV 高级版、需要付费的简历置顶）。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（正在进行的修复标为“修复进行中 (R-Z<n>)”，仍计为部分）；不支持 = 尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 网站的官方 API（只有 hh.ru 和 SuperJob；其他是杜撰的或不存在）；网页 = 浏览器中的网站，实际上就是通过 browser-commander 运行的 CV 资料方案；归档 = 文件导入；不可访问 = 需要官方应用或雇主账号。“草稿”步骤是从未在真实网站上运行过的选择器。
- **需求**：实现该功能的 [`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中的 R-ID。“—”表示没有需求行覆盖它。需求行写“Done”并不代表该功能已被验证。
- **验证**：所有功能都只用假数据（注入的 `fetch` / 假浏览器）测试过，没有任何功能在真实账号上检查过。“planned (R-Z<n>)”表示排入后续批次的工作，不改变状态。

## 已知缺口

1. 没有 API 的每个网站（Naukri、TopCV、VietnamWorks、Habr Career）都缺少招聘者消息功能，有 API 的两个（hh.ru、SuperJob）也未经证实。可靠的途径是在已登录的浏览器配置文件中使用各网站的收件箱，但未构建。
2. hh.ru、SuperJob 和 Habr Career 的 API 简历写入调用的是仓库自己调研说求职者并不存在的端点，而 R-E8、R-E9、R-D6 写着 “Done”；只有草稿状态的浏览器 CV 方案能写入。通用简历同步不再对没有 `syncResume` 的适配器错误地报告成功（已修复，R-Z4），hh.ru 简历同步返回 `unsupported`。
3. 归档线程以及 Habr Career 和 SuperJob 实时线程的聊天回复目标是错的：聊天命名为 `vacancy:<id>`，而发送需要真实线程 id。
4. 除非列表内嵌，hh.ru 的线程消息只是占位；单独的消息调用从未发出，求职者令牌能做什么也未确认。
5. 任何地方都没有职位搜索、申请、提醒或针对具体网站的通知，而这些正是求职者日常的核心。
6. CV 方案大多是从未在真实网站运行过的草稿（草稿步骤：hh.ru 30 步中 22、Naukri 34 步中 27、TopCV 32 步中 27、VietnamWorks 32 步中 21、SuperJob 18 步中 13、Habr Career 17 步中 5）。Habr Career 的读取集合比写入集合窄，所以差异无法确认写入了什么。
