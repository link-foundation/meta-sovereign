## Объём и доступ

GitHub рассматривается как канал общения: issues, pull request, комментарии к ревью, discussions, уведомления, упоминания и ответы. Issue #5 («Add GitHub support») просит issues, комментарии и pull request, а также скачивание каждого репозитория в хранилище ссылок. Код: `js/src/sources/github.js` и `github-check.js`; в Rust-сервере адаптера GitHub нет.

Как части соединены сегодня:

- **Импорт**: страница Connections, загрузка JSON, разбор в странице, сохранение по одной ссылке. Работает без сервера.
- **Живая загрузка**: `POST /api/github/pull` и CLI `source-pull --source=github` берут один репозиторий (`owner`, `repo`). Ни кнопка страницы, ни расписание их не вызывают, поэтому нет кнопки «синхронизировать репозиторий» и нет общего входящего по всем репозиториям.
- **Живая отправка**: `POST /api/github/post-comment` (с токеном подтверждения) и CLI `github-comment` работают, если вызывающий указал `owner`, `repo` и номер issue.
- **Поле ввода чата, автоматизации, re-engage**: общий путь отправки не передаёт owner, repo и номер issue, поэтому ответ в ветку GitHub из чата падает с «requires owner and repo» (воспроизведено на поддельном `fetch`).
- **Правка, удаление, реакция из чата**: адаптеру передаётся id сообщения `owner/repo#123` вместо числового id комментария, а owner и repo не передаются, поэтому вызовы уходят не на тот endpoint или падают.
- **Форма сообщения**: id `msg:github:<kind>:<owner/repo>#<id>`, чат `owner/repo#<номер issue или PR>`.

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении, которое запускает пользователь; Частично = работает с ограничением из примечаний (исправление, которое делается сейчас, помечено «исправление в работе (R-Z<n>)», строка всё равно считается как «Частично»); Не поддерживается = не сделано; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = REST или GraphQL (endpoint указан); Веб = github.com в браузере; Архив = импорт файла; Недоступно = нужны официальные приложения. Вся работа с GitHub здесь идёт через API, веб-приложение нигде не используется.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют. «—» означает, что ни одна строка требований это не покрывает. Строка требований со словом «Done» не означает, что функция проверена.
- **Проверка**: всё проверено только на подделках (подставленный `fetch` / поддельный браузер). Ничего не проверялось на настоящем аккаунте. «planned (R-Z<n>)» — работа в очереди на следующую волну, статус она не меняет.

## Известные пробелы

1. Правка, удаление и реакции требуют сохранённого id GitHub: элементы, загруженные до R-Z11, дополняет миграция 0004, где это позволяют сохранённые url / raw; остальные отказывают с `no-external-id`, пока репозиторий не загружен заново.
2. Нет поискового входящего по всем репозиториям («всё, где я участвую» через `GET /issues`); входящие — это выбранные репозитории и уведомления.
3. На странице нет значков новой активности; «Загрузить сейчас» и расписание сообщают только число. (Карточка GitHub показывает непрочитанные уведомления с кнопкой «Отметить прочитанным», R-Z20, а комментарии ревью показывают контекст diff, R-Z11.)
4. Полнота показа: не видны состояние issue/PR, метки, Markdown, постоянная ссылка, реакции и аватары.
5. Discussions читаются и пишутся через GraphQL только токеном с доступом к ним; иначе репозиторий загружается, а причина показывается.
6. Работа с токенами: нет OAuth device flow, только один аккаунт, в интерфейсе нет базового URL Enterprise, мало подсказок про classic и fine-grained токены (для уведомлений нужен classic).
7. У клонирования репозитория нет лимита размера и проверки бинарных файлов, и нельзя клонировать все репозитории разом.
8. Ничего не проверено на настоящем аккаунте GitHub; все тесты используют подделки.
