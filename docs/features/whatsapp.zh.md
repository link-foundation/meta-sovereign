## 范围与访问方式

范围是用户的个人 WhatsApp 账号。这里的内容都没有在真实 WhatsApp 账号上验证过：所有测试都使用替身（fake），没有测试触及真实的 WhatsApp Web 页面，WhatsApp Web 的选择器也是未经验证的猜测（代码本身就说没有已登录账号就无法核实）。关于 WhatsApp 的事实来自代码和下面列出的官方页面；导出数量上限没有重新核对。

共有三条途径；个人号码只有两条能用。

| 途径                                    | 它做什么                                                                                        | 个人账号可用吗？                                                                                                                                                                                                                                      |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WhatsApp Cloud API（Graph API `v22.0`） | 发送文本和贴纸、标记已读、输入状态、回应、更新商业资料；入站只能解析别人交给它的 webhook 载荷。 | 不可用。Cloud API 只服务 WhatsApp Business Platform 号码（需注册到 API，并有 Meta 应用、商务组合、令牌和 phone-number id）。在 24 小时客户服务窗口之外只能发送已批准的模板。文档：https://developers.facebook.com/docs/whatsapp/cloud-api/get-started |
| 聊天导出归档（`_chat.txt`）             | 从“设置”导入框和自动导入中导入。                                                                | 可用，一次一个聊天，需在手机上手动操作：聊天，更多，导出聊天（含或不含媒体）。FAQ：https://faq.whatsapp.com/1180414079177245 （导出上限约为含媒体 10,000 条、不含媒体 40,000 条，未重新核对）。                                                       |
| 浏览器中的 WhatsApp Web（已关联设备）   | 发送、输入状态、读取最近消息和聊天列表、编辑、删除、回应、转发、标记已读、页面捕获。            | 原则上可用，也是个人号码唯一的实时途径。实际上目前处于休眠状态：用户无法登录发送器使用的配置文件（见“账号”）。已关联设备 FAQ：https://faq.whatsapp.com/378279804439436                                                                                |

**不可访问：**所有仅限官方应用的功能：用手机号发起通话、WhatsApp Pay、聊天备份和恢复、手机通讯录、聊天锁 PIN、端到端加密备份、更换手机号、Web 之外的账号注册和删除。个人账号没有官方 API。未考虑非官方库（Baileys、whatsapp-web.js）：它们是第三方代码，且违反 WhatsApp 的条款。

**需要了解的风险：**WhatsApp 的条款禁止自动化或群发消息以及非官方客户端。用脚本化按键事件驱动 WhatsApp Web 并运行问候自动化，可能导致个人号码被限制或封禁。应用目前还没有就此给出警告（计划 (R-Z9)：服务条款提示）。

简而言之：代码可以通过 WhatsApp Web 读取聊天列表、读取单个聊天的可见历史、发送、输入状态、编辑、删除、回应、转发和标记已读，但用户无法登录发送器使用的配置文件（WhatsApp Web 通过二维码登录，而发送器以无头模式运行），所以对真实用户来说这些通路处于休眠状态。群聊根本无法寻址（点击聊天的 URL 只接受电话号码）。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（“修复进行中 (R-Z<n>)” = 修复正在开发）；不支持 = 虽可访问但尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 该网络的官方 API（已知时给出端点）；网页 = 浏览器中该网络的网页应用，作为后备（R-Y38）；归档 = 导入该网络的数据导出；API + 网页 = 先用 API，API 没有该调用或被拒绝时用网页应用；不可访问 = 需要只有官方应用才具备的能力。
- **需求**：[`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中实现该功能的 R-ID。
- **验证**：此处所有内容均对照 main 上的代码和测试替身（fake）检查，没有任何内容在真实账号上验证过。备注中的“计划 (R-Z<n>)”表示以后的工作，当前并未进行。

## 已知缺口

1. 个人用户无法为发送器登录 WhatsApp Web（二维码需要可见的浏览器），所以所有实时 WhatsApp 通路都处于休眠状态（计划 (R-Z9)）。
2. 聊天身份：读取得到聊天标题，发送需要电话号码；没有稳定的聊天 id，从导入到回复无法闭环，各途径之间会出现重复对话（计划 (R-Z9)）。
3. 消息 id 和时间戳不可靠：群 id 模式捕获的是参与者，区域化的日期无法解析，归档 id 是每个文件的计数器（计划 (R-Z9)）。
4. 归档导入器只处理 iOS 格式，并丢失多行消息、系统行和媒体（计划 (R-Z9)）。
5. WhatsApp Web 的选择器从未对照真实页面检查过。
6. Web 读取只有文本，且只针对可见行：没有回复、回应、媒体、历史回滚。
7. 问候把 Cloud API 的 24 小时窗口套用到个人账号，错误地跳过老联系人（自动化安全进行中，R-Z3）。
8. 还没有诚实的连接指南或封号风险提示（计划 (R-Z9)）。
9. 较低优先级：后台轮询和通知、面向商业用户的 Cloud API webhook 接收器和媒体、媒体 / 语音 / 文件发送、群管理、Status、频道、投票、联系人视图、多账号。
