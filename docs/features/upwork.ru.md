# Upwork матрица функций (languages: [en](upwork.md) • [zh](upwork.zh.md) • [hi](upwork.hi.md) • ru)

Назад к [матрице поддержки функций Telegram](../FEATURES.ru.md).

## Объём и доступ

Issue #4 просит: поиск заданий, общение до и после одобрения со стороны и заказчика, и фрилансера, кэширование в хранилище ссылок и импорт выгрузок уровня аккаунта. Строки требований R-S1..R-S22 все говорят «Done»; эта матрица показывает, что реально доказано. Ничего здесь не проверялось на настоящем аккаунте Upwork, а форма живого API угадана (см. ниже). Код: `js/src/sources/upwork.js`; в Rust-сервере есть только имя в списке.

Маршруты для личного аккаунта:

- **Официальный API (GraphQL, `https://api.upwork.com/graphql`)**. Нужен API-ключ, который Upwork проверяет вручную. Фрилансер может запросить его для личного или внутреннего использования; опубликованные критерии в разных версиях статьи различаются (подтверждённая личность, способ оплаты, фото профиля, а в одной версии ещё доход 25 000 USD за всё время и Job Success Score не ниже 90%). Ключи не для коммерческого использования и ограничены 40K запросов в сутки ([запрос API-ключа](https://support.upwork.com/hc/en-us/articles/115015857647-How-to-request-an-API-key-from-Upwork), [документация GraphQL](https://www.upwork.com/developer/documentation/graphql/api/docs/index.html)). Одобрение не гарантировано; сообщество описывает ключи, зависшие на недели. Код шлёт bearer-токен и необязательный заголовок `X-Upwork-API-TenantId`. Загрузка документации GraphQL при аудите не удалась (HTTP 403), так что какие scope нужны операциям с сообщениями, не подтверждено, а собственное исследование репозитория помечает имена полей room, message и contract как непроверенные. Все имена операций ниже считайте догадками.
- **Веб-приложение в браузере** (`https://www.upwork.com/ab/messages/`) через браузерный отправитель и запись `upwork` в `WEB_UIS`. Все селекторы — непроверенные догадки (атрибуты `data-test`), и ни один тест эту запись не запускает.
- **Импорт архива**: CSV истории транзакций и собранный вручную JSON-конверт. Настоящий формат запроса данных (DSAR) Upwork коду неизвестен; он лишь угадывает имена полей.
- **Недоступно**: мобильное приложение и десктопное Upwork Messages, видеозвонки, покупка Connects, вехи контракта и эскроу, всё, что требует официальных приложений или внутренних API Upwork. Позволяет ли публичный API фрилансеру отправлять proposal, не подтверждено.

Загрузка входящих готова: кнопка «Получить сейчас» и расписание раз в 5 минут (R-Z8); очистка кэша через 24 часа и обновление токена пока не подключены (R-Z7).

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении, которое запускает пользователь; Частично = работает с ограничением из примечаний (исправление, которое делается сейчас, помечено «исправление в работе (R-Z<n>)», строка всё равно считается как «Частично»); Не поддерживается = не сделано; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = официальный GraphQL API (операция указана; имена — догадки); Веб = веб-приложение Upwork в браузере; Архив = импорт файла; Недоступно = нужны официальные приложения.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют. «—» означает, что ни одна строка требований это не покрывает. Строка требований со словом «Done» не означает, что функция проверена.
- **Проверка**: всё проверено только на подделках (подставленный `fetch` / поддельный браузер). Ничего не проверялось на настоящем аккаунте. «planned (R-Z<n>)» — работа в очереди на следующую волну, статус она не меняет.

## Известные пробелы

1. Форма живого API не проверена, одобрение ключа неопределённо: все имена операций и полей GraphQL — догадки. Без одобренного ключа остаётся только браузерный путь, а его селекторы не проверены.
2. Отправка из Chat берёт id комнаты из ключа чата `room:` (исправлено, R-Z4; только из ключа, не из сохранённых связей), а браузерный путь не проверен.
3. Синхронизация резюме для Upwork теперь отвечает `unsupported` вместо успеха (исправлено, R-Z4). Плана CV для Upwork нет.
4. Нет сценария proposal и интерфейса на странице: ни живого списка proposal, ни отправки, ни экрана поиска.
5. У серверных маршрутов нет тестов; очистка кэша через 24 часа не запускается, refresh-токен не используется (R-Z7); загрузка входящих готова и проверена на подделках (R-Z8).
6. Данные сообщений скудны: не запрашиваются имена отправителей, вложения и время правки.
7. Ничего не проверено на настоящем аккаунте Upwork; все тесты используют подделки.
