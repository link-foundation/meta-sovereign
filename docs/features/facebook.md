# Facebook (Messenger and Instagram) feature matrix (languages: en • [zh](facebook.zh.md) • [hi](facebook.hi.md) • [ru](facebook.ru.md))

Back to the [Telegram feature matrix](../FEATURES.md). This page covers Facebook (Messenger and Instagram) only.

## Scope and access

The scope is a personal Facebook account (Messenger) and, as a separate row group at the end, Instagram Direct. Nothing here has been verified against a live Facebook or Instagram account: every test uses fakes, and the web selectors are unverified guesses (the code itself says so).

Three routes exist for a personal account. Only the third works for a personal inbox's live messages, and it is untested against real markup.

1. **Official API (Graph API / Messenger Platform).** The adapter uses `https://graph.facebook.com/v22.0` with a _Page_ access token and a Page id. The Messenger Platform serves Pages only: a Page's inbox, webhooks, the 24-hour standard messaging window, and App Review (`pages_messaging`) for anyone but app roles. There is **no API for a personal Messenger inbox** (the old `read_mailbox` permission and the Chat API are gone). The adapter is useful only to someone who runs a Page. Docs: https://developers.facebook.com/docs/messenger-platform/ , https://developers.facebook.com/docs/graph-api/reference/page/conversations/ , https://developers.facebook.com/docs/messenger-platform/send-messages/ .
2. **Download-your-data archive.** The importer reads one `message_N.json` per call. The auto-import recipe opens the Accounts Center "Download your information" page; the Connections page accepts `.json` and `.zip`. The archive is a one-off snapshot: end-to-end encrypted chats are not in the normal export (Meta offers them separately) and no new messages arrive. Docs: https://www.facebook.com/help/212802592074644 .
3. **Web app in a browser.** The app drives `https://www.facebook.com/messages/` in a persistent automation profile: send, read recent messages and the chat list, edit, unsend, react, forward. `messenger.com` is not used; whether it still serves a full web client in 2026 is uncertain, since Meta has been folding it into `facebook.com/messages`.

**Instagram Direct.** Nothing exists in the app yet: no Instagram source, web entry, archive recipe or connection guide (planned, R-Z10: Instagram archive import). Official routes: the Instagram Messaging API serves Business and Creator accounts linked to a Page only, not personal accounts (https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/messaging-api/ ). A personal inbox is reachable through the "Download your information" archive (the same `message_1.json` shape as Facebook's) and through `instagram.com/direct/` in a browser.

**Not accessible:** voice and video calls, rooms, end-to-end encrypted chats without the user's restore PIN in the web app (the PIN flow needs the user), Messenger-only features of the mobile apps (Chat Heads, AR effects, payments), and every personal-inbox API call (there is none).

## Legend

- **Status**: Supported = works end to end in the app a user runs; Partial = works with the limit named in the notes ("fix in progress (R-Z<n>)" = a fix is being built right now); Not supported = not built although reachable; Not accessible = needs a capability only the official apps have.
- **Access**: API = the network's official API (endpoints named where known); Web = the network's web app in a browser, as a fallback (R-Y38); Archive = import of the network's data export; API + Web = API first, web app when the API has no such call or refuses; Not accessible = needs a capability only the official apps have.
- **Requirements**: R-IDs in [`REQUIREMENTS.md`](../REQUIREMENTS.md) that implement the feature.
- **Verification**: everything here is checked against the code on main and against fakes (test doubles). Nothing is verified against a live account. "Planned (R-Z<n>)" in the notes means later work, not in progress now.

## Known gaps

1. Reading a personal inbox in the web app is thin and unverified: no sender / direction, 5 chats per pull, no message ids, never checked against real Messenger markup.
2. The archive parser loses data and can corrupt ids: same-millisecond ids collide, mojibake in non-Latin text, attachments, reactions and thread type are dropped (planned, R-Z10).
3. Archive chat ids do not match the numeric thread id the web app needs, so replying from an imported thread fails (planned, R-Z10).
4. The Connections page offers a Page-token form first, but a personal user needs the archive (history) plus a signed-in browser (live); the wording should say so (docs, R-Z13).
5. Parts of the Page API code are unproven or dead: the delivery-receipt parser has no caller (R-Z7), the webhook has no route, profile sync is untested, sending cannot attach files or reply.
6. Web sending lacks stickers, attachments, replies, pacing, and its selectors cover English and Russian only. An ambiguous send failure is no longer retried (fixed, R-Z4).
7. Instagram Direct is absent; the archive route is the cheap first step (planned, R-Z10).
8. Lower priority: reactions, forwards, friends list, group metadata and message requests are readable from the archive or the web but dropped.
