# X फ़ीचर मैट्रिक्स (languages: [en](x.md) • [zh](x.zh.md) • hi • [ru](x.ru.md))

[Telegram फ़ीचर मैट्रिक्स](../FEATURES.hi.md) पर वापस। यह पृष्ठ केवल X के बारे में है।

## दायरा और पहुँच

व्यक्तिगत खाते के लिए तीन रास्ते हैं:

1. **आधिकारिक API v2** (`https://api.x.com`)। दस्तावेज़: https://docs.x.com/x-api/getting-started/pricing और https://developer.x.com/en/docs/authentication/oauth-2-0। पहुँच उपयोग के अनुसार भुगतान (क्रेडिट) पर है, कोई सब्सक्रिप्शन नहीं (मूल्य पृष्ठ के अनुसार: DM इवेंट पढ़ना लगभग $0.010 प्रति संसाधन, DM बनाना लगभग $0.015 प्रति अनुरोध, पोस्ट पढ़ना $0.005, पोस्ट बनाना $0.015, URL के साथ $0.20)। मूल्य पृष्ठ यह नहीं बताता कि DM किस प्लान में खुलते हैं और DM एंडपॉइंट का संदर्भ पृष्ठ नहीं मिल सका, इसलिए DM की पात्रता X Developer Console में पुष्टि करनी होगी। DM एंडपॉइंट को `dm.read` / `dm.write` स्कोप वाला उपयोगकर्ता-संदर्भ टोकन चाहिए (सामान्य जानकारी, यहाँ सत्यापित नहीं)। ऐप एक चिपकाया हुआ bearer टोकन लेता है (`secret:x:token` या env `X_ACCESS_TOKEN`); कोई OAuth प्रवाह, रिफ़्रेश या स्कोप जाँच नहीं है।
2. **ब्राउज़र में वेब ऐप** (x.com/messages), ऐप के ब्राउज़र ऑटोमेशन से: भेजना, चैट सूची और इतिहास पढ़ना, हटाना, प्रतिक्रिया देना। सेलेक्टर यथासंभव बने हैं और असली खाते पर सत्यापित नहीं हैं। X के DM में संपादन या फ़ॉरवर्ड नहीं है।
3. **आर्काइव आयात** (Settings > Download your data): `tweets.js` और `direct-messages.js`।

पहुँच से बाहर: वॉइस और वीडियो कॉल, Spaces, एन्क्रिप्टेड (XChat) DM, Grok, Communities का प्रशासन, Premium और भुगतान फ़ीचर, और वह सब जो केवल नेटिव ऐप में है।

X के लिए अलग सर्वर रूट या पृष्ठ स्क्रीन नहीं है। X सामान्य कोड से चलता है: लाइव पुल, डिफ़ॉल्ट भेजने वाला, संदेश क्रियाएँ, कनेक्शन गाइड और ऑटो-इम्पोर्ट।

## संकेत

- **स्थिति**: समर्थित = उपयोगकर्ता के चलाए ऐप में शुरू से अंत तक काम करता है; आंशिक = टिप्पणी में बताई सीमा के साथ काम करता है ("सुधार जारी (R-Z<n>)" = सुधार अभी बन रहा है); असमर्थित = पहुँच संभव है पर बना नहीं; पहुँच से बाहर = ऐसी क्षमता चाहिए जो केवल आधिकारिक ऐप में है।
- **पहुँच**: API = नेटवर्क की आधिकारिक API (जहाँ पता हैं, एंडपॉइंट सहित); वेब = ब्राउज़र में नेटवर्क का वेब ऐप, विकल्प के रूप में (R-Y38); आर्काइव = नेटवर्क के डेटा एक्सपोर्ट का आयात; API + वेब = पहले API, और जब API में ऐसी कॉल न हो या मना करे तो वेब ऐप; पहुँच से बाहर = ऐसी क्षमता चाहिए जो केवल आधिकारिक ऐप में है।
- **आवश्यकताएँ**: [`REQUIREMENTS.hi.md`](../REQUIREMENTS.hi.md) के R-ID जो इस फ़ीचर को पूरा करते हैं।
- **सत्यापन**: यहाँ सब कुछ main के कोड और नकली (fake) परीक्षण-प्रतिरूपों के विरुद्ध जाँचा गया है। कुछ भी असली खाते पर सत्यापित नहीं है। टिप्पणियों में "योजना (R-Z<n>)" का अर्थ बाद का काम है, अभी चल नहीं रहा।

## ज्ञात कमियाँ

1. DM पढ़ने से अब भेजने वाला, समय और बातचीत id मिलते हैं, और सहेजा हुआ user id पुल को mentions पर नहीं भेजता (सुधार हुआ, R-Z4)।
2. DM केवल संख्यात्मक user id से भेजा जा सकता है; मौजूदा बातचीत में उत्तर अब बातचीत एंडपॉइंट से जाता है (सुधार हुआ, R-Z4)।
3. ऐप में पहुँच और लागत दिखती नहीं: उपयोग-आधारित क्रेडिट, चिपकाया टोकन, OAuth प्रवाह, रिफ़्रेश या स्कोप जाँच नहीं। कोई सुधार निर्धारित नहीं।
4. ब्राउज़र विकल्प असत्यापित अनुमानों का समूह है; असली x.com पर कुछ आज़माया नहीं गया।
5. मीडिया भेजना नहीं है; आर्काइव आयात अब ग्रुप DM और DM मीडिया पढ़ता है (R-Z10), पर `tweets_media/` नहीं।
6. पोस्ट करना केवल सादा पाठ है: हटाना, उत्तर, उद्धरण या मीडिया नहीं।
7. प्रोफ़ाइल अपडेट OAuth 2.0 टोकन से शायद विफल होता है; पुष्टि नहीं हुई।
8. आवश्यकता R-E3 पूरी दिखती है, पर कई रास्तों के परीक्षण बहुत हल्के हैं।
