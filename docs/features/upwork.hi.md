[Telegram फ़ीचर समर्थन मैट्रिक्स](../FEATURES.hi.md) पर वापस।

## दायरा और पहुँच

Issue #4 माँगता है: काम की खोज, स्वीकृति से पहले और बाद में क्लाइंट व फ़्रीलांसर दोनों पक्षों से संवाद, links स्टोर में कैशिंग, और खाता-स्तर के निर्यात का इम्पोर्ट। आवश्यकता-पंक्तियाँ R-S1..R-S22 सब "Done" कहती हैं; यह मैट्रिक्स दिखाता है कि वास्तव में क्या सिद्ध है। यहाँ कुछ भी असली Upwork खाते पर नहीं जाँचा गया, और लाइव API का आकार अनुमानित है (नीचे देखें)। कोड: `js/src/sources/upwork.js`; Rust सर्वर में सूची में केवल एक नाम है।

व्यक्तिगत खाते के रास्ते:

- **आधिकारिक API (GraphQL, `https://api.upwork.com/graphql`)**। ऐसी API कुंजी चाहिए जिसे Upwork हाथ से जाँचता है। फ़्रीलांसर व्यक्तिगत या आंतरिक उपयोग के लिए माँग सकता है; प्रकाशित शर्तें लेख के संस्करणों में अलग हैं (सत्यापित पहचान, भुगतान विधि, प्रोफ़ाइल फ़ोटो, और एक संस्करण में कुल 25,000 USD कमाई व कम से कम 90% Job Success Score)। कुंजी व्यावसायिक उपयोग के लिए नहीं और प्रति दिन 40K अनुरोधों तक सीमित है ([API कुंजी का अनुरोध](https://support.upwork.com/hc/en-us/articles/115015857647-How-to-request-an-API-key-from-Upwork), [GraphQL दस्तावेज़](https://www.upwork.com/developer/documentation/graphql/api/docs/index.html))। स्वीकृति की गारंटी नहीं; समुदाय बताता है कि कुंजियाँ हफ़्तों अटकी रहीं। कोड bearer टोकन और वैकल्पिक `X-Upwork-API-TenantId` हेडर भेजता है। ऑडिट में GraphQL दस्तावेज़ लाना विफल रहा (HTTP 403), इसलिए संदेश ऑपरेशनों को कौन-से स्कोप चाहिए यह अपुष्ट है, और रिपॉज़िटरी का अपना शोध भी room, message और contract फ़ील्ड नामों को अपुष्ट बताता है। नीचे के हर ऑपरेशन नाम को अनुमान मानें।
- **ब्राउज़र में वेब ऐप** (`https://www.upwork.com/ab/messages/`), ब्राउज़र सेंडर और `WEB_UIS` की `upwork` प्रविष्टि के ज़रिए। सारे सेलेक्टर बिना परखे अनुमान हैं (`data-test` एट्रिब्यूट), और कोई टेस्ट इस प्रविष्टि को नहीं चलाता।
- **आर्काइव इम्पोर्ट**: लेन-देन इतिहास CSV और हाथ से बना JSON लिफ़ाफ़ा। Upwork का असली डेटा-अनुरोध (DSAR) प्रारूप कोड नहीं जानता; वह केवल फ़ील्ड नाम अनुमानता है।
- **पहुँच से बाहर**: मोबाइल ऐप और Upwork Messages डेस्कटॉप ऐप, वीडियो कॉल, Connects खरीद, कॉन्ट्रैक्ट माइलस्टोन और एस्क्रो प्रवाह, और जिसके लिए आधिकारिक ऐप या Upwork के आंतरिक API चाहिए। सार्वजनिक API फ़्रीलांसर को proposal भेजने देता है या नहीं, अपुष्ट है।

नियोजित: इनबॉक्स पुल का पेज बटन और शेड्यूल (R-Z8); 24 घंटे का कैश सफ़ाया और टोकन रिफ़्रेश अभी जुड़े नहीं (R-Z7)।

## संकेत

- **स्थिति**: समर्थित = उपयोगकर्ता के चलाए ऐप में शुरू से अंत तक काम करता है; आंशिक = टिप्पणी में बताई सीमा के साथ काम करता है (अभी चल रहा सुधार "सुधार जारी (R-Z<n>)" से चिह्नित है; फिर भी आंशिक गिना जाता है); असमर्थित = बना नहीं; पहुँच से बाहर = ऐसी क्षमता चाहिए जो केवल आधिकारिक ऐप में है।
- **पहुँच**: API = आधिकारिक GraphQL API (ऑपरेशन नाम सहित; नाम अनुमान हैं); वेब = ब्राउज़र में Upwork वेब ऐप; आर्काइव = फ़ाइल इम्पोर्ट; पहुँच से बाहर = आधिकारिक ऐप चाहिए।
- **आवश्यकताएँ**: [`REQUIREMENTS.hi.md`](../REQUIREMENTS.hi.md) की R-ID, जो इस फ़ीचर को पूरा करती हैं। "—" का अर्थ है कोई आवश्यकता-पंक्ति इसे नहीं ढकती। आवश्यकता-पंक्ति में "Done" का अर्थ यह नहीं कि फ़ीचर जाँचा जा चुका है।
- **जाँच**: सब कुछ केवल नकली (fake) के साथ परखा गया है (इंजेक्ट किया `fetch` / नकली ब्राउज़र)। यहाँ कुछ भी असली खाते पर नहीं जाँचा गया। "planned (R-Z<n>)" बाद की लहर के लिए कतारबद्ध काम है; इससे स्थिति नहीं बदलती।

## ज्ञात कमियाँ

1. लाइव API का आकार अपुष्ट है और कुंजी की स्वीकृति अनिश्चित: हर GraphQL ऑपरेशन और फ़ील्ड नाम अनुमान है। स्वीकृत कुंजी के बिना केवल ब्राउज़र रास्ता बचता है, और उसके सेलेक्टर बिना परखे हैं।
2. Chat से भेजना room id `room:` चैट कुंजी से लेता है (सुधार हुआ, R-Z4; केवल कुंजी से, सहेजे लिंक से नहीं), और ब्राउज़र रास्ता अपरीक्षित है।
3. Upwork के लिए रिज़्यूमे सिंक अब सफलता के बजाय `unsupported` बताता है (सुधार हुआ, R-Z4)। Upwork की कोई CV योजना नहीं।
4. proposal प्रवाह और पेज UI नहीं: लाइव proposal सूची, जमा करना या खोज स्क्रीन नहीं।
5. सर्वर रूट के टेस्ट नहीं; 24 घंटे का कैश सफ़ाया कभी नहीं चलता और रिफ़्रेश टोकन अनुपयोगी है (R-Z7); इनबॉक्स पुल planned (R-Z8)।
6. संदेश का विवरण पतला है: भेजने वालों के नाम, अटैचमेंट और संपादन समय नहीं माँगे जाते।
7. किसी भी चीज़ को असली Upwork खाते पर नहीं जाँचा गया; सारे परीक्षण नकली से हैं।
