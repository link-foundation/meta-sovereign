## 范围与访问方式

Issue #4 要求：任务搜索、批准前后客户端与自由职业者两侧的沟通、在 links 存储中缓存，以及导入账号级导出。需求行 R-S1..R-S22 全写着 “Done”；本矩阵展示实际被证明的内容。这里没有任何内容在真实 Upwork 账号上验证过，实时 API 的结构是猜测的（见下）。代码：`js/src/sources/upwork.js`；Rust 服务器只在名称列表里有一个名字。

个人账号的途径：

- **官方 API（GraphQL，`https://api.upwork.com/graphql`）**。需要 Upwork 人工审核的 API 密钥。自由职业者可为个人或内部使用申请；公布的条件在文章的不同版本间不一致（已验证身份、付款方式、头像，某个版本还要求累计收入 25,000 美元加 Job Success Score 至少 90%）。密钥不得用于商业用途，每天限 40K 次请求（[申请 API 密钥](https://support.upwork.com/hc/en-us/articles/115015857647-How-to-request-an-API-key-from-Upwork)、[GraphQL 文档](https://www.upwork.com/developer/documentation/graphql/api/docs/index.html)）。不保证批准；社区反馈有密钥卡了数周。代码发送 bearer 令牌和可选的 `X-Upwork-API-TenantId` 头。审计时获取 GraphQL 文档失败（HTTP 403），所以消息操作需要哪些范围未确认，仓库自己的调研也把房间、消息和合同字段名标为未验证。下面所有操作名都应视为猜测。
- **浏览器中的网页应用**（`https://www.upwork.com/ab/messages/`），通过浏览器发送器和 `WEB_UIS` 里的 `upwork` 条目。所有选择器都是未经测试的猜测（`data-test` 属性），没有测试覆盖该条目。
- **归档导入** 交易历史 CSV 和手工构造的 JSON 信封。代码不知道 Upwork 真实的数据请求 (DSAR) 格式，只是猜字段名。
- **不可访问**：移动应用和 Upwork Messages 桌面应用、视频通话、Connects 购买、合同里程碑和托管流程，以及任何需要官方应用或 Upwork 内部 API 的内容。公共 API 是否允许自由职业者提交 proposal 未确认（未验证）。

收件箱拉取已完成：“立即获取”按钮和每 5 分钟的定时任务 (R-Z8)；24 小时缓存清理和令牌刷新尚未接通 (R-Z7)。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（正在进行的修复标为“修复进行中 (R-Z<n>)”，仍计为部分）；不支持 = 尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 官方 GraphQL API（已写出操作名；名称为猜测）；网页 = 浏览器中的 Upwork 网页应用；归档 = 文件导入；不可访问 = 需要官方应用。
- **需求**：实现该功能的 [`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中的 R-ID。“—”表示没有需求行覆盖它。需求行写“Done”并不代表该功能已被验证。
- **验证**：所有功能都只用假数据（注入的 `fetch` / 假浏览器）测试过，没有任何功能在真实账号上检查过。“planned (R-Z<n>)”表示排入后续批次的工作，不改变状态。

## 已知缺口

1. 实时 API 的结构未验证，密钥能否获批也不确定：所有 GraphQL 操作和字段名都是猜的。没有获批密钥时只剩浏览器途径，而它的选择器未经测试。
2. 从聊天发送时从 `room:` 聊天键取 room id（已修复，R-Z4；只来自键，不查已存链接），浏览器路径未测试。
3. Upwork 的简历同步现在返回 `unsupported` 而不是成功（已修复，R-Z4）。没有 Upwork 的 CV 方案。
4. 没有 proposal 工作流，也没有页面界面：没有实时 proposal 列表、提交或搜索界面。
5. 服务器路由没有测试；24 小时缓存清理从不运行，刷新令牌未使用 (R-Z7)；收件箱拉取已完成，并用模拟服务器测试 (R-Z8)。
6. 消息细节单薄：没有请求发送者姓名、附件和编辑时间。
7. 没有任何内容在真实 Upwork 账号上验证过；所有测试都用假数据。
