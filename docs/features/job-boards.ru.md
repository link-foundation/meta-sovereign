# Job-борды матрица функций (languages: [en](job-boards.md) • [zh](job-boards.zh.md) • [hi](job-boards.hi.md) • ru)

Назад к [матрице поддержки функций Telegram](../FEATURES.ru.md).

## Объём и доступ

Эта страница охватывает шесть job-бордов: hh.ru, Habr Career, SuperJob, Naukri, TopCV и VietnamWorks. Issue #29 просит читать и обновлять резюме на LinkedIn, hh.ru, Habr, Naukri, VietnamWorks и TopCV через browser-commander, допуская телеметрию и черновики там, где разметка ещё неизвестна. Строки требований: R-E7..R-E13, R-D6, R-V1..R-V22. У LinkedIn своя страница сети; здесь он не рассматривается. Ничего здесь не проверялось на живых сайтах: большинство шагов планов CV — черновики, ни разу не запускавшиеся на настоящих бордах (число черновых шагов указано в строках).

**Сообщения с рекрутёрами** идут тремя возможными путями: официальный API (только hh.ru и SuperJob), веб-приложение борда через браузерного отправителя (нужна запись в `WEB_UIS`) и импорт архива. **Ни у одного из шести бордов нет записи в `WEB_UIS`** (она есть только у vk, telegram, whatsapp, x, facebook, linkedin и upwork), поэтому браузерный путь чтения и отправки сообщений не сделан ни на одном борде. Единственная существующая «веб»-работа — планы профиля CV, которые запускаются через browser-commander в постоянном профиле ([CV-синхронизация](../CV-SYNC.ru.md)).

**Официальные API**:

- hh.ru: `https://api.hh.ru` ([hhru/api на GitHub](https://github.com/hhru/api), [dev.hh.ru](https://dev.hh.ru/)). Нужно приложение, зарегистрированное в аккаунте hh, и OAuth. Спецификацию OpenAPI получить не удалось (HTTP 403), утверждений о доступности токена соискателя не найдено; отраслевые материалы говорят, что доступ жёстко ограничен. Собственные данные репозитория от 2026-09-16: в публичном OpenAPI нет изменения резюме соискателя (`/resumes/{id}` только GET), а `/resumes/mine` читается.
- SuperJob: `https://api.superjob.ru/2.0` ([документация](https://api.superjob.ru/)). Нужно зарегистрированное приложение (секретный ключ в `X-Api-App-Id`) и токен пользователя. Сайт документации при аудите вернул HTTP 403. План CV для SuperJob в репозитории указывает, что ключ API покрывает вакансии, но не редактирование резюме соискателя.
- Habr Career: публичного API для соискателя нет. Адаптер сам об этом говорит; его пути `/api/applications`, `/api/resume` и проба `/api/frontend/me` придуманы.
- Naukri, TopCV, VietnamWorks: API для соискателя нет.

**Архивы**: ни один из бордов не известен выгрузкой данных пользователя об откликах или сообщениях в форме, которую ждут парсеры. Руководства подключения советуют «используйте экспорт JSON» (hh, Habr, SuperJob) или «сохраните JSON, который загружает страница» (Naukri, TopCV, VietnamWorks); подтвердить такой экспорт не удалось. Для Naukri настоящий путь — письма рекрутёров, которые умеет импортировать почтовый источник.

**Недоступно**: функции работодателя и рекрутёра (публикация вакансий, поиск по базе резюме), официальные мобильные приложения, видеоинтервью и платные услуги (премиум hh и TopCV, платное продвижение резюме).

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении, которое запускает пользователь; Частично = работает с ограничением из примечаний (исправление, которое делается сейчас, помечено «исправление в работе (R-Z<n>)», строка всё равно считается как «Частично»); Не поддерживается = не сделано; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = официальный API борда (только hh.ru и SuperJob; у остальных он придуман или отсутствует); Веб = борд в браузере, на практике — планы профиля CV через browser-commander; Архив = импорт файла; Недоступно = нужны официальные приложения или аккаунты работодателя. «Черновые» шаги — селекторы, ни разу не запускавшиеся на настоящем сайте.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют. «—» означает, что ни одна строка требований это не покрывает. Строка требований со словом «Done» не означает, что функция проверена.
- **Проверка**: всё проверено только на подделках (подставленный `fetch` / поддельный браузер). Ничего не проверялось на настоящем аккаунте. «planned (R-Z<n>)» — работа в очереди на следующую волну, статус она не меняет.

## Известные пробелы

1. Сообщений рекрутёров нет на каждом борде без API (Naukri, TopCV, VietnamWorks, Habr Career) и они не доказаны на двух с API (hh.ru, SuperJob). Надёжным путём был бы входящий каждого борда в браузерном профиле с входом, но он не сделан.
2. Запись резюме через API для hh.ru, SuperJob и Habr Career вызывает endpoint, которых, по собственному исследованию репозитория, у соискателей нет, при этом R-E8, R-E9 и R-D6 говорят «Done»; писать могут только черновые браузерные планы CV. Общая синхронизация резюме больше не сообщает ложный успех для адаптеров без `syncResume` (исправлено, R-Z4), а синхронизация резюме hh.ru отвечает `unsupported`.
3. Адресат ответа из чата неверен для архивных веток и живых веток Habr Career и SuperJob: чаты названы `vacancy:<id>`, а для отправки нужен настоящий id ветки.
4. Сообщения веток hh.ru — лишь заглушка, если список их не содержит; отдельный вызов сообщений не делается, а что разрешено токенам соискателя, не подтверждено.
5. Нигде нет поиска вакансий, откликов, оповещений и уведомлений по бордам, хотя это основа дня соискателя.
6. Планы CV в основном черновые и ни разу не запускались на настоящих сайтах (черновых шагов: hh.ru 22 из 30, Naukri 27 из 34, TopCV 27 из 32, VietnamWorks 21 из 32, SuperJob 13 из 18, Habr Career 5 из 17). Набор чтения Habr Career уже набора записи, поэтому diff не подтверждает, что записано.
7. Неточности документации и интерфейса: руководства советуют действия «экспорт JSON», существование которых неизвестно, а id секрета SuperJob и флаг необязательного токена не согласованы. Чистка документации planned (R-Z13).
8. У Upwork и PeoplePerHour нет плана CV-платформы (см. их страницы).
9. Ничего не проверено на живых сайтах; все тесты используют подделки.
