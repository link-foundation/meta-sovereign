# LinkedIn матрица функций (languages: [en](linkedin.md) • [zh](linkedin.zh.md) • [hi](linkedin.hi.md) • ru)

Назад к [матрице функций Telegram](../FEATURES.ru.md). Эта страница только про LinkedIn.

## Объём и доступ

1. **Официальный API.** Документация: Posts API https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api и Sign In with LinkedIn (OIDC) https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2.
   - Самообслуживание для участника: `openid profile email` (OIDC `GET /v2/userinfo`: sub, имя, фото, locale, email) и `w_member_social` (создание, изменение текста через PARTIAL_UPDATE и удаление постов; изображения, видео, документы, мультиизображения, опрос, статья, репост).
   - **Ограничено:** `r_member_social` (чтение своих постов, комментариев, лайков) доступен только одобренным пользователям, поэтому обычному личному приложению недоступно даже чтение своих постов через `GET /rest/posts?q=author`.
   - **Messaging API только для партнёров**, самостоятельного доступа нет (общеизвестно): личные сообщения читать и отправлять нельзя. API правки профиля тоже только для партнёрских программ.
2. **Веб-приложение в браузере** (linkedin.com/messaging, /in/me): единственный путь читать и отправлять сообщения и править профиль. LinkedIn жёстко блокирует автоматический трафик, поэтому любая автоматизация несёт риск ограничения аккаунта.
3. **Архив выгрузки данных** (Settings > Get a copy of your data): импортируется `messages.csv`. Остальные CSV (Connections, Profile, Positions, Skills, Shares, Comments, Invitations) не импортируются.

Недоступно: звонки, видеовстречи, Premium и кредиты InMail, Sales Navigator, инструменты рекрутера, потоки отклика на вакансии, всё, что есть только в приложениях.

Отдельного серверного маршрута или экрана страницы для LinkedIn нет, кроме экрана резюме (`/api/cv/*`). Сообщения идут через общий код. Веб-селекторы никогда не сверялись с настоящим залогиненным LinkedIn.

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении пользователя; Частично = работает с ограничением из примечания («исправляется (R-Z<n>)» = исправление делается сейчас); Не поддерживается = не сделано, хотя доступ возможен; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = официальный API сети (эндпоинты названы, где известны); Веб = веб-приложение сети в браузере, как запасной путь (R-Y38); Архив = импорт выгрузки данных сети; API + Веб = сначала API, веб-приложение — когда в API нет такого вызова или он отказывает; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют.
- **Проверка**: всё здесь сверено с кодом в main и с подделками (fake). Ничто не проверено на настоящем аккаунте. «Запланировано (R-Z<n>)» в примечаниях означает будущую работу, сейчас она не ведётся.

## Известные пробелы

1. Сообщение в чат LinkedIn больше не превращается в публичный пост в ленте, а синхронизация профиля или резюме отвечает `unsupported`, если не передан `shareAsPost` (исправлено, R-Z4). Сообщения в LinkedIn идут через веб-приложение, не проверенное на реальном сайте.
2. Сообщения есть только через браузер, и его селекторы не проверены; LinkedIn может ограничить автоматизированный аккаунт.
3. Импорт архива тонкий: сталкивающиеся id, нет URL профиля отправителя, темы, папки, вложений и участников, нет файлов Connections, Shares, Profile (запланировано, R-Z10).
4. Запись профиля покрывает только заголовок, About и навыки; место, опыт и образование не пишутся.
5. Жизненный цикл поста через API минимален: нет id поста, правки, удаления, медиа и видимости только для контактов; author URN вводится вручную.
6. Для чтения своих постов нужно одобрение LinkedIn на `r_member_social`.
7. Контакты и связи не импортируются.
8. Низкий приоритет: репосты, комментарии, страницы, опросы, отложенная публикация.
