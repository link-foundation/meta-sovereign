# Email feature matrix (languages: en • [zh](email.zh.md) • [hi](email.hi.md) • [ru](email.ru.md))

Back to the [Telegram feature matrix](../FEATURES.md). This page covers Email only.

## Scope and access

Routes to a PERSONAL mailbox and what each needs:

| Route                                                                                | What it gives                                                                                         | Needs                                                                                                                                                                                                                                                                                                                                             | Status in this app                                                                                                        |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Gmail API (`gmail.googleapis.com`)                                                   | read, send, labels, threads                                                                           | OAuth 2.0 token with `gmail.readonly` / `gmail.send` / `gmail.modify`. These are restricted scopes: a personal client in "Testing" mode works for up to 100 test users but refresh tokens expire after 7 days; a public client needs Google verification. Access tokens live about 1 hour.                                                        | Adapter exists; the user pastes a short-lived token by hand. No OAuth flow, no refresh.                                   |
| Microsoft Graph (`graph.microsoft.com/v1.0/me/messages`, `/me/sendMail`)             | read, send, folders, categories, attachments                                                          | Entra app registration, delegated `Mail.ReadWrite` + `Mail.Send`, PKCE sign-in; personal Outlook.com works through the `consumers` tenant.                                                                                                                                                                                                        | Adapter exists; token pasted by hand, same limits.                                                                        |
| JMAP (RFC 8620/8621; Fastmail, Stalwart, Cyrus)                                      | read, send, mailboxes, threads, push                                                                  | API token or app password; discovery at `/.well-known/jmap`.                                                                                                                                                                                                                                                                                      | Adapter exists; the user types the API URL and account id (no session discovery).                                         |
| IMAP / POP3 / SMTP (any provider, Proton Bridge, Yahoo, iCloud, Mail.ru, Yandex)     | read, send                                                                                            | host, user, app password (Google, Yahoo, iCloud, Yandex need an app password with 2-step verification). Gmail and personal Outlook.com no longer accept plain passwords without OAuth (XOAUTH2). Proton needs Proton Bridge on `127.0.0.1` with STARTTLS and a self-signed certificate. Browsers cannot open TCP, so a local process is required. | Local server only, implicit TLS (993/995/465) or plain; no STARTTLS, no XOAUTH2, no custom CA.                            |
| Webmail in a browser (Gmail, Outlook.com, Proton, Yandex) through browser automation | everything the web app does                                                                           | persistent signed-in profile                                                                                                                                                                                                                                                                                                                      | NOT wired: the web table has no email entry, so the "API first, web app second" rule (R-Y38) has no second step for mail. |
| Data export                                                                          | Google Takeout `.mbox`, Thunderbird / Apple Mail `.mbox` / `.eml`, Fastmail / Proton `.eml` / `.mbox` | a file                                                                                                                                                                                                                                                                                                                                            | `.eml`, `.mbox` and JSON are read. PST, OST, EMLX and MSG are not.                                                        |

Official docs: Gmail API https://developers.google.com/gmail/api/reference/rest, Google OAuth scopes https://developers.google.com/gmail/api/auth/scopes, Microsoft Graph mail https://learn.microsoft.com/graph/api/resources/mail-api-overview, JMAP https://jmap.io/spec-mail.html, IMAP RFC 3501 / 9051, SMTP RFC 5321 / 6409, XOAUTH2 https://developers.google.com/gmail/imap/xoauth2-protocol, Proton Bridge https://proton.me/mail/bridge. Quota and token-lifetime figures come from these references and from memory, not re-fetched; treat exact numbers as unverified.

Not accessible: server-side features that need an official client (Gmail confidential mode, Outlook "Focused" ranking, Proton end-to-end encrypted mail without Bridge, S/MIME and PGP key stores, phone push notifications). Everything else a webmail does is reachable through at least one API above.

How the pieces connect on main:

- **Import:** Connections screen, archive upload, parse in the page, store each message. Works without a server.
- **Live pull:** `POST /api/email/pull` (the "Fetch mail now" button on the Email card, at most one pull per 15 s), a 10-minute poller that starts after the server is listening, the CLI `source-pull --source=email` and the `source-pull:` command link. Pulls are incremental; the cursor is written after the mail is stored.
- **Live send:** the Chat composer, automations and `POST /api/email/send` (asks for a confirmation token) all use the saved connection; the protocol is chosen from it (IMAP/SMTP, Gmail, Graph or JMAP). A reply keeps the thread. There is no email web fallback.
- The host / port / security / login / password fields saved by the Connections screen are read by the server (R-Z5). Not yet on the page: an OAuth sign-in, a protocol field and a folder picker.

Claims about bugs were reproduced with a throwaway script and fakes; nothing here is verified against a real mailbox.

## Legend

- **Status**: Supported = works end to end in the app a user runs; Partial = works with the limit named in the notes ("fix in progress (R-Z<n>)" = a fix is being built right now; "fixed (R-Z<n>)" = the fix is merged); Not supported = not built although reachable; Not accessible = needs a capability only the official apps have.
- **Access**: API = the network's official API (endpoints named where known); Web = the network's web app in a browser, as a fallback (R-Y38); Archive = import of the network's data export; API + Web = API first, web app when the API has no such call or refuses; Not accessible = needs a capability only the official apps have.
- **Requirements**: R-IDs in [`REQUIREMENTS.md`](../REQUIREMENTS.md) that implement the feature.
- **Verification**: everything here is checked against the code on main and against fakes (test doubles). Nothing is verified against a live account. "Planned (R-Z<n>)" in the notes means later work, not in progress now.

## Known gaps

1. Pages and the poller need a saved mailbox; there is no OAuth sign-in screen, protocol field or folder picker yet, and Gmail / personal Outlook.com tokens still expire in about an hour.
2. Replies whose client dropped `References` and `In-Reply-To` and changed the subject may thread separately.
3. Archives imported through the page keep attachment names and sizes only (no bytes); there is no `.mbox` / `.eml` export.
4. No unread state, new-mail notification or folder choice on the page; SMTP does not append to Sent.
5. Gmail and personal Outlook.com need OAuth with refresh; today the user pastes a one-hour token by hand. No fix is scheduled.
6. Remote images in mail are dropped on purpose (loading them would tell the sender the mail was opened); there is no button to load them.
7. No attachments, drafts, scheduled send or signatures when sending.
8. Folders, labels and message actions beyond read and delete (archive, move, spam, star) are not built.
9. Webmail fallback through the browser automation (R-Y38) is not wired for any provider; low priority.
10. Export to `.mbox` / `.eml` and PST / EMLX import are missing.
