## 范围与访问方式

访问个人邮箱的路径及各自需求：

| 路径                                                                            | 能做什么                                                                                              | 需要什么                                                                                                                                                                                                                                                                     | 在本应用中的状态                                                                          |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Gmail API（`gmail.googleapis.com`）                                             | 读取、发送、标签、会话                                                                                | 带 `gmail.readonly` / `gmail.send` / `gmail.modify` 的 OAuth 2.0 令牌。这些是受限范围：个人客户端处于“测试”模式最多 100 个测试用户，刷新令牌 7 天过期；公开客户端需要 Google 验证。访问令牌约 1 小时有效。                                                                   | 有适配器；用户手动粘贴短期令牌。没有 OAuth 流程，没有刷新。                               |
| Microsoft Graph（`graph.microsoft.com/v1.0/me/messages`、`/me/sendMail`）       | 读取、发送、文件夹、分类、附件                                                                        | Entra 应用注册、委托权限 `Mail.ReadWrite` + `Mail.Send`、PKCE 登录；个人 Outlook.com 通过 `consumers` 租户可用。                                                                                                                                                             | 有适配器；令牌手动粘贴，限制相同。                                                        |
| JMAP（RFC 8620/8621；Fastmail、Stalwart、Cyrus）                                | 读取、发送、邮箱、会话、推送                                                                          | API 令牌或应用专用密码；在 `/.well-known/jmap` 发现。                                                                                                                                                                                                                        | 有适配器；用户手动输入 API 网址和账号 ID（没有会话发现）。                                |
| IMAP / POP3 / SMTP（任何提供商、Proton Bridge、Yahoo、iCloud、Mail.ru、Yandex） | 读取、发送                                                                                            | 主机、用户、应用专用密码（Google、Yahoo、iCloud、Yandex 需要启用两步验证后的应用专用密码）。Gmail 和个人 Outlook.com 不再接受没有 OAuth（XOAUTH2）的明文密码。Proton 需要 `127.0.0.1` 上的 Proton Bridge，使用 STARTTLS 和自签名证书。浏览器不能打开 TCP，因此需要本地进程。 | 仅本地服务器，隐式 TLS（993/995/465）或明文；没有 STARTTLS、没有 XOAUTH2、没有自定义 CA。 |
| 浏览器中的网页邮箱（Gmail、Outlook.com、Proton、Yandex），通过浏览器自动化      | 网页应用能做的一切                                                                                    | 持久的已登录配置                                                                                                                                                                                                                                                             | 未接入：网页表中没有邮件条目，因此“先 API，再网页应用”的规则（R-Y38）对邮件没有第二步。   |
| 数据导出                                                                        | Google Takeout `.mbox`、Thunderbird / Apple Mail `.mbox` / `.eml`、Fastmail / Proton `.eml` / `.mbox` | 一个文件                                                                                                                                                                                                                                                                     | 读取 `.eml`、`.mbox` 和 JSON。不读取 PST、OST、EMLX、MSG。                                |

官方文档：Gmail API <https://developers.google.com/gmail/api/reference/rest>，Google OAuth 范围 <https://developers.google.com/gmail/api/auth/scopes>，Microsoft Graph 邮件 <https://learn.microsoft.com/graph/api/resources/mail-api-overview>，JMAP <https://www.rfc-editor.org/rfc/rfc8621>，IMAP RFC 3501 / 9051，SMTP RFC 5321 / 6409，XOAUTH2 <https://developers.google.com/gmail/imap/xoauth2-protocol>，Proton Bridge <https://proton.me/mail/bridge>。配额和令牌有效期数字来自这些资料和记忆，未重新获取；确切数字视为未验证。

不可访问：需要官方客户端的服务端功能（Gmail 保密模式、Outlook “Focused” 排序、没有 Bridge 的 Proton 端到端加密邮件、S/MIME 和 PGP 密钥库、手机推送通知）。网页邮箱的其余功能都至少能通过上述一种 API 访问。

main 上各部分如何衔接：

- **导入：** 连接界面、上传归档、在页面中解析、存储每条消息。无需服务器即可使用。
- **实时拉取：** `POST /api/email/pull`（Email 卡片上的“立即收取邮件”，每 15 秒最多一次）、每 10 分钟一次的拉取（共享拉取运行器的任务，服务器开始监听后启动；`POST /api/pull {source:"email"}` 同样可用）、命令行 `source-pull --source=email` 以及 `source-pull:` 命令链接。拉取是增量且只读的；游标在邮件保存后才写入 (R-Z20)。
- **实时发送：** 聊天输入框、自动化和 `POST /api/email/send`（要求确认令牌）都使用已保存的连接，并据此选择协议（IMAP/SMTP、Gmail、Graph 或 JMAP）。回复保持在同一会话。邮件没有网页回退。
- 连接页面保存的主机 / 端口 / 安全方式 / 登录名 / 密码字段由服务器读取（R-Z5）。页面上尚无：OAuth 登录、协议字段和文件夹选择。

关于缺陷的说法均用一次性脚本和 fake 复现；这里没有任何内容在真实邮箱上验证过。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（“修复进行中 (R-Z<n>)” = 修复正在开发；“已修复 (R-Z<n>)” = 修复已合并）；不支持 = 虽可访问但尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 该网络的官方 API（已知时给出端点）；网页 = 浏览器中该网络的网页应用，作为后备（R-Y38）；归档 = 导入该网络的数据导出；API + 网页 = 先用 API，API 没有该调用或被拒绝时用网页应用；不可访问 = 需要只有官方应用才具备的能力。
- **需求**：[`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中实现该功能的 R-ID。
- **验证**：此处所有内容均对照 main 上的代码和测试替身（fake）检查，没有任何内容在真实账号上验证过。备注中的“计划 (R-Z<n>)”表示以后的工作，当前并未进行。

## 已知缺口

1. 页面和轮询器需要已保存的邮箱；还没有 OAuth 登录界面、协议字段和文件夹选择，Gmail / 个人 Outlook.com 的令牌仍约一小时过期。
2. 客户端丢掉 `References` 和 `In-Reply-To` 并改了主题的回复可能单独成串。
3. 通过页面导入的归档只保留附件名称和大小（没有字节）；没有 `.mbox` / `.eml` 导出。
4. 页面上没有未读状态、新邮件通知和文件夹选择；SMTP 不追加到 Sent。
5. Gmail 和个人 Outlook.com 需要带刷新的 OAuth；目前用户手动粘贴一小时有效的令牌。尚未安排修复。
6. 邮件中的远程图片被有意丢弃（加载它们会告诉发件人邮件已被打开）；没有加载它们的按钮。
7. 发送时没有附件、草稿、定时发送或签名。
8. 除读取和删除外的文件夹、标签和消息操作（归档、移动、垃圾邮件、加星）未构建。
9. 通过浏览器自动化的网页邮箱后备（R-Y38）未对任何提供商接入；优先级低。
10. 缺少导出为 `.mbox` / `.eml` 以及 PST / EMLX 导入。
