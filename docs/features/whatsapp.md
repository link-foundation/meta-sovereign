# WhatsApp feature matrix (languages: en • [zh](whatsapp.zh.md) • [hi](whatsapp.hi.md) • [ru](whatsapp.ru.md))

Back to the [Telegram feature matrix](../FEATURES.md). This page covers WhatsApp only.

## Scope and access

The scope is the user's personal WhatsApp account. Nothing here has been verified against a live WhatsApp account: every test uses fakes, no test touches a real WhatsApp Web page, and the WhatsApp Web selectors are unverified guesses (the code itself says they cannot be checked without a signed-in account). Facts about WhatsApp come from the code and the official pages listed below; exact export limits were not re-checked.

Three routes exist; only two can work for a personal number.

| Route                                     | What it does                                                                                                                           | Works for a personal account?                                                                                                                                                                                                                                                                                                |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WhatsApp Cloud API (Graph API `v22.0`)    | Send text and stickers, mark read, typing, react, business profile update; inbound only by parsing a webhook payload someone hands in. | No. The Cloud API serves only WhatsApp Business Platform numbers (registered to the API, with a Meta app, a business portfolio, a token and a phone-number id). Outside the 24-hour customer-service window only approved templates can be sent. Docs: <https://developers.facebook.com/docs/whatsapp/cloud-api/get-started> |
| Chat export archive (`_chat.txt`)         | Imported from the Settings import box and by auto-import.                                                                              | Imported from the Settings import box (a `.txt` or a `.zip` with media) and by auto-import. Both Android and iOS layouts are read (R-Z9).                                                                                                                                                                                    |
| WhatsApp Web in a browser (linked device) | Send, type, read recent messages and the chat list, edit, delete, react, forward, mark read, page capture.                             | Send, type, read recent messages and the chat list, edit, delete, react, forward, mark read, page capture. Only a message you confirm is ever sent through it (R-Z9).                                                                                                                                                        |

**Not accessible:** every official-app-only function: starting calls from a phone number, WhatsApp Pay, chat backup and restore, the phone's contact book, chat-lock PIN, end-to-end encrypted backups, changing the phone number, account registration and deletion beyond Web. There is no official API for a personal account. Unofficial libraries (Baileys, whatsapp-web.js) were not considered: they are third-party code and against WhatsApp's terms.

**Terms of use:** WhatsApp's terms prohibit automated or bulk messaging and unofficial clients. The WhatsApp card on Connections now says so, and the app acts on it: only a message you confirm yourself is ever typed into WhatsApp Web; greetings, rules, broadcast and batch re-engage never send to a personal WhatsApp (they are refused with `unsupported`). Meta can still restrict a number that is used through Web (R-Z9).

In short: the app can read the chat list, the visible history of one chat, send a message you confirm, type, edit, delete, react, forward and mark read through WhatsApp Web, and the user can now sign in to the profile the sender uses (a visible window, QR scanned by the user). The selectors are still unverified guesses. Chats from Web and archives get stable ids. Group chats still cannot be addressed for sending.

## Legend

- **Status**: Supported = works end to end in the app a user runs; Partial = works with the limit named in the notes ("fix in progress (R-Z<n>)" = a fix is being built right now); Not supported = not built although reachable; Not accessible = needs a capability only the official apps have.
- **Access**: API = the network's official API (endpoints named where known); Web = the network's web app in a browser, as a fallback (R-Y38); Archive = import of the network's data export; API + Web = API first, web app when the API has no such call or refuses; Not accessible = needs a capability only the official apps have.
- **Requirements**: R-IDs in [`REQUIREMENTS.md`](../REQUIREMENTS.md) that implement the feature.
- **Verification**: everything here is checked against the code on main and against fakes (test doubles). Nothing is verified against a live account. "Planned (R-Z<n>)" in the notes means later work, not in progress now.

## Known gaps

1. A personal user can sign in to WhatsApp Web with the "Sign in to WhatsApp Web" action (a visible window, QR scanned by the user); nothing was run against a real WhatsApp account (fixed, R-Z9).
2. Chat identity: Web messages and archives get stable ids (number in E.164, group JID; a hash of the chat name only for archives whose file name is a contact name), but the chat-list pull still keys rows by title and an archive of a named contact is not matched to the same person on Web (partly fixed, R-Z9).
3. Message ids are stable (the group id pattern is fixed, archive ids are deterministic); Web locale dates still do not parse and archive times carry no zone (partly fixed, R-Z9).
4. The archive importer reads the Android and iOS formats, multi-line messages, system lines and media names, `.txt` and `.zip` (fixed, R-Z9).
5. The WhatsApp Web selectors have never been checked against a live page.
6. Web reading is text only, for visible rows only: no replies, reactions, media, history scroll-back.
7. Greetings go through the Cloud API even for a personal account and fail clearly without its credentials; the 24-hour window no longer wrongly skips old contacts (fixed, R-Z3).
8. The terms notice and an honest sign-in route are on the WhatsApp card; the connection guide still lists the Cloud API first (partly fixed, R-Z9).
9. Lower priority: background polling and notifications, Cloud API webhook receiver and media for business users, media / voice / file send, group admin, Status, Channels, polls, contacts view, multi-account.
