# X матрица функций (languages: [en](x.md) • [zh](x.zh.md) • [hi](x.hi.md) • ru)

Назад к [матрице функций Telegram](../FEATURES.ru.md). Эта страница только про X.

## Объём и доступ

Для личного аккаунта есть три пути:

1. **Официальный API v2** (`https://api.x.com`). Документация: https://docs.x.com/x-api/getting-started/pricing и https://developer.x.com/en/docs/authentication/oauth-2-0. Доступ — оплата по факту использования (кредиты), без подписки (по странице цен: чтение события DM около $0,010 за ресурс, создание DM около $0,015 за запрос, чтение поста $0,005, создание поста $0,015, с URL — $0,20). Страница цен не говорит, какой план открывает DM, а справку по DM-эндпоинтам получить не удалось, поэтому право на DM нужно подтвердить в X Developer Console. DM-эндпоинтам нужен пользовательский токен с областями `dm.read` / `dm.write` (общеизвестно, здесь не проверялось). Приложение принимает один вставленный bearer-токен (`secret:x:token` или переменная `X_ACCESS_TOKEN`); OAuth-потока, обновления токена и проверки областей нет.
2. **Веб-приложение в браузере** (x.com/messages) через браузерную автоматизацию приложения: отправка, чтение списка чатов и истории, удаление, реакции. Селекторы сделаны по возможности и не проверены на настоящем аккаунте. В DM на X нет правки и пересылки.
3. **Импорт архива** (Settings > Download your data): `tweets.js` и `direct-messages.js`.

Недоступно: голосовые и видеозвонки, Spaces, зашифрованные DM (XChat), Grok, администрирование Communities, Premium и платёжные функции, всё, что умеют только нативные приложения.

Отдельного серверного маршрута или экрана страницы для X нет. X идёт через общий код: живую загрузку, отправитель по умолчанию, действия над сообщениями, мастер подключения и автоимпорт.

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении пользователя; Частично = работает с ограничением из примечания («исправляется (R-Z<n>)» = исправление делается сейчас); Не поддерживается = не сделано, хотя доступ возможен; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = официальный API сети (эндпоинты названы, где известны); Веб = веб-приложение сети в браузере, как запасной путь (R-Y38); Архив = импорт выгрузки данных сети; API + Веб = сначала API, веб-приложение — когда в API нет такого вызова или он отказывает; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют.
- **Проверка**: всё здесь сверено с кодом в main и с подделками (fake). Ничто не проверено на настоящем аккаунте. «Запланировано (R-Z<n>)» в примечаниях означает будущую работу, сейчас она не ведётся.

## Известные пробелы

1. Чтение DM теперь возвращает отправителя, время и id диалога, а сохранённый user id больше не уводит загрузку на упоминания (исправлено, R-Z4).
2. DM отправляется только по числовому user id; ответ внутри существующего диалога теперь идёт через endpoint диалога (исправлено, R-Z4).
3. Доступ и стоимость в приложении не видны: кредиты за использование, вставленный токен без OAuth-потока, обновления и проверки областей. Исправление не запланировано.
4. Браузерный запасной путь — набор непроверенных догадок; на настоящем x.com ничего не пробовали.
5. Отправки медиа нет; импорт архива теперь читает групповые DM и медиа DM (R-Z10), но не `tweets_media/`.
6. Публикация только простым текстом: нет удаления, ответа, цитаты и медиа.
7. Обновление профиля, вероятно, не работает с токеном OAuth 2.0; не подтверждено.
8. Требование R-E3 выглядит выполненным, но у ряда путей лишь тонкие тесты.
