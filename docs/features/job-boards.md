## Scope and access

This page covers six job boards: hh.ru, Habr Career, SuperJob, Naukri, TopCV and VietnamWorks. Issue #29 asks to read and update CVs on LinkedIn, hh.ru, Habr, Naukri, VietnamWorks and TopCV using browser-commander, with telemetry and drafts allowed where the markup is not yet known. Requirement rows: R-E7..R-E13, R-D6, R-V1..R-V22. LinkedIn has its own network; this page does not cover it. Nothing here was verified against a live site: most CV-plan steps are drafts that have never run on the real boards (draft step counts are in each row).

**Messaging with recruiters** has three possible routes: the official API (hh.ru and SuperJob only), the board's web app driven by the browser sender (needs a `WEB_UIS` entry), and archive import. **None of the six boards has a `WEB_UIS` entry** (only vk, telegram, whatsapp, x, facebook, linkedin and upwork do), so the browser route for reading or sending messages is unbuilt on every board. The only "web" work that exists is the CV profile plans, run through browser-commander in a persistent profile ([CV sync](../CV-SYNC.md)).

**Official APIs**:

- hh.ru: `https://api.hh.ru` ([hhru/api on GitHub](https://github.com/hhru/api), [dev.hh.ru](https://dev.hh.ru/)). Needs an app registered in an hh account and OAuth. The OpenAPI spec could not be fetched (HTTP 403) and no statement on applicant-token availability was found; industry coverage says access is tightly guarded. The repo's own evidence from 2026-09-16 says the public OpenAPI has no applicant resume mutation (`/resumes/{id}` is GET only) and that `/resumes/mine` is readable.
- SuperJob: `https://api.superjob.ru/2.0` ([docs](https://api.superjob.ru/)). Needs a registered app (secret key sent as `X-Api-App-Id`) and a user token. The docs site returned HTTP 403 during the audit. The repo's SuperJob CV plan states the API key covers vacancies, not applicant resume editing.
- Habr Career: no public candidate API. The adapter itself says so; its `/api/applications` and `/api/resume` paths and the `/api/frontend/me` probe are invented.
- Naukri, TopCV, VietnamWorks: no candidate API.

**Archives**: none of the boards is known to offer a user data export of applications or messages in the shape the parsers expect. The connection guides tell users to "use the JSON export" (hh, Habr, SuperJob) or "save the JSON payload the page loads" (Naukri, TopCV, VietnamWorks); no such export could be confirmed. For Naukri the real route is recruiter e-mail, which the email source can import.

**Not accessible**: employer and recruiter features (posting vacancies, resume database search), the official mobile apps, video interviews, and paid services (hh and TopCV premium, resume boosts that need payment).

## Legend

- **Status**: Supported = works end to end in the app a user runs; Partial = works with the limit named in the notes (a fix being worked on now is marked "fix in progress (R-Z<n>)"; it still counts as Partial); Not supported = not built; Not accessible = needs a capability only the official apps have.
- **Access**: API = the board's official API (hh.ru and SuperJob only; the others are invented or absent); Web = the board in a browser, in practice the CV profile plans run through browser-commander; Archive = file import; Not accessible = needs the official apps or employer accounts. "Draft" steps are selectors never run on the real site.
- **Requirements**: R-IDs in [`REQUIREMENTS.md`](../REQUIREMENTS.md) that deliver the feature. "—" means no requirement row covers it. A requirement row saying "Done" does not mean the feature is verified.
- **Verification**: everything is tested only with fakes (injected `fetch` / fake browser). Nothing here was checked against a live account. "planned (R-Z<n>)" marks work queued for a later wave; it does not change the status.

## Known gaps

1. Recruiter messaging is missing on every board without an API (Naukri, TopCV, VietnamWorks, Habr Career) and unproven on the two with one (hh.ru, SuperJob). The dependable route would be each board's inbox in a logged-in browser profile, which is not built.
2. API resume writes for hh.ru, SuperJob and Habr Career call endpoints that the repo's own research says do not exist for applicants, while R-E8, R-E9 and R-D6 say "Done"; only the draft browser CV plans can write. The generic resume sync no longer reports false success for adapters without `syncResume` (fixed, R-Z4), and hh.ru resume sync is `unsupported`.
3. Chat reply targets are wrong for archived threads and for Habr Career and SuperJob live threads: chats are named `vacancy:<id>`, but sending needs the real thread id.
4. hh.ru thread messages are only a stub unless the list embeds them; the separate messages call is never made, and what applicant tokens may do is unconfirmed.
5. No job search, apply, alerts or board-specific notifications anywhere, though these are the core of a job seeker's day.
6. CV plans are mostly drafts never run on the real sites (draft steps: hh.ru 22 of 30, Naukri 27 of 34, TopCV 27 of 32, VietnamWorks 21 of 32, SuperJob 13 of 18, Habr Career 5 of 17). The Habr Career read set is thinner than its write set, so diffs cannot confirm what was written.
7. Documentation and UX inaccuracies: the guides tell users to use "JSON export" actions that are not known to exist, and the SuperJob secret id and optional-token flag are inconsistent. Docs cleanup is planned (R-Z13).
8. Upwork and PeoplePerHour have no CV platform plan (see their own pages).
9. Nothing has been verified against a live site; all tests use fakes.
