## Объём и доступ

Официальные документы: Gmail API https://developers.google.com/gmail/api/reference/rest, области Google OAuth https://developers.google.com/gmail/api/auth/scopes, почта Microsoft Graph https://learn.microsoft.com/graph/api/resources/mail-api-overview, JMAP https://jmap.io/spec-mail.html, IMAP RFC 3501 / 9051, SMTP RFC 5321 / 6409, XOAUTH2 https://developers.google.com/gmail/imap/xoauth2-protocol, Proton Bridge https://proton.me/mail/bridge. Цифры квот и сроков токенов взяты из этих источников и по памяти, заново не загружались; точные числа считайте непроверенными.

Недоступно: серверные функции, которым нужен официальный клиент (конфиденциальный режим Gmail, ранжирование «Focused» в Outlook, сквозное шифрование Proton без Bridge, хранилища ключей S/MIME и PGP, push-уведомления на телефон). Всё остальное, что умеет веб-почта, достижимо хотя бы одним из API выше.

Как части соединены на main:

- **Импорт:** экран подключений, загрузка архива, разбор на странице, сохранение каждого сообщения. Работает без сервера.
- **Живая загрузка:** только `POST /api/email/pull`, CLI `source-pull --source=email` и командная ссылка `source-pull:`. Ни один код страницы не вызывает `/api/email/*`, поэтому на странице нет кнопки «получить почту» и плановой проверки почты (R-Z5 охватывает почту; загрузка входящих других сетей запланирована, R-Z8).
- **Живая отправка:** `POST /api/email/send` (просит токен подтверждения) и CLI `email-send`. Поле ввода чата и автоматизации идут через общий отправитель только с сохранённым токеном, он доходит до почтового адаптера без протокола, по умолчанию берёт JMAP и падает с «jmap accountId is required». Веб-запаса для почты нет. Поэтому ответ на письмо из чата сегодня не работает (R-Z5, в работе).
- Поля хоста / логина / пароля, сохранённые экраном подключений, никогда не читаются обратно; IMAP / SMTP работают из CLI или вызовом маршрута с учётными данными в теле, но не со страницы.

Утверждения об ошибках воспроизведены одноразовым скриптом на подделках; ничто здесь не проверено на настоящем почтовом ящике.

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении пользователя; Частично = работает с ограничением из примечания («исправляется (R-Z<n>)» = исправление делается сейчас); Не поддерживается = не сделано, хотя доступ возможен; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = официальный API сети (эндпоинты названы, где известны); Веб = веб-приложение сети в браузере, как запасной путь (R-Y38); Архив = импорт выгрузки данных сети; API + Веб = сначала API, веб-приложение — когда в API нет такого вызова или он отказывает; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют.
- **Проверка**: всё здесь сверено с кодом в main и с подделками (fake). Ничто не проверено на настоящем аккаунте. «Запланировано (R-Z<n>)» в примечаниях означает будущую работу, сейчас она не ведётся.

## Известные пробелы

1. Отправка и ответ из чата не работают, ответы не собираются в цепочку (нет In-Reply-To / References); помощники прочтения и удаления никогда не доходят до провайдера (R-Z5, в работе).
2. Цепочки рвутся, границы multipart со смешанным регистром теряют текст и вложения, а закодированные темы и кодировки не UTF-8 искажаются — первыми страдают русская, китайская и хинди-почта (R-Z5, в работе).
3. Укрепление SMTP: Bcc виден в заголовках, возможна инъекция заголовков, нет STARTTLS и XOAUTH2, не-ASCII заголовки не кодируются (R-Z5, в работе).
4. Для живой почты нет сценария на странице: нет кнопки получения, выбора папки, опроса, состояния непрочитанного и уведомлений (R-Z5, в работе).
5. Gmail и личному Outlook.com нужен OAuth с обновлением; сегодня пользователь вручную вставляет токен на час. Исправление не запланировано.
6. HTML-письма сплющиваются в текст, встроенные картинки теряются, вложения — только имена, скачивания нет.
7. При отправке нет вложений, черновиков, отложенной отправки и подписей.
8. Папки, метки и действия над письмами, кроме чтения и удаления (архив, перенос, спам, звезда), не сделаны.
9. Запасной путь через веб-почту с браузерной автоматизацией (R-Y38) не подключён ни для одного провайдера; приоритет низкий.
10. Нет экспорта в `.mbox` / `.eml` и импорта PST / EMLX.
