# VK 功能矩阵 (languages: [en](vk.md) • zh • [hi](vk.hi.md) • [ru](vk.ru.md))

返回 [Telegram 功能矩阵](../FEATURES.zh.md)。本页只涉及 VK。

## 范围与访问方式

范围是个人 VK 账号。这里的内容都没有在真实 VK 账号上验证过：所有测试都使用替身（fake），网页选择器也是未经验证的猜测。关于 VK 本身的事实来自仓库的案例研究（`docs/case-studies/issue-32/README.md`）和 VK 公开的文档；无法重新核对的 VK 细节会在备注中说明。

共有三条途径。

1. **官方 API（`api.vk.ru/method/*`）。** 认证使用用户粘贴的访问令牌（`VK_ACCESS_TOKEN` 或已保存的密钥）。硬性限制：
   - 自 2024-06-25 起，VK 不再向新应用授予用户的 `messages` 权限，用户令牌的隐式流程已关闭。只有旧版令牌（Kate Mobile、VK Admin）曾拥有该权限，而这些令牌已被切断。据报告，vk.com 网页客户端（id 6287487）和 VK Calls（7793118）的令牌仍可使用，但风险由用户自己的账号承担（有报告称账号会被冻结 24 小时至 4 天）。
   - **社区令牌**只能用于该社区的对话。它无法读取用户的个人聊天；成员列表、好友和输入状态部分不适用（错误 27）。
   - 所有消息方法（`messages.getConversations`、`getHistory`、`send`、`edit`、`delete`、`markAsRead`、`sendReaction`、`getLongPollServer`、照片和文档上传）都需要 `messages`（以及 `photos` / `docs`）权限；没有该权限的用户令牌会得到错误 7 或 15。
   - 文档：https://dev.vk.ru/ru/api/access-token/getting-started 、https://dev.vk.ru/ru/reference/access-rights 、https://dev.vk.ru/ru/reference/errors 、https://dev.vk.com/en/method/messages 。
2. **用户自己浏览器配置文件中的网页应用（vk.com/im）。** 这是不需要 `messages` 令牌的唯一途径：用户在配置文件中登录一次。选择器覆盖 VK 的两代界面，尚未对照真实 vk.com 验证。
3. **数据导出归档**（https://vk.com/data_protection?section=rules）。导入器读取 konard/vk-export 的 JSON 结构（`conversations[].messages[]`）。VK 自己的导出是 HTML；其页面现在也能读取 (R-Z8，尚未在真实归档上试过)。

**不可访问**（仅限官方应用，或 VK 已对第三方关闭）：语音和视频通话、VK Pay 转账、聊天内的小程序和 VK Play、VK Messenger 的端到端（密聊）、VK ID 通行密钥登录、贴纸购买和 VK Donut、消息翻译、聊天内的 Clips 和动态查看器、推送通知投递，以及音乐 API（`audio.*`，自 2016/2018 年起对第三方关闭）。

只要服务器运行且已保存令牌，VK 现在会自行保持最新：卡片上有“立即获取”按钮、每 10 分钟的定时任务和官方 Long Poll (R-Z8)。没有任何内容在真实 VK 上试过。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（“修复进行中 (R-Z<n>)” = 修复正在开发）；不支持 = 虽可访问但尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 该网络的官方 API（已知时给出端点）；网页 = 浏览器中该网络的网页应用，作为后备（R-Y38）；归档 = 导入该网络的数据导出；API + 网页 = 先用 API，API 没有该调用或被拒绝时用网页应用；不可访问 = 需要只有官方应用才具备的能力。
- **需求**：[`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中实现该功能的 R-ID。
- **验证**：此处所有内容均对照 main 上的代码和测试替身（fake）检查，没有任何内容在真实账号上验证过。备注中的“计划 (R-Z<n>)”表示以后的工作，当前并未进行。

## 已知缺口

1. VK 会自行保持最新（“立即获取”、每 10 分钟定时和官方 Long Poll，R-Z8），但前提是令牌仍能读取消息；新应用拿不到这项权限，而且这些都没有在真实 VK 上试过。
2. 聊天名称和发送者名称会被补全，每次获取会向前翻几个聊天和几页历史；页面没有向上滚动触发，聊天列表也不是从 VK 实时读取 (R-Z8)。
3. 图片和贴纸从 VK 图片 CDN 内嵌显示，语音消息、文件和视频以链接打开（页面策略没有 `media-src`），消息的所有附件都会显示。VK 地址会过期，不会下载 (R-Z8)。
4. 可以导入 VK 官方 HTML 数据导出 (R-Z8)，但读取器是凭对页面结构的记忆写的，尚未在真实归档上试过；归档中的时间按 UTC 读取。
5. 回应通过发送时用的同一张 id 表显示为表情（未知 id 仍为数字）；VK 真实的 id 列表未经验证，所以这张表仍可能有误 (R-Z8)。
6. 发送只有文字和贴纸：没有回复、照片、文件或语音。`random_id` 现在来自草稿，所以重试不会送达两次，验证码以 `captcha` 报告 (R-Z8)。含糊的 API 失败不再回退到浏览器（已修复，R-Z4）。
7. 网页后备尚未对照当前的 vk.com 验证。
8. Kate Mobile 被切断后，获取令牌是薄弱环节；页面没有引导流程。
9. 较低优先级：已删除消息检测（计划中；历史拉取中没有任何标记 VK 已删除消息的信息）、好友和资料卡、聊天管理、搜索方法、动态、墙、机器人键盘。
