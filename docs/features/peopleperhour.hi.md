# PeoplePerHour फ़ीचर मैट्रिक्स (languages: [en](peopleperhour.md) • [zh](peopleperhour.zh.md) • hi • [ru](peopleperhour.ru.md))

[Telegram फ़ीचर समर्थन मैट्रिक्स](../FEATURES.hi.md) पर वापस।

## दायरा और पहुँच

Issue #12 PeoplePerHour के लिए वही माँगता है जो issue #4 (Upwork) माँगता है, JavaScript और Rust दोनों में। आवश्यकता-पंक्तियाँ R-T1..R-T22 सब "Done" कहती हैं, पर Rust वाला हिस्सा सूची में केवल एक नाम है और JavaScript वाला हिस्सा अनुमानित एंडपॉइंट पर टिका है। यहाँ कुछ भी असली PeoplePerHour खाते पर नहीं जाँचा गया। कोड: `js/src/sources/peopleperhour.js`।

**एंडपॉइंट अपुष्ट और अनुमानित हैं।** नीचे के सारे API पथ परिपाटी से गढ़े गए हैं, दस्तावेज़ से नहीं लिए गए।

- **आधिकारिक API**: व्यक्तिगत खाते के लिए उसके होने की पुष्टि नहीं हुई। PeoplePerHour डेवलपर दस्तावेज़ की वेब खोज में केवल तीसरे पक्ष के स्क्रैपर मिले, peopleperhour.com का कोई पेज नहीं, और रिपॉज़िटरी का अपना शोध (issue #12) कहता है कि डेवलपर पोर्टल बंद है और हर एंडपॉइंट पथ अपुष्ट है। पथ `GET /projects/search`, `/workstreams`, `/workstreams/{id}/messages`, `/proposals/{id}/messages`, `/projects/{id}/proposals`, `/me/proposals` और जाँच `GET /api/v1/me` अनुमान हैं। OAuth प्राधिकरण और टोकन URL भी अपुष्ट हैं। पूरे API रास्ते को "शायद मौजूद ही न हो" मानें।
- **ब्राउज़र में वेब ऐप** (`https://www.peopleperhour.com/`): `WEB_UIS` में प्रविष्टि नहीं है (केवल vk, telegram, whatsapp, x, facebook, linkedin और upwork की है), इसलिए ब्राउज़र सेंडर PeoplePerHour को पढ़ या भेज ही नहीं सकता। यही व्यावहारिक रास्ता है और यह पूरी तरह बना नहीं है।
- **आर्काइव इम्पोर्ट**: JSON लिफ़ाफ़ा और Earnings CSV। PeoplePerHour के डेटा निर्यात का असली आकार अपुष्ट है।
- **पहुँच से बाहर**: मोबाइल ऐप, PeoplePerHour की होस्ट की वीडियो या कॉल सुविधाएँ, और एस्क्रो राशि जारी करने के प्रवाह।

नियोजित: इनबॉक्स पुल का पेज बटन और शेड्यूल (R-Z8); 24 घंटे का कैश सफ़ाया और टोकन रिफ़्रेश अभी जुड़े नहीं (R-Z7)।

## संकेत

- **स्थिति**: समर्थित = उपयोगकर्ता के चलाए ऐप में शुरू से अंत तक काम करता है; आंशिक = टिप्पणी में बताई सीमा के साथ काम करता है (अभी चल रहा सुधार "सुधार जारी (R-Z<n>)" से चिह्नित है; फिर भी आंशिक गिना जाता है); असमर्थित = बना नहीं; पहुँच से बाहर = ऐसी क्षमता चाहिए जो केवल आधिकारिक ऐप में है।
- **पहुँच**: API = ऐसा PeoplePerHour API जिसका अस्तित्व अपुष्ट है (हर पथ "अनुमानित"); वेब = ब्राउज़र में PeoplePerHour वेब ऐप (बना नहीं); आर्काइव = फ़ाइल इम्पोर्ट; पहुँच से बाहर = आधिकारिक ऐप चाहिए।
- **आवश्यकताएँ**: [`REQUIREMENTS.hi.md`](../REQUIREMENTS.hi.md) की R-ID, जो इस फ़ीचर को पूरा करती हैं। "—" का अर्थ है कोई आवश्यकता-पंक्ति इसे नहीं ढकती। आवश्यकता-पंक्ति में "Done" का अर्थ यह नहीं कि फ़ीचर जाँचा जा चुका है।
- **जाँच**: सब कुछ केवल नकली (fake) के साथ परखा गया है (इंजेक्ट किया `fetch` / नकली ब्राउज़र)। यहाँ कुछ भी असली खाते पर नहीं जाँचा गया। "planned (R-Z<n>)" बाद की लहर के लिए कतारबद्ध काम है; इससे स्थिति नहीं बदलती।

## ज्ञात कमियाँ

1. व्यक्तिगत खातों के लिए API शायद है ही नहीं और हर एंडपॉइंट पथ अनुमान है। व्यावहारिक रास्ता वेब ऐप है, जो बना नहीं (`WEB_UIS` प्रविष्टि नहीं), इसलिए चैट PeoplePerHour को भरोसे से न पढ़ सकता है न भेज सकता है।
2. चैट से भेजना फेंकता है क्योंकि workstream या proposal id चैट से निकाली नहीं जाती; `roomId` से पढ़ना चुपचाप कुछ नहीं लौटाता।
3. PeoplePerHour के लिए रिज़्यूमे सिंक अब सफलता के बजाय `unsupported` बताता है (सुधार हुआ, R-Z4)। PeoplePerHour की कोई CV योजना नहीं।
4. proposal जमा करना नहीं और प्रोजेक्ट खोज या संदेशों के लिए पेज स्क्रीन नहीं।
5. सर्वर रूट के टेस्ट नहीं; 24 घंटे का कैश सफ़ाया कभी नहीं चलता और रिफ़्रेश टोकन अनुपयोगी है (R-Z7); इनबॉक्स पुल planned (R-Z8); issue #12 का Rust हिस्सा पूरा नहीं।
6. किसी भी चीज़ को असली PeoplePerHour खाते पर नहीं जाँचा गया; सारे परीक्षण नकली से हैं।
