# PeoplePerHour матрица функций (languages: [en](peopleperhour.md) • [zh](peopleperhour.zh.md) • [hi](peopleperhour.hi.md) • ru)

Назад к [матрице поддержки функций Telegram](../FEATURES.ru.md).

## Объём и доступ

Issue #12 просит для PeoplePerHour то же, что issue #4 (Upwork), и в JavaScript, и в Rust. Строки требований R-T1..R-T22 все говорят «Done», но Rust-половина — лишь имя в списке, а JavaScript-половина держится на угаданных endpoint. Ничего здесь не проверялось на настоящем аккаунте PeoplePerHour. Код: `js/src/sources/peopleperhour.js`.

**Endpoint не проверены и угаданы.** Все пути API ниже придуманы по соглашениям, а не взяты из документации.

- **Официальный API**: его существование для личного аккаунта не подтверждено. Веб-поиск документации разработчика PeoplePerHour выдал только сторонние скраперы, ни одной страницы peopleperhour.com, а собственное исследование репозитория (issue #12) говорит, что портал разработчика закрыт и все пути endpoint не проверены. Пути `GET /projects/search`, `/workstreams`, `/workstreams/{id}/messages`, `/proposals/{id}/messages`, `/projects/{id}/proposals`, `/me/proposals` и проба `GET /api/v1/me` — догадки. URL авторизации и токена OAuth тоже не проверены. Весь API-маршрут считайте «возможно, не существует».
- **Веб-приложение в браузере** (`https://www.peopleperhour.com/`): записи в `WEB_UIS` нет (она есть только у vk, telegram, whatsapp, x, facebook, linkedin и upwork), поэтому браузерный отправитель вообще не может читать или отправлять в PeoplePerHour. Это реалистичный маршрут, и он целиком не сделан.
- **Импорт архива**: JSON-конверт и CSV Earnings. Настоящая форма выгрузки данных PeoplePerHour не проверена.
- **Недоступно**: мобильное приложение, видео- и звонковые функции на стороне PeoplePerHour, потоки выпуска эскроу.

Запланировано: кнопка и расписание загрузки входящих (R-Z8); очистка кэша через 24 часа и обновление токена пока не подключены (R-Z7).

## Обозначения

- **Статус**: Поддерживается = работает от начала до конца в приложении, которое запускает пользователь; Частично = работает с ограничением из примечаний (исправление, которое делается сейчас, помечено «исправление в работе (R-Z<n>)», строка всё равно считается как «Частично»); Не поддерживается = не сделано; Недоступно = нужна возможность, которая есть только у официальных приложений.
- **Доступ**: API = API PeoplePerHour, существование которого не подтверждено (каждый путь «угадан»); Веб = веб-приложение PeoplePerHour в браузере (не сделано); Архив = импорт файла; Недоступно = нужны официальные приложения.
- **Требования**: R-ID из [`REQUIREMENTS.ru.md`](../REQUIREMENTS.ru.md), которые это реализуют. «—» означает, что ни одна строка требований это не покрывает. Строка требований со словом «Done» не означает, что функция проверена.
- **Проверка**: всё проверено только на подделках (подставленный `fetch` / поддельный браузер). Ничего не проверялось на настоящем аккаунте. «planned (R-Z<n>)» — работа в очереди на следующую волну, статус она не меняет.

## Известные пробелы

1. API для личных аккаунтов, возможно, не существует, и все пути endpoint — догадки. Реалистичный путь — веб-приложение, но оно не сделано (нет записи в `WEB_UIS`), поэтому чат не может надёжно ни читать, ни отправлять в PeoplePerHour.
2. Отправка из чата падает, потому что id workstream или proposal не выводится из чата; чтение по `roomId` молча возвращает пустоту.
3. Синхронизация резюме для PeoplePerHour теперь отвечает `unsupported` вместо успеха (исправлено, R-Z4). Плана CV для PeoplePerHour нет.
4. Нет отправки proposal и нет экранов страницы для поиска проектов и сообщений.
5. У серверных маршрутов нет тестов; очистка кэша через 24 часа не запускается, refresh-токен не используется (R-Z7); загрузка входящих planned (R-Z8); Rust-часть issue #12 не сделана.
6. Ничего не проверено на настоящем аккаунте PeoplePerHour; все тесты используют подделки.
