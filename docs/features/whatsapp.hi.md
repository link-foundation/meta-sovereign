# WhatsApp फ़ीचर मैट्रिक्स (languages: [en](whatsapp.md) • [zh](whatsapp.zh.md) • hi • [ru](whatsapp.ru.md))

[Telegram फ़ीचर मैट्रिक्स](../FEATURES.hi.md) पर वापस। यह पृष्ठ केवल WhatsApp के बारे में है।

दायरा उपयोगकर्ता का व्यक्तिगत WhatsApp खाता है। यहाँ कुछ भी असली WhatsApp खाते पर सत्यापित नहीं है: हर परीक्षण नकली (fake) से चलता है, कोई परीक्षण असली WhatsApp Web पेज को नहीं छूता, और WhatsApp Web सेलेक्टर असत्यापित अनुमान हैं (कोड स्वयं कहता है कि साइन-इन खाते के बिना इन्हें जाँचा नहीं जा सकता)। WhatsApp के तथ्य कोड और नीचे दिए आधिकारिक पृष्ठों से हैं; एक्सपोर्ट की ठीक सीमाएँ दोबारा नहीं जाँची गईं।

तीन रास्ते हैं; व्यक्तिगत नंबर के लिए केवल दो चल सकते हैं।

**पहुँच से बाहर:** हर वह फ़ंक्शन जो केवल आधिकारिक ऐप में है: फ़ोन नंबर से कॉल शुरू करना, WhatsApp Pay, चैट बैकअप और रिस्टोर, फ़ोन की संपर्क पुस्तिका, चैट-लॉक PIN, एंड-टू-एंड एन्क्रिप्टेड बैकअप, फ़ोन नंबर बदलना, Web से परे खाता पंजीकरण और हटाना। व्यक्तिगत खाते के लिए कोई आधिकारिक API नहीं है। अनौपचारिक लाइब्रेरी (Baileys, whatsapp-web.js) पर विचार नहीं किया गया: वे तीसरे पक्ष का कोड हैं और WhatsApp की शर्तों के विरुद्ध हैं।

**जानने योग्य जोखिम:** WhatsApp की शर्तें स्वचालित या थोक संदेश और अनौपचारिक क्लाइंट मना करती हैं। स्क्रिप्टेड कुंजी-इवेंट से WhatsApp Web चलाना और अभिवादन ऑटोमेशन चलाना व्यक्तिगत नंबर को प्रतिबंधित या बैन करा सकता है। ऐप अभी इसकी चेतावनी नहीं देता (योजना, R-Z9: ToS सूचना)।

संक्षेप में: कोड WhatsApp Web के ज़रिए चैट सूची पढ़ सकता है, एक चैट की दिखती हिस्ट्री पढ़ सकता है, भेज सकता है, typing, संपादन, हटाना, रिएक्ट, फ़ॉरवर्ड और पढ़ा चिह्नित करना कर सकता है, पर उपयोगकर्ता के पास भेजने वाले की प्रोफ़ाइल में साइन इन करने का कोई तरीका नहीं है (WhatsApp Web QR कोड से साइन इन होता है, और भेजने वाला headless चलता है), इसलिए असली उपयोगकर्ता के लिए ये रास्ते निष्क्रिय हैं। ग्रुप चैट को पते से पहचाना ही नहीं जा सकता (click-to-chat URL केवल फ़ोन नंबर लेता है)।

## संकेत

- **स्थिति**: समर्थित = उपयोगकर्ता के चलाए ऐप में शुरू से अंत तक काम करता है; आंशिक = टिप्पणी में बताई सीमा के साथ काम करता है ("सुधार जारी (R-Z<n>)" = सुधार अभी बन रहा है); असमर्थित = पहुँच संभव है पर बना नहीं; पहुँच से बाहर = ऐसी क्षमता चाहिए जो केवल आधिकारिक ऐप में है।
- **पहुँच**: API = नेटवर्क की आधिकारिक API (जहाँ पता हैं, एंडपॉइंट सहित); वेब = ब्राउज़र में नेटवर्क का वेब ऐप, विकल्प के रूप में (R-Y38); आर्काइव = नेटवर्क के डेटा एक्सपोर्ट का आयात; API + वेब = पहले API, और जब API में ऐसी कॉल न हो या मना करे तो वेब ऐप; पहुँच से बाहर = ऐसी क्षमता चाहिए जो केवल आधिकारिक ऐप में है।
- **आवश्यकताएँ**: [`REQUIREMENTS.hi.md`](../REQUIREMENTS.hi.md) के R-ID जो इस फ़ीचर को पूरा करते हैं।
- **सत्यापन**: यहाँ सब कुछ main के कोड और नकली (fake) परीक्षण-प्रतिरूपों के विरुद्ध जाँचा गया है। कुछ भी असली खाते पर सत्यापित नहीं है। टिप्पणियों में "योजना (R-Z<n>)" का अर्थ बाद का काम है, अभी चल नहीं रहा।

## ज्ञात कमियाँ

1. व्यक्तिगत उपयोगकर्ता भेजने वाले के लिए WhatsApp Web में साइन इन नहीं कर सकता (QR के लिए दिखता ब्राउज़र चाहिए), इसलिए हर लाइव WhatsApp रास्ता निष्क्रिय है (योजना, R-Z9)।
2. चैट पहचान: पढ़ने पर चैट शीर्षक मिलते हैं, भेजने को फ़ोन नंबर चाहिए; स्थिर चैट id नहीं, आयात से उत्तर तक का चक्र नहीं, और रास्तों के बीच बातचीतें दोहराई जाती हैं (योजना, R-Z9)।
3. संदेश id और टाइमस्टैम्प अविश्वसनीय हैं: ग्रुप id पैटर्न प्रतिभागी पकड़ता है, लोकेल तारीखें पार्स नहीं होतीं, आर्काइव id प्रति-फ़ाइल काउंटर हैं (योजना, R-Z9)।
4. आर्काइव इम्पोर्टर केवल iOS रूप संभालता है और बहु-पंक्ति संदेश, सिस्टम पंक्तियाँ और मीडिया खोता है (योजना, R-Z9)।
5. WhatsApp Web सेलेक्टर कभी असली पेज पर जाँचे नहीं गए।
6. Web से पढ़ना केवल पाठ है, केवल दिखती पंक्तियों के लिए: उत्तर, रिएक्शन, मीडिया, हिस्ट्री पीछे स्क्रॉल नहीं।
7. अभिवादन व्यक्तिगत खाते के लिए भी Cloud API से जाते हैं और उसके क्रेडेंशियल के बिना साफ़ विफल होते हैं; 24-घंटे विंडो अब पुराने संपर्कों को गलत नहीं छोड़ती (ठीक किया गया, R-Z3)।
8. अभी कोई ईमानदार कनेक्शन गाइड या बैन-जोखिम सूचना नहीं (योजना, R-Z9)।
9. कम प्राथमिकता: पृष्ठभूमि पोलिंग और सूचनाएँ, बिज़नेस उपयोगकर्ताओं के लिए Cloud API webhook रिसीवर और मीडिया, मीडिया / वॉइस / फ़ाइल भेजना, ग्रुप एडमिन, Status, Channels, पोल, संपर्क दृश्य, बहु-खाता।
