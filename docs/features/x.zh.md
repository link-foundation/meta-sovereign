## 范围与访问方式

对个人账号有三条路径：

1. **官方 API v2**（`https://api.x.com`）。文档：<https://docs.x.com/x-api/getting-started/pricing> 和 <https://developer.x.com/en/docs/authentication/oauth-2-0>。访问按用量付费（无订阅）：按定价页，读取 DM 事件约每资源 $0.010，创建 DM 约每请求 $0.015，读取帖子 $0.005，发帖 $0.015（含 URL 为 $0.20）。定价页没有说明哪个方案开放 DM，DM 端点参考文档也无法获取，因此是否有 DM 资格必须在 X Developer Console 中确认。DM 端点需要带 `dm.read` / `dm.write` 权限范围的用户上下文令牌（常识，此处未验证）。应用只接受一个手动粘贴的 bearer 令牌（`secret:x:token` 或环境变量 `X_ACCESS_TOKEN`）；没有 OAuth 流程、没有刷新、也不检查权限范围。
2. **浏览器中的网页应用**（x.com/messages），通过应用的浏览器自动化：发送、读取聊天列表和历史、删除、回应。选择器是尽力而为的，没有在真实账号上验证。X 的 DM 没有编辑和转发。
3. **归档导入**（设置 > 下载你的数据）：`tweets.js` 和 `direct-messages.js`。

不可访问：语音和视频通话、Spaces、加密（XChat）DM、Grok、Communities 管理、Premium 与支付功能，以及只有原生应用才有的一切。

没有 X 专用的服务器路由或页面界面。X 走通用代码：实时拉取、默认发送器、消息操作、连接向导和自动导入。

## 图例

- **状态**：已支持 = 在用户运行的应用中端到端可用；部分 = 可用但有备注中所述的限制（“修复进行中 (R-Z<n>)” = 修复正在开发）；不支持 = 虽可访问但尚未构建；不可访问 = 需要只有官方应用才具备的能力。
- **访问方式**：API = 该网络的官方 API（已知时给出端点）；网页 = 浏览器中该网络的网页应用，作为后备（R-Y38）；归档 = 导入该网络的数据导出；API + 网页 = 先用 API，API 没有该调用或被拒绝时用网页应用；不可访问 = 需要只有官方应用才具备的能力。
- **需求**：[`REQUIREMENTS.zh.md`](../REQUIREMENTS.zh.md) 中实现该功能的 R-ID。
- **验证**：此处所有内容均对照 main 上的代码和测试替身（fake）检查，没有任何内容在真实账号上验证过。备注中的“计划 (R-Z<n>)”表示以后的工作，当前并未进行。

## 已知缺口

1. 读取 DM 现在会返回发送者、时间和会话 id，保存的用户 ID 也不再把拉取转向提及（已修复，R-Z4）。
2. 发送 DM 只能用数字用户 ID；在现有会话中回复现在使用会话端点（已修复，R-Z4）。
3. 应用里看不到访问与费用：按用量付费的额度、手动粘贴的令牌，没有 OAuth 流程、刷新或权限范围检查。尚未安排修复。
4. 浏览器后备是一组未经验证的猜测；从未在真实 x.com 上试过。
5. 缺少媒体发送；归档导入现在读取群 DM 和 DM 媒体（R-Z10），但不读 `tweets_media/`。
