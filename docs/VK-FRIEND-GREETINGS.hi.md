# VK मित्रों को अभिवादन (भाषाएँ: [en](VK-FRIEND-GREETINGS.md) • [ru](VK-FRIEND-GREETINGS.ru.md) • hi • [zh](VK-FRIEND-GREETINGS.zh.md))

**कनेक्शन → VK → मैन्युअल दर्ज करें → VK मित्रों को अभिवादन** खोलें। सेवा आपके कॉन्फ़िगर किए हुए व्यक्तिगत VK API क्रेडेंशियल से वर्तमान मित्रता जाँचती है। ऑफलाइन सेटिंग बदल सकते हैं, लेकिन VK से समीक्षा या संदेश नहीं भेज सकते। स्वचालित शेड्यूल शुरू में बंद है और केवल ऑनलाइन मित्रों का फ़िल्टर चालू है।

अभिवादन का टेक्स्ट या मूल VK स्टीकर ID चुनें। शून्य से अलग ID होने पर टेक्स्ट की जगह स्टीकर भेजा जाता है। बातचीत की न्यूनतम खामोशी, प्रति व्यक्ति विराम, जाँचे जाने वाले मित्रों की संख्या और भेजने की सीमा सेट करें। शून्य सीमा पर कोई कार्रवाई नहीं होती। केवल खाली बातचीत चुन सकते हैं या ऑनलाइन फ़िल्टर बंद कर सकते हैं। पहले खाली, फिर सबसे पुरानी बातचीत आती है; कुल मित्रों की संख्या का वैकल्पिक क्रम पहले लागू होता है। प्राथमिकता ID और साझा संदेश अस्वीकार सूची हमेशा संबंधित खातों को सुरक्षित रखते हैं।

सेव करें, फिर **वर्तमान स्थिति की समीक्षा करें** दबाकर सटीक सामग्री और पात्रता देखें। पुष्टि केवल उस समीक्षा किए गए प्लान पर लागू होती है, जो पाँच मिनट तक मान्य है। हर संदेश से ठीक पहले वास्तविक मित्रता, ऑनलाइन स्थिति, अपठित स्थिति, लिखने की अनुमति, पूरी सीमित हिस्ट्री और खाता फिर से मेल खाने चाहिए। अपठित बातचीत, सेवा घटनाएँ, अनुपलब्ध या अधूरी हिस्ट्री और अज्ञात डिलीवरी रोक दी जाती हैं। 1,000 से अधिक संदेशों वाली बातचीत का केवल आखिरी हिस्सा देखकर अनुमान नहीं लगाया जाता। हर बैच में अधिकतम 100 अभिवादन और 10,000 मित्रों की जाँच होती है, कार्रवाइयों के बीच 30 सेकंड का विराम रहता है।

शेड्यूल चालू करने पर स्थानीय ऐप सर्वर हर मिनट सेव किया हुआ अंतराल जाँचता है और बंद होने तक काम का स्वामित्व रखता है। स्वचालित संदेशों पर शांत समय लागू होता है। सर्वर बंद होने पर नई कार्रवाइयाँ और बीच की प्रतीक्षा रुकती हैं। मैन्युअल पुष्टि शेड्यूल चालू नहीं करती।

CLI वही नीति और स्थायी स्टोरेज इस्तेमाल करता है:

```sh
meta-sovereign vk-greet status
meta-sovereign vk-greet save --message="नमस्ते!" --limit=3 --online-only=true --stale-days=30 --cooldown-days=7
meta-sovereign vk-greet plan
meta-sovereign vk-greet run --plan=THE_REVIEWED_PLAN_ID --confirm
```

स्थानीय API `/api/vk/greet` है, जिसके `/plan` और `/run` एक्शन हैं। इसमें डिफ़ॉल्ट Lino टेक्स्ट और बाइनरी वायर फ़ॉर्मेट, समान स्रोत से लिखने की जाँच और वही स्पष्ट प्लान पुष्टि मिलती है। बाहरी अनुरोध शेड्यूल वाला रन होने का दावा नहीं कर सकता।

केवल सकारात्मक मूल संदेश रसीद पर पुष्टि दिखाई जाती है। पुष्टि किए अभिवादन वास्तविक VK संदेश ID के साथ Chat में आते हैं; स्टीकर की मूल ID भी रहती है। खोई या अमान्य रसीद अज्ञात मानी जाती है और रीफ़्रेश या रीस्टार्ट के बाद अपने आप दोबारा नहीं भेजी जाती। स्पष्ट अस्वीकृति और अज्ञात डिलीवरी अलग रहती हैं। बाद में नया अभिवादन भेजने के लिए नई समीक्षा और सेव की हुई खामोशी तथा प्रति व्यक्ति विराम दोनों पूरे होने चाहिए।
