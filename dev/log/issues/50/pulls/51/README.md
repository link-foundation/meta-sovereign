## Root causes and reproducible fixes

1. Main's original Checks run40765563701 failed in dependency review capability preflight with HTTP403 (log lines175,204; terminal failure744). Repository admin API enabled vulnerability alerts; dependency comparison now returns HTTP200 and the rerun passes preflight. No gate was disabled or made optional.
2. That rerun then failed Chromium: `Browser launch failed (endpoint: early_exit)` and `No usable sandbox!` at main-chromium-rerun.log:973–975. Browser Commander0.34.0 launches Chrome for Testing directly with sandboxing. The existing Pages workflow already enables the required Ubuntu AppArmor user-namespace setting; release workflow omitted it. Local default launch reproduced the same error. ci-contracts regression failed before setup and passes after it. The fix retains sandboxing and direct launch.
3. Mobile's wrapper used CLI7.6.2 despite peers8.5.3. mobile-before.log records expected/current peer range versus actual7.6.2. It now reads the updated8.6.0 peer and preserves both platform operations. The mocked subprocess test checks actual launched argv without Xcode/Android Studio installation.
4. npm12 `npm view --json` always returns arrays; scalar-only registry probing incorrectly rejects a published version. New regression fails with `Unexpected registry version: ["1.2.3"]` before normalization, then passes while malformed, wrong and ambiguous versions still fail. npm12 pack/publish metadata is keyed by package name; pack-smoke now validates the named object and still checks actual packed consumer behavior in CI. Actual npm12 dry-run metadata is archived.
5. Edition2024 enables Clippy let-chain simplification diagnostics. Initial Rust CI preserved ten collapsible-if failures in pr-rust-first.log:442–655. Applied equivalent let chains, kept -D warnings, and ran focused email/WASM tests plus lint. Full workspace remains CI's responsibility.
6. Latest published setup-swift2.4.0 rejects Swift6.4.1 (`Version "6.4.1" is not available`, pr-native-macos-first.log) and emits Node20 action-runtime deprecation. The official checksummed Swiftly1.2.0 installer supports that exact toolchain, removing the unmaintained action dependency. Existing upstream PR806 tracks the underlying migration.
7. actionlint1.7.12's built-in runner table lacks current GA Ubuntu26 and Windows11 VS2026 ARM labels. Narrow documented label additions admit only official verified labels; all other rule checks remain active. Upstream #682 already tracks this gap.

8. WebKit main CI also failed because the cross-origin Pages fixture intentionally launches Chromium before other WebKit checks, but the matrix installed only WebKit (main-checks-rerun-complete.log:34259–34276). A new workflow regression fails before the change. Both lanes now install Chromium as well as their selected engine; the Pages comparison and all WebKit cases remain mandatory.
9. The new native check initially omitted the production contact helper’s `-parse-as-library` flag required by its `@main` entry point (pr-native-macos-swiftly.log:302–315). The check now matches the existing application invocation; no source semantics changed.
10. New mobile test initially invoked `process.execPath` as Node while running in Deno, triggering Deno read permissions on Windows (pr-deno-windows-current.log:5939). The fixture now explicitly launches Node, matching both npm and the production script’s Node entry points; the full nine-runtime matrix retains the test.

## Migration sources and applicability

- [Node26 major release](https://nodejs.org/en/blog/release/v26.0.0): removed http.writeHeader and private _stream modules are not used in project source; standard writeHead remains. Stable fs.promises.glob replaces local recursive traversal. No unsupported experimental flags added.
- [npm12 major notes](https://github.com/npm/cli/releases/tag/v12.0.0): updated both affected JSON formats. No npm-shrinkwrap.json, removed star commands or legacy npm profile fields are used. Node26 satisfies new engine requirements.
- [Rust2024 edition guide](https://doc.rust-lang.org/edition-guide/rust-2024/): cargo fix updates unsafe export attributes, workspace resolver3 and current rustfmt; current Clippy let chains adopted. No foreign dependency migration exists because the project uses only std and local crates.
- [Electron breaking changes45](https://www.electronjs.org/docs/latest/breaking-changes): preload only requires electron; removed events/timers/url shims and Buffer/immediate globals are not used there. No desktopCapturer WebContents-id path or frame Node integration exists. All native packaging targets still required.
- [Capacitor8 guide](https://capacitorjs.com/docs/updating/8-0): Node22+, Xcode26+, SPM default and native platform migrations reviewed. There are no checked-in generated iOS/Android projects, removed config margins or custom bridge layouts to migrate. Wrapper now creates current native projects with the matching CLI; mobile web build and wrapper argv are verified.
- [Swift6.4.1 announcement](https://forums.swift.org/t/announcing-swift-6-4-1/90029), [Swiftly automation](https://docs.swift.org/latest/documentation/swiftlydocs/automated-install/), [Python3.15.2 release](https://www.python.org/downloads/release/python-3152/), [Ubuntu26 GA](https://github.blog/changelog/2026-09-17-ubuntu-26-generally-available-and-latest-migration/) and captured runner-images list support the compiler/image choices.
